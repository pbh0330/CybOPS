> **이것은 가상 훈련 시나리오이고 실제 부대 배치가 아니다.** 실제 부대편성·임무계획·
> 자산대장을 쓰지 않았고, 실제 건물이나 전산실 위치도 쓰지 않았다. 이 시나리오는 위경도
> 앵커가 **없다** - 좌표는 지구상 어디에도 놓이지 않으며 지도 위젯에 올릴 수 없다.

## 0. 2026-10-14 에 고친 세 가지

이 문서의 첫 판(2026-10-14 오전)은 이 시나리오의 데이터에서 셋을 찾아내고 **고치지는
않았다.** 당시 작업의 제약이 시나리오 수치를 손대지 않는 것이었기 때문이다. 같은 날
오후에 셋을 고쳤고, 아래가 그 기록이다. 어느 것도 **엔진 입력이 아니다** - 기준치
·가중치·엣지·좌표는 하나도 바뀌지 않았고 `node ui\tools\parity.mjs` 는 전후 모두
1622 값 / 불일치 0 이다. 그것이 입력을 건드리지 않았다는 증거다.

| 무엇 | 전 | 후 | 근거 |
|---|---|---|---|
| `notes[6]`, `geo._redundancy_note` 의 "실측 확인" 수치 | DC01+DC02 M-C2 **80.5%**, ESX01 격리 첫 행 **70.1%** | **84.4%**, **100.0%** | 아래 0.1 |
| 자산 16개의 `geo.source` | `asset-register` | `authored-on-facility` | 아래 4.2 |
| 교전이 시작하는 거점 | 선언 없음 - `defaultFoothold()` 가 전파 입력(0.3)을 집어왔다 | `wargame.foothold` = WKS003 0.5 | 아래 7절 |

### 0.1 80.5% / 70.1% 는 ADR-0020 이 바꿨다

`notes[6]` 와 `geo._redundancy_note` 가 "실측 확인" 으로 적고 있던 두 수치는
**ADR-0020 이전에 측정한 값**이었다. ADR-0020 이 `requires` 엣지 12건에 `hard` 를
붙였고(이 시나리오 몫은 4건), hard 요구는 가중평균의 대체 가능성을 끊으므로 같은
입력에서 더 큰 저하도가 나온다. 그래서 값이 움직였다.

2026-10-14 재측정값(`runChain`, method = weighted, 스냅샷):

| 입력 | M-C2 | 적혀 있던 값 |
|---|---|---|
| DC01 침해 1.0 단독 | **0.0%** | 0.0% - 그대로다 |
| DC01 + DC02 침해 1.0 | **84.4%** (0.844) | 80.5% |
| ESX01 격리(침해 1.0) | **100.0%** (1.0) | 70.1% |

`docs/11-tactical-time-axis.md` 111~112행, `docs/07-synthetic-data.md` 83·150행,
`docs/10-limitations.md` 128행은 ADR-0020 당시 이미 고쳐졌다(괄호로 "ADR-0020 이후" 를
달았다). 데이터 파일과 `docs/17-geo-layer.md` 497행이 빠졌고, 이번에 같이 고쳤다.
80.5% 의 출처는 `docs/15-propagation-functions.md` 132행의 `weighted` 계산 예시이고,
그 예시는 `hard` 가 없던 시절의 것이다.

**80.5% 와 70.1% 는 인용하면 안 된다.** 옛 수치를 기억하는 독자는 ADR-0020 때문으로
읽어야 한다. 바뀐 쪽은 입력이 아니라 기록이다. 세 값은 검사기가 매 게이트 실행마다
다시 확인한다(아래 6절).

## 4. 시설 배치 (표시 전용. 판단에 들어가지 않는다)

이 시나리오는 지형장(terrain)을 넣지 않고 시설 배치(facility)만 넣는다. 국방망 자산은
건물 안에 있고 "어느 능선에 있는가" 는 의미가 없다. 의미가 있는 것은 **이중화 쌍이 같은
건물에 있는지 다른 건물에 있는지**다.

| 값 | 출처 | 유도 과정 또는 근거 |
|---|---|---|
| `frame.extent` = x [0,300], y [0,220], z [0,20] | **저작 가정** | 영내 300 x 220 m. 크기를 고른 근거는 기록돼 있지 않다 |
| `frame.grid_step_m` = 50 | **저작 가정** | 표시 격자 간격 |
| `facility.buildings[].polygon` 5개 (전부 축평행 사각형) | **저작 가정** | **어떤 실제 도면에서도 유도하지 않았다.** 이중화 구조가 읽히게 그린 그림이다 |
| `floors` = 4 / 2 / 1 / 2 / 2 | **출처 미상, 저작 가정** | |
| `floor_height_m` = 3.6 (사무 건물) / 4.2 (전산동) | **출처 미상, 저작 가정** | 전산동이 더 높은 것은 그럴듯하지만 그 근거가 기록돼 있지 않다. 건축 기준에서 가져온 값이 **아니다** |
| `asset.geo.at.z` = 1.0 (1층) / 4.6 (2층) | **유도값** | 아래 4.1 |
| `asset.geo.source` = "authored-on-facility" (16개 전부) | **정확한 자기 기술** | 아래 4.2 |
| 건물 이름 (본관, 본부 전산동, 예비 전산동, 1대대 청사, 군수대대 청사) | **일반명사** | 실제 시설명이 아니다 |

### 4.1 `z` 는 층에서 유도된다

16개 자산 전부가 아래 규칙을 만족한다. 검사기가 이것을 강제한다.

```
z = (floor - 1) * building.floor_height_m + 1.0
```

- B-DC / B-DR 1층: (1-1) * 4.2 + 1.0 = **1.0**
- B-HQ / B-1BN / B-LOG 2층: (2-1) * 3.6 + 1.0 = **4.6**

마지막 항 **1.0 m 는 바닥에서 장비까지의 높이**로 읽힌다. 그 값 자체는 **출처 미상,
저작 가정**이고, 규칙이 16개 전부에서 성립하는 것은 **측정으로 확인한 사실**이다. 원래
저자가 이 규칙을 의식했는지는 기록이 없다. 규칙을 세운 것은 이 문서이고, 그 뒤로는
검사기가 지킨다.

### 4.2 `source` 는 `asset-register` 였고 그것은 사실이 아니었다

16개 자산 전부가 `geo.source` 를 `asset-register` 로 적고 있었는데, 위 4절이 말하듯
**실제 자산대장도 실제 도면도 입력에 없었다.** 좌표는 이 파일의 `geo.facility` 배치도
위에 저작한 것이고, 그 배치도 자체가 이중화 구조가 읽히게 그린 그림이다.

tacnet-01 이 2026-09-19 에 같은 문제를 고쳐 13개 자산 전부를 `authored-on-dem` 으로
통일했다(커밋 4f3cb36. 좌표는 그대로 두고 `source` 라벨과 `accuracy_m` 만 바꿨고,
`steps[*]` 산출값은 diff 0 이었다). defnet-01 은 그때 빠졌고 2026-10-14 에 같은 방식으로
고쳤다 - 16개 전부 **`authored-on-facility`**. 값의 꼴이 tacnet-01 과 같다: `authored-on-`
뒤에 좌표를 저작한 바탕(tacnet 은 DEM, 여기는 `geo.facility` 배치도)을 적는다. 좌표는
한 자리도 바뀌지 않았고 `parity.mjs` 는 1622 값 / 불일치 0 이다.

`geo._not_ip_geolocation` 도 "자산대장 정보다" 라고 적고 있었고 같은 이유로 틀렸다.
지금은 저작 좌표라고 적는다.

`accuracy_m` 필드가 없는 것은 이 시나리오에서는 맞는 선택이다. 선언할 정확도가 없다.
tacnet-01 이 `accuracy_m` 을 30 으로 맞춘 것은 DEM 격자라는 바탕이 있어서였고, 여기에는
그에 대응하는 것이 없다.

## 6. 엔진 산출값은 재현된다

```powershell
.\scripts\Export-ReplayData.ps1
node ui\tools\parity.mjs                   # 불일치 0
.\scripts\Test-ScenarioInvariants.ps1      # 아래 세 값을 매번 다시 확인한다
```

검사기가 못 박는 **현재** 값 (method = weighted, 스냅샷):

| 입력 | M-C2 | M-LOG |
|---|---|---|
| DC01 침해 1.0 단독 | **0.0%** | 0.0% |
| DC01 + DC02 침해 1.0 | **84.4%** | 50.2% |
| ESX01 격리(침해 1.0) | **100.0%** | 21.8% |

첫 행이 0.0% 인 것이 이 시나리오의 요점이다. DC01 하나만으로는 임무가 멀쩡한데(S-DIR 이
DC02 로 이중화돼 있다) DC02 까지 가면 84.4% 다. 그리고 **격리가 공격보다 비싸다** -
ESX01 을 격리하면 공격이 아무것도 하지 않은 상태에서 M-C2 가 100.0% 가 된다. ADR-0014 가
이것을 데모의 핵심으로 꼽는다.

**이 백분율들은 저작한 가중치의 함수다.** 할 수 있는 주장은 부호에 관한 것("이중화
처리를 빼먹으면 과잉경보가 난다", "봉쇄가 공격보다 비쌀 수 있다")이고, 크기에 관한
것("실제로 84% 저하된다")은 아니다.

2026-10-14 부터 `mission.json` `notes[6]` 와 `geo._redundancy_note` 도 같은 값을 적는다.
세 곳(데이터, 이 문서, 검사기)이 어긋나면 검사기가 떨어진다.

## 7. 교전이 시작하는 거점 (`wargame.foothold`)

| 값 | 출처 | 비고 |
|---|---|---|
| `wargame.foothold` = WKS003, 0.5 | **저작 결정** | 자산은 침해 체인의 `victim_entry` 와 같고, 수준은 시작 카드가 제공하는 두 값(0.5 거점 / 0.8 자격증명) 중 낮은 쪽이다 |

이 선언이 없던 2026-10-14 오전까지 `game.js` `defaultFoothold()` 가 리플레이의 첫 침해
상태를 교전 거점으로 집어왔다. 그 값은 `attack-chain.json` `states[0]` 의 WKS003 **0.3**
이고 `attack.js` 의 거점 임계값 0.5 에 미달하므로, **이 시나리오에서 자기 기본값으로
교전을 시작하면 공격자의 합법 수가 0 이었다.** 게임이 1턴 전에 끝난다.

**0.3 을 올려서 고치지 않았다.** 위 5절이 말하듯 `states` 는 전파 입력이고, 0.3 이
임계값 아래인 것은 사고가 아니라 맞는 서술이다 - 메일 첨부 스크립트가 돌았다는 것만
가지고는 아직 쓸 수 있는 거점이 아니다. 출력(게임이 시작되는가)을 고치려고 입력(시점별
침해 판정)을 바꾸는 것은 이 문서가 존재하는 이유인 바로 그 동작이다. 그래서 전파 입력은
그대로 두고 **교전용 거점을 따로 선언**했다. 두 값이 다른 것이 의도다.

tacnet-01 은 선언하지 않는다. 그쪽 타임라인의 첫 침해가 CO2-VEH 0.5 이고 그대로 쓸 수
있기 때문이다. 그것이 우연히 성립하는 것이므로 검사기가 매번 확인한다.

읽는 쪽은 둘이다. `ui/src/ui/Wargame.jsx` `startFoothold()` 가 시작 카드의 기본값으로
쓰고, `ui/tools/verify-scenarios.mjs` `checkWargameFoothold` 가 **이 선언으로 실제
게임을 시작해 합법 수를 센다.** 0 이면 게이트가 떨어진다. 같은 검사가 선언이 없는
시나리오에는 `defaultFoothold()` 폴백에 대해 돈다. 검사가 공허하지 않다는 것도 같이
확인한다 - 같은 자산을 0.01 로 두면 합법 수가 0 이어야 한다.

같은 파일의 `checkGraphMirror` 는 `mission.json` 과 리플레이에 박힌 `graph` 사본이
같은지 본다. UI 는 `mission.json` 을 열지 않고 리플레이의 사본을 읽으므로(ADR-0003),
`mission.json` 만 고치고 `Export-ReplayData.ps1` 을 다시 돌리지 않으면 화면에는 아무
변화가 없다. 커밋 4f3cb36 이 재export 를 같이 한 이유가 그것이다.

이번에도 같이 돌렸다. `Export-ReplayData.ps1 -Scenario scenarios\defnet-01\mission.json`
의 산출물은 **`generated` 타임스탬프 한 줄을 빼고 전부 동일**했다 - `steps[*]` 의
mission/task/service/asset/whatif 가 diff 0 이다. 위 세 수정이 어느 것도 엔진 입력이
아니었다는 두 번째 증거이고, 첫 번째는 패리티 1622 값 / 불일치 0 이다.
