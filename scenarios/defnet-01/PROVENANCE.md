# defnet-01 - 숫자의 출처

> **이것은 가상 훈련 시나리오이고 실제 부대 배치가 아니다.** 실제 부대편성·임무계획·
> 자산대장을 쓰지 않았고, 실제 건물이나 전산실 위치도 쓰지 않았다. 이 시나리오는 위경도
> 앵커가 **없다** - 좌표는 지구상 어디에도 놓이지 않으며 지도 위젯에 올릴 수 없다.
> `georef` 블록이 없는 것은 누락이 아니라 결정이다.

출처 표기 어휘는 [`../README.md`](../README.md) 에 있다.

---

## 0. 먼저: 이 파일 안에 낡은 수치가 있다

`mission.json` 의 두 곳이 **ADR-0020 이전에 측정한 값**을 "실측 확인" 으로 적고 있고,
지금 엔진은 다른 값을 낸다.

| 적혀 있는 값 | 어디 | 현재 엔진 값 | 왜 달라졌는가 |
|---|---|---|---|
| DC01 단독 0.0% | `notes[6]`, `geo._redundancy_note` | **0.0%** | 그대로다 |
| DC01+DC02 M-C2 **80.5%** | `notes[6]`, `geo._redundancy_note` | **84.4%** | ADR-0020 이 `requires` 12건에 `hard` 를 붙였다 |
| ESX01 격리 첫 행 **70.1%** | `notes[6]` | **100.0%** (M-C2) | 같은 이유 |

`docs/11-tactical-time-axis.md` 111~112행, `docs/07-synthetic-data.md` 83·150행,
`docs/10-limitations.md` 128행은 **이미 고쳐져 있다**(괄호로 "ADR-0020 이후" 를 달았다).
고쳐지지 않은 것은 데이터 파일이다. 80.5% 의 출처는 `docs/15-propagation-functions.md`
132행의 `weighted` 계산 예시이고, 그 예시는 `hard` 가 없던 시절의 것이다.

**이 파일에서 그 문자열을 고치지 않았다.** 시나리오 데이터의 수치를 손대지 않는 것이 이
작업의 제약이었다. 대신 현재 값을 여기 적고, 검사기가 매 게이트 실행마다 현재 값을 다시
확인한다(아래 6절). `notes[6]` 와 `geo._redundancy_note` 의 두 수치는 **낡은 기록으로
읽어야 하고, 인용하면 안 된다.**

## 1. 임무·단계·작업

| 값 | 출처 | 비고 |
|---|---|---|
| `missions[].priority` = 1(지휘통제), 2(군수지원) | **출처 미상, 저작 가정** | 서열만 의미가 있다. 저하도 계산은 priority 를 읽지 않는다 |
| `tasks[].criticality` = 1.0 / 1.0 / 0.8 / 0.9 | **출처 미상, 저작 가정** | 소요 집계 0.8 과 보급 지시 0.9 의 차이에 근거가 없다 |
| `phases[]` 4개 (window 없음) | **저작 결정** | 시간축을 넣지 않는다는 결정이고 ADR-0017 1항이 근거다. window 가 없으면 엔진이 모든 단계를 활성으로 본다 |
| `units[]` 사령부-1대대-군수대대 | **저작 가정** | 제대 이름은 일반명이다 |

| 값 | 출처 | 비고 |
|---|---|---|

| `edges.depends_on[].w` = 0.8 (MAIL01→S-DIR), 0.9 (FS01→S-DIR), 0.5 (DB01/DB02→S-DIR), 0.7 (WEB01→S-DB) | **출처 미상, 저작 가정** | 대상이 **서비스 id** 인 것은 저작 결정이고 근거가 있다. 자산에 직접 걸면 이중화를 우회해 과잉 저하가 계산된다(2026-09-05 실측) |

| `edges.communicates_with` 16쌍 | **저작 가정** | 논리 통신 관계이고 물리 전송로(`links[]`)와 다른 층이다. 복사본이 아니다 |

## 3. 전송로

| 값 | 출처 | 비고 |
|---|---|---|
| `links[]` 15건, 2계층 구조(SW01 코어 / FW01 경계) | **저작 결정** | 2026-09-07 추가. 방화벽을 두 구간 경계에 놓은 것은 국방망의 통상적인 구간 분리 형태를 따른 것이고, 동시에 "워크스테이션에서 서버로 가는 모든 트래픽이 지나는 지점" 을 그래프에 한 노드로 명시하기 위한 것이다 |

| 부대별 액세스 스위치가 **없다** | **의도적 추상화** | `_links_note` 가 적는다. FW01 이 사용자 구간의 집선 지점을 겸한다 |

## 4. 시설 배치 (표시 전용. 판단에 들어가지 않는다)

이 시나리오는 지형장(terrain)을 넣지 않고 시설 배치(facility)만 넣는다. 국방망 자산은
건물 안에 있고 "어느 능선에 있는가" 는 의미가 없다. 의미가 있는 것은 **이중화 쌍이 같은
건물에 있는지 다른 건물에 있는지**다.

| 값 | 출처 | 유도 과정 또는 근거 |
|---|---|---|
| `frame.extent` = x [0,300], y [0,220], z [0,20] | **저작 가정** | 영내 300 x 220 m. 크기를 고른 근거는 기록돼 있지 않다 |
| `frame.grid_step_m` = 50 | **저작 가정** | 표시 격자 간격 |
| `facility.buildings[].polygon` 5개 (전부 축평행 사각형) | **저작 가정** | **어떤 실제 도면에서도 유도하지 않았다.** 이중화 구조가 읽히게 그린 그림이다 |
| `floors` = 4 / 2 / 1 / 2 / 2 | **출처 미상, 저작 가정** | |
| `floor_height_m` = 3.6 (사무 건물) / 4.2 (전산동) | **출처 미상, 저작 가정** | 전산동이 더 높은 것은 그럴듯하지만 그 근거가 기록돼 있지 않다. 건축 기준에서 가져온 값이 **아니다** |
| `asset.geo.at.z` = 1.0 (1층) / 4.6 (2층) | **유도값** | 아래 4.1 |
| `asset.geo.source` = "asset-register" (16개 전부) | **부정확한 자기 기술** | 아래 4.2 |
| 건물 이름 (본관, 본부 전산동, 예비 전산동, 1대대 청사, 군수대대 청사) | **일반명사** | 실제 시설명이 아니다 |

### 4.1 `z` 는 층에서 유도된다

16개 자산 전부가 아래 규칙을 만족한다. 검사기가 이것을 강제한다.

```
z = (floor - 1) * building.floor_height_m + 1.0
```

- B-DC / B-DR 1층: (1-1) * 4.2 + 1.0 = **1.0**
- B-HQ / B-1BN / B-LOG 2층: (2-1) * 3.6 + 1.0 = **4.6**

마지막 항 **1.0 m 는 바닥에서 장비까지의 높이**로 읽힌다. 그 값 자체는 **출처 미상,
저작 가정**이고, 규칙이 16개 전부에서 성립하는 것은 **측정으로 확인한 사실**이다. 원래
저자가 이 규칙을 의식했는지는 기록이 없다. 규칙을 세운 것은 이 문서이고, 그 뒤로는
검사기가 지킨다.

### 4.2 `source` = "asset-register" 는 사실이 아니다

16개 자산 전부가 `geo.source` 를 `asset-register` 로 적는데, 위 4절이 말하듯 **실제
자산대장도 실제 도면도 입력에 없었다.** tacnet-01 은 2026-09-19 에 같은 문제를 고쳐
13개 자산 전부를 `authored-on-dem` 으로 통일했다(커밋 4f3cb36). defnet-01 은 고쳐지지
않았다.

`accuracy_m` 필드가 없는 것은 이 시나리오에서는 맞는 선택이다. 선언할 정확도가 없다.

**데이터를 손대지 않았으므로 이 문자열은 그대로 남아 있다.** 읽을 때 `asset-register` 를
"실측" 으로 읽지 않는다.

## 6. 엔진 산출값은 재현된다

```powershell
.\scripts\Export-ReplayData.ps1
node ui\tools\parity.mjs                   # 불일치 0
.\scripts\Test-ScenarioInvariants.ps1      # 아래 세 값을 매번 다시 확인한다
```

검사기가 못 박는 **현재** 값 (method = weighted, 스냅샷):

| 입력 | M-C2 | M-LOG |
|---|---|---|
| DC01 침해 1.0 단독 | **0.0%** | 0.0% |
| DC01 + DC02 침해 1.0 | **84.4%** | 50.2% |
| ESX01 격리(침해 1.0) | **100.0%** | 21.8% |

첫 행이 0.0% 인 것이 이 시나리오의 요점이다. DC01 하나만으로는 임무가 멀쩡한데(S-DIR 이
DC02 로 이중화돼 있다) DC02 까지 가면 84.4% 다. 그리고 **격리가 공격보다 비싸다** -
ESX01 을 격리하면 공격이 아무것도 하지 않은 상태에서 M-C2 가 100.0% 가 된다. ADR-0014 가
이것을 데모의 핵심으로 꼽는다.

**이 백분율들은 저작한 가중치의 함수다.** 할 수 있는 주장은 부호에 관한 것("이중화
처리를 빼먹으면 과잉경보가 난다", "봉쇄가 공격보다 비쌀 수 있다")이고, 크기에 관한
것("실제로 84% 저하된다")은 아니다.
