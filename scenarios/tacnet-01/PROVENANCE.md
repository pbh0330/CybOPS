# tacnet-01 - 숫자의 출처

> **이것은 가상 훈련 시나리오이고 실제 부대 배치가 아니다.** 실제 부대편성·임무계획·
> 자산대장을 쓰지 않았다. 좌표는 공개된 훈련 지역(강원 인제 일대)의 실지형 위에 저작한
> 가상 배치이고, 그 지역에 이런 부대가 이렇게 배치돼 있다는 뜻이 전혀 아니다(ADR-0025).

출처 표기 어휘는 [`../README.md`](../README.md) 에 있다. 요약하면 **공개 자료 / 유도값 /
도구 산출 / 저작 가정 / 출처 미상, 저작 가정** 다섯 가지이고, 아래에서 마지막 칸이 가장
많다.

`cause_labels` 는 5종을 선언하는데 이 파일이 실제로 쓰는 것은 mobility, terrain, unknown

입력으로 들어오고, 엔진이 거부(deny) 결과로만 `cause=attack` 을 만든다(ADR-0017 3항,
`scripts/Test-Ontology.ps1` 이 강제한다). `maintenance` 는 선언만 돼 있고 쓰이지 않는다.

### 4.1 `approximation_error_m` = 90 은 상한이고, 실측은 그보다 작다

선언된 식은 cos 를 앵커 위도에 고정한 등장방형(equirectangular) 근사다.

```
lon = anchor.lon + x / (111320 * cos(anchor.lat))
lat = anchor.lat + y / 111320
```

검사기(`ui/tools/verify-scenarios.mjs` `checkGeoref`)가 extent 전체를 240 x 180 격자로
훑어 WGS84 기준(위도·경도 1도 길이 급수)과의 어긋남을 재면

- 동서 방향 최대 **30.4 m**
- 남북 방향 최대 **52.0 m**
- 합(유클리드) 최대 **56.7 m**, 위치는 AO 북동 모서리 (x=24000, y=18000)

파일의 주석이 말하는 메커니즘(cos 를 앵커 위도에 고정)만 따로 떼어 재면, 즉 111320 m/도를
참값으로 두고 cos 고정의 효과만 보면 같은 모서리에서 동서 **53.1 m** 다.

**어느 분해로 재도 90 m 에 못 미친다.** 주석의 "북쪽 가장자리에서 동서 방향 최대 약 90 m"
라는 문장은 **재현되지 않는다**. 선언값 90 은 안전 쪽으로 올린 **상한**으로 읽어야 하고,
그 상한으로서는 유효하다.

검사기는 **동일성이 아니라 상한**을 건다: 실측 합이 선언값을 넘으면 실패하고, 넘지 않으면
`--verbose` 에서 실측값을 출력한다. 선언이 상한이라는 것이 이 값의 정확한 성격이다.

### 4.2 참고: z12 DEM 지상 해상도

```
40075016.686 / (2^12 * 256) * cos(38.02 deg) = 30.11 m
```

웹 메르카토르 타일 한 변 256 px, 줌 12 에서의 적도 해상도에 앵커 위도의 cos 를 곱한 값이다.
`accuracy_m` = 30 과 같은 크기인 것은 **관찰**이고, 저자가 그렇게 유도했다는 기록은 없다.

## 6. 데이터에 없는 숫자 (없다고 적는다)

지어내지 않은 것도 기록할 값이 있다.

- **베어러 용량과 지연이 없다.** `links[].bearer` 는 `wired` / `satcom` / `vhf` 범주뿐이고
  kbps 도 ms 도 없다. 전술망의 핵심 성질인 **저대역폭 성능 저하**(끊김이 아니라 느려짐)가
  미모델링이라는 뜻이다. `docs/03-mission-ontology.md` 9절이 같은 공백을 적는다.
  **여기에 그럴듯한 숫자를 넣지 않는다.** 그 숫자는 출처가 없을 것이고, 있으면 저하도
  계산이 그것을 읽기 시작할 것이다.
- **편성 규모가 없다.** 중대에 지휘차가 몇 대인지 모델링하지 않는다. 자산 13개는 의존
  구조를 그릴 최소 집합이다.
- **가시선·전파 모델이 없다.** terrain 단절은 DEM 으로 계산한 것이 아니라 손으로 놓은
  구간이다(위 3절).

## 7. 엔진 산출값은 재현된다

위 입력에서 나오는 모든 저하도 수치는 **도구 산출**이고 한 줄로 재현된다.

```powershell
.\scripts\Export-ReplayData.ps1            # PowerShell 참조 구현이 리플레이를 쓴다
node ui\tools\parity.mjs                   # JS 포트와 1622 값 대조, 불일치 0 이어야 한다
.\scripts\Test-ScenarioInvariants.ps1      # 아래 두 이야기를 매번 다시 확인한다
```

검사기가 못 박는 이 시나리오의 두 이야기:

- **95~125분 구간의 저하는 공격이 아니다.** t=105 에서 `mission_attack[M-C2]` = 0.0%,
  `mission_env[M-C2]` = 79.0%. 상황도가 언덕을 적의 소행으로 보고하면 안 된다는
  ADR-0012 2항이 수치로 확인된다.
- **도달하지 못하는 이중화는 이중화가 아니다.** 300~345분 위성 단절 구간에서 전역
  `service[S-C2MSG]` 는 0.0% 인데 대대 지휘소에서 수행하는 `task[T-CTRL]` 은 100.0% 다.
  S-C2MSG 는 TOC-SRV/BN-SRV 이중화인데 대대에서 TOC-SRV 에 도달하지 못한다.
  `notes[0]` 의 주장이고, 정적 그래프로는 표현되지 않는 전술망의 성질이다.

이 시나리오는 `wargame.foothold` 를 **선언하지 않는다.** `game.js` `defaultFoothold()`
가 `attack-timeline.json` 의 첫 침해 상태(CO2-VEH 0.5)를 집어오고, 그것이 `attack.js`
의 거점 임계값 0.5 를 넘으므로 교전이 시작된다. **그것은 우연히 성립하는 것이다** -
defnet-01 은 같은 자리가 0.3 이어서 합법 수가 0 이었고, 그래서 거기는 교전용 거점을
따로 선언한다(`scenarios/defnet-01/PROVENANCE.md` 7절). 여기서는 선언이 없어도 되는
것이 아니라 선언 없이 맞는 것이므로, `ui/tools/verify-scenarios.mjs`
`checkWargameFoothold` 가 폴백 값으로 실제 게임을 시작해 합법 수를 매번 센다. 첫 침해
수준이 내려가면 게이트가 떨어진다.

**79.0% 와 100.0% 는 저작한 가중치의 함수다.** 구조에 관한 주장("기동 단절은 공격이
아니다", "도달성 없는 이중화는 무의미하다")은 이 데이터로 할 수 있고, 수치 자체에 관한
주장("실제로 79% 저하된다")은 할 수 없다.
