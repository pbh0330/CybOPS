# 05. 데이터 수명주기 정책 — 받고, 뽑고, 지운다

## 왜 이 문서가 있는가

이 과제가 쓰는 공개 데이터셋은 합치면 테라바이트급이다. 로컬 디스크에 영구 보관하는 것은
불가능하고 필요하지도 않다. 정책은 하나다.

> **원본은 임시 자원이다. 영구 자산은 원본에서 뽑아낸 파생물이다.**

원본을 지운 뒤에도 (1) 결과를 재현할 수 있고 (2) 상황도 데모를 돌릴 수 있어야 한다.
그 두 가지를 보장하는 것이 아래 규칙의 전부다. (ADR-0010)

## 4단계 수명주기

```
 [1] ACQUIRE ──▶ [2] DISTILL ──▶ [3] VERIFY ──▶ [4] PURGE
  원본 다운로드    파생물 생성      파생물 자립성   원본 삭제
                                   확인 (게이트)
      │                │                              │
      ▼                ▼                              ▼
  data/raw/       data/processed/                 raw 비움
  (임시)          (영구, 백업 대상)                manifest만 남음
```

### [0] PLACE — 어느 볼륨에 둘지 정한다

**F:가 1순위, C:가 예비다.** 취득 스크립트는 경로를 직접 하드코딩하지 말고
`scripts/Get-DataRoot.ps1`에 물어본다.

```powershell
$root = .\scripts\Get-DataRoot.ps1 -Dataset optc -NeedGB 60
.\scripts\Get-DataRoot.ps1 -Report        # 현재 용량 현황
```

| 순위 | 경로 |
|---|---|
| 1 | `F:\mc-cycop-data\raw` |
| 2 | `C:\mc-cycop-data\raw` |

규칙 세 가지다.

1. **예비 공간 50GB를 남긴다.** 볼륨이 꽉 차면 Windows까지 같이 죽는다.
   `F: 여유 − 필요량 < 50GB`일 때만 C:로 넘어간다.
2. **하나의 데이터셋을 두 볼륨에 쪼개지 않는다.** 매니페스트와 PURGE가 데이터셋
   단위로 동작하므로, 배치 단위도 데이터셋이어야 한다.
3. **이미 파일이 있으면 그 볼륨을 유지한다.** 정책보다 기존 위치가 우선이다.
   부분 다운로드 중에 목적지가 바뀌면 이어받기가 깨진다. 크기가 아니라 **파일 존재
   여부**로 판단한다 — 몇 MB짜리 초기 조각은 GB로 반올림하면 0이 되어 "없음"으로
   오판된다(실제로 겪은 버그다).

용량이 부족하면 스크립트는 **조용히 넘어가지 않고 예외를 던진다.** 사흘 뒤에
디스크가 차서 실패하는 것보다 시작 전에 실패하는 편이 낫다.

### [1] ACQUIRE — 받는다

- 받기 전에 `docs/01-datasets.md`의 크기 표와 현재 여유 공간을 대조한다.
- **한 번에 한 데이터셋만.** 부분 받기가 가능하면 부분만 받는다(OpTC는 호스트/일자 단위,
  AIT는 테스트베드 단위로 쪼갤 수 있다).
- 받는 즉시 `data/raw/<dataset>/MANIFEST.json`을 쓴다:
  ```json
  {
    "dataset": "optc",
    "subset": "ecar/evaluation/23Sep19",
    "source_url": "...",
    "downloaded_at": "2026-09-05T12:00:00+09:00",
    "files": [{"path": "...", "bytes": 123, "sha256": "..."}],
    "license": "...",
    "redistributable": false
  }
  ```
  이 매니페스트는 **원본을 지운 뒤에도 저장소에 남는다.** 재취득 지시서이자 출처 증빙이다.
- `data/raw/`는 읽기 전용으로 취급한다. 압축 해제도 가능하면 스트리밍으로 처리하고
  전체 해제본을 만들지 않는다.

#### ACQUIRE 실전 교훈 (2026-09-05, AIT 취득 중 실측)

같은 사고를 다시 겪지 않도록 남긴다. 취득 스크립트를 새로 짤 때 반드시 읽을 것.

1. **Zenodo는 게스트 요청을 레이트리밋한다 (HTTP 429).** 동시 3개 다운로드 + 사전 HEAD
   일괄 조회로 즉시 차단당했다. → **동시 연결 1개, HEAD는 파일당 1회 받기 직전에만.**
   차단되면 2분 정도면 풀린다.
2. **`curl --retry` 를 쓰지 말 것.** 재시도 시 `-o` 대상 파일을 0바이트로 잘라버렸다.
   6.6GB 중 120MB를 날렸다. → **재시도는 바깥 루프에서 `-C -` 로 이어받는다.**
   Zenodo는 GET Range를 지원한다(206 확인). HEAD에 Range를 주면 200이 오지만 이는 무의미하다.
3. **같은 파일에 두 프로세스를 붙이지 말 것.** 큐 스크립트가 중복 실행되어 4개 러너가
   동시에 돌았다. 파일 하나당 프로세스 하나를 보장하는 구조로 짠다.
4. **PowerShell 5.1은 BOM 없는 UTF-8 스크립트를 잘못 읽는다.** 한글 주석이 섞인 배열에서
   8개 중 7개만 인식되어 파일 하나가 조용히 누락됐다. → **취득 스크립트는 ASCII로만 작성**하고,
   시작 시 `file count = N`을 로그에 찍어 검증한다.
5. **매 시도마다 파일 크기가 줄었는지 검사한다.** 줄었으면 truncate이므로 즉시 중단하고
   로그에 남긴다. 조용히 재시작하면 며칠을 날린다.
6. 실측 속도는 단일 연결 기준 **0.75~1.7 MB/s**. AIT 전체 130GB는 하루 이상 걸린다고 보고
   일정을 잡는다. 병렬로 올리려다 429를 맞으면 오히려 느려진다.

### [2] DISTILL — 뽑는다

원본에서 아래 파생물을 만든다. 이것들이 영구 자산이다.

| 파생물 | 경로 | 대략 크기 | 용도 |
|---|---|---|---|
| **OCSF 정규화 이벤트** (Parquet, 관심 구간만) | `data/processed/<ds>/events/` | 원본의 1~5% | 상황도 리플레이 |
| **데모 슬라이스** — 시연용 몇 시간 구간 전체 | `data/processed/<ds>/demo/` | 수백 MB 이하 | 데모·테스트 고정 입력 |
| **그라운드트루스 라벨** | `data/processed/<ds>/labels/` | 수 MB | 평가 |
| **엔티티 사전** — 호스트·계정·자산 ID 매핑 | `data/processed/<ds>/entities/` | 수 MB | L2 조인 |
| **집계 통계** — 필드 분포, 카디널리티, 시간대별 볼륨 | `data/processed/<ds>/stats/` | KB | 합성 데이터 생성 파라미터 |
| **학습 완료물** — 경량 ML 모델 가중치, RAG 인덱스 | `models/`, `.chroma/` | 수십 MB | 런타임 |
| **평가 산출물** — 지표, 예측값 덤프 | `eval/results/` | 수 MB | 논문 표 |

집계 통계가 조용히 가장 중요하다. 원본을 지운 뒤 **비슷한 성질의 합성 데이터를 다시 만들 수
있게 해주는 것**이 이 통계다. AIT 테스트베드 재생성 경로와 직접 연결된다.

파생 코드 규칙:
- 원본을 한 번만 순회(single pass)해서 필요한 파생물을 전부 뽑는다. 원본을 지운 뒤
  "아 그것도 뽑을걸" 하는 상황을 만들지 않기 위해, 파생 스크립트를 짜기 전에
  **뽑을 항목 목록을 먼저 확정**한다.
- 모든 파생물에 `_provenance.json`을 붙인다: 입력 매니페스트 해시, 코드 커밋, 실행 시각,
  파라미터.

### [3] VERIFY — 자립성을 확인한다 (삭제 게이트)

원본 삭제 전에 아래를 전부 통과해야 한다. 하나라도 실패하면 지우지 않는다.

- [ ] 파생물만으로 리플레이 데모가 끝까지 돈다 (원본 디렉터리를 rename해두고 실행해 확인)
- [ ] 평가 하네스가 파생물만으로 지표를 재계산한다
- [ ] `MANIFEST.json`에 재취득에 필요한 URL·부분 지정자가 전부 있다
- [ ] `_provenance.json`이 모든 파생물에 존재한다
- [ ] 파생물이 별도 위치에 백업되어 있다 (외장 디스크 또는 클라우드)
- [ ] 재취득 비용을 감당할 수 있다 (수백 GB 재다운로드가 현실적인가? 아니면 보관 유지)

### [4] PURGE — 지운다

- 삭제는 `data/raw/<dataset>/` 단위로만 한다. `data/processed/`는 절대 자동 삭제하지 않는다.
- 삭제 로그를 `data/PURGE_LOG.md`에 남긴다: 데이터셋, 삭제 시각, 회수 용량, 게이트 통과 확인자.
- 삭제 후 해당 데이터셋의 상태를 `docs/01-datasets.md` 상태 표에 `purged`로 갱신한다.

## 하드 규칙

1. **`data/processed/`, `models/`, `eval/results/`는 삭제 대상이 아니다.** 어떤 정리
   스크립트도 이 경로를 건드리지 않는다.
2. **삭제는 사람이 확인한 뒤 실행한다.** 자동 정리 크론을 만들지 않는다.
3. **원본 삭제 후 그 데이터셋에 대한 새 실험을 하려면 재취득한다.** 파생물을 원본처럼
   재해석해서 쓰지 않는다(파생 과정에서 이미 필터·샘플링이 들어갔다).
4. **라이선스상 재배포 불가인 원본은 파생물도 공개 배포하지 않는다.** 매니페스트의
   `redistributable` 필드를 기준으로 판단한다. 논문 부록에 넣을 수 있는 것은 대개
   집계 통계와 지표뿐이다.

## 권장 진행 순서 (용량 부담 순)

작은 것부터 파이프라인을 완성하고, 큰 것은 파이프라인이 검증된 뒤에 받는다.
이 순서를 지키면 대용량 데이터셋의 체류 시간이 최소화된다.

1. **AIT-LDS v2.0** (수십 GB, Zenodo) — 그라운드트루스가 깔끔하고 재생성 가능. 파이프라인
   개발용 1순위.
2. **LANL Comprehensive** (약 12GB 압축) — 압축 대비 규모가 크고 포맷이 단순(CSV).
   불균형 실험용.
3. **DARPA TC** (서브셋 단위) — ATT&CK 정렬 라벨. 기법 단위 평가용.
4. **DARPA OpTC** (대용량) — 마지막. 부분 다운로드로 필요한 호스트·일자만.

## 도구 (예정)

`src/data/` 아래에 수명주기 CLI를 둔다.

```
python -m mccycop.data acquire  <dataset> [--subset ...]   # 다운로드 + 매니페스트
python -m mccycop.data distill  <dataset>                  # 파생물 생성
python -m mccycop.data verify   <dataset>                  # 삭제 게이트 검사
python -m mccycop.data purge    <dataset>                  # 게이트 통과 시에만 삭제
python -m mccycop.data status                              # 데이터셋별 상태·용량 표
```

`verify`가 실패하면 `purge`는 거부한다. 이 커플링이 정책의 실질적 집행 수단이다.
