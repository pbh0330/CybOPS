# ADR-0029. AWS 시연 사본 - 정적 번들, 시연 시간에만 모델, 엔진은 클라이언트에

**상태**: 채택 (2026-09-23). 아무것도 대체하지 않는다. ADR-0021 이 정한 세 자세 중
공개 시연 사본이 어느 것을 어떤 근거로 쓰는지를 기록한다.

## 맥락

산출물 1순위가 데모다(ADR-0014). 심사위원이 각자의 브라우저에서 열어 볼 수 있는 공개
사본이 필요해졌다. 지금까지 배포는 `docs/21-deployment.md` 의 산문 절차뿐이었고, 그 절차는
서버가 하나 있다고 가정한다. 서버를 상시로 띄우면 두 가지가 따라온다 - GPU 요금이 계속
나가고, 인증 없는 추론 엔드포인트가 공개된다.

그리고 배포 자세를 고르는 일에는 앞서 닫아 둔 결정이 두 개 걸려 있다. 상태 산출을 결정론
계층이 한다는 것(ADR-0003)과, 엔진의 두 구현이 `parity.mjs` 로 묶여 있다는 것이다.

## 결정

1. **공개 사본은 정적 번들이다.** 비공개 S3 버킷 + CloudFront OAC. 서버 프로세스가 없다.
   *근거*: UI 는 이미 정적 번들이고(ADR-0018) 데이터는 사전 생성된 replay·브리핑 JSON 이다.
   올릴 것이 파일뿐이면 운영해야 할 것도 없다.

2. **엔진은 클라이언트에 남는다. 서버측 엔진을 만들지 않는다.**
   *근거*: tacnet-01(자산 13)에서 `runChain` 1회가 **0.07 ms**(Node 24, 1000회 평균)인데
   서울 리전 왕복은 **10~50 ms** 다. 옮기면 계산이 100~700배 느려지고, 마커 드래그와 시간
   슬라이더가 매 프레임 재계산이라 조작 한 번이 요청 수십 개가 된다. 그리고 구현이 셋이
   된다 - PowerShell 참조, 브라우저 JS, 서버. `ui/tools/parity.mjs` 가 지키는 것은 **둘**
   사이의 1,622개 값 일치이고, 셋이 되면 그 비용이 그대로 늘어난다. 무거운 배치가 필요하면
   같은 `engine.js` 를 Node 에서 돌린다 - 구현은 둘 그대로다.

3. **모델은 시연 시간에만 켜는 GPU 인스턴스다. 평소에는 꺼져 있고, 꺼진 상태가 기본이다.**
   *근거*: 모델 없는 사본이 온전히 동작한다. LLM 출력이 상태값을 정하는 경로를 만들지
   않았기 때문에(ADR-0003) 저하도·원인 분해·봉쇄 비용·교전 점수·격리 순위표·사전 생성
   브리핑과 인용이 전부 그대로 나온다. 빠지는 것은 실시간 LLM 공격자 선택지와 순위표를
   **읽어 주는 문장** 둘뿐이다 - **기능 차이가 아니라 서술 차이다**
   (`docs/superpowers/specs/2026-09-23-staff-officer-design.md` 7절).
   그래서 **꺼진 상태는 고장이 아니라 정상 동작이고**, 화면 문구가 그렇게 읽혀야 한다.

4. **서버측 상태를 두지 않는다.** DB 없음, 세션 없음. 승인 기록·참모 로그·교전장 플랜은
   브라우저 저장소에 남고 JSON 으로 내보낸다.
   *근거*: 상태가 생기면 백업·스키마 이전·개인정보가 따라온다. 시연 사본이 질 부채가 아니다.
   대가는 심사위원 둘이 같은 판을 보려면 파일을 주고받아야 한다는 것이고, 그것을 받는다.

5. **인증은 CloudFront 뷰어 요청 함수의 basic auth 다. 함수는 검사 직후 `authorization`
   헤더를 지운다.**
   *근거*: 도메인이 없어 모델 오리진 구간이 평문 http 다. 자격이 그 구간을 건너가면 안 된다.
   이 성질은 저절로 생기지 않는다 - 함수가 지우기 때문에 생기고, 거기에 더해 `/api/llm/*`
   의 원본 요청 정책을 허용목록(`content-type`, `accept`)으로 둬서 `AllViewer` 가 무엇을
   통과시키는지에 대한 기억에 걸지 않는다. **basic auth 는 관문이지 비밀이 아니다** -
   자격은 배포된 함수 코드에 박히므로 계정 읽기 권한이 있는 사람은 꺼내 볼 수 있다.
   다른 곳에서 쓰는 비밀번호를 넣지 않는다.

6. **직접 접속에 대한 실제 통제는 보안 그룹이다. `X-Demo-Origin` 은 두 번째 겹이다.**
   *근거*: 80/tcp 를 CloudFront 관리 프리픽스 목록
   (`com.amazonaws.global.cloudfront.origin-facing`)에서만 받는다(AWS-1 이 만든다). 비밀
   헤더는 그 목록 **안**의 다른 CloudFront 배포가 이 오리진을 때리는 경우를 막는 용도다.
   **평문 구간의 도청자는 이 헤더를 읽어 재생할 수 있으므로 그 사람에게는 비밀이 아니다.**
   이것을 1차 통제로 적으면 안 된다. 도메인을 확보하면 오리진을 https 로 바꾸고 이 항목은
   사라진다.

7. **스팟 인스턴스를 쓰지 않는다.**
   *근거*: 심사 도중 회수되면 그걸로 끝이다. 아낄 금액은 시연 2시간에 $1 이 안 된다.

8. **접근 로그는 CloudFront 표준 로그만 쌓고 90일 수명주기로 지운다. 유량 제한에 걸린
   요청을 따로 남기지 않는다.**
   *근거*: `docs/21-deployment.md` 6절이 남겨 둔 미결 항목이다. 따로 남기면 "차단된 사람"
   목록이 되고 그것은 개인정보 쪽으로 한 발 들어가는 일인데, 시연 사본에서 그 기록으로 할
   일이 없다. 표준 로그만으로 접속 여부와 경로는 보이고, 90일이면 심사 이후 분석에 충분하다.

## 하지 않는 것

서버측 엔진, 서버측 상태(DB·세션), GPU 상시 가동, 스팟, 계정 관리가 필요한 인증,
AWS 전용 API 를 코드에서 직접 부르는 것(ADR-0007 - Bedrock 을 쓰게 되면 모델 어댑터 뒤에
두고 Ollama 경로를 함께 유지한다). 그리고 **이 저장소의 어떤 스크립트도 AWS 자원을 만들지
않는다** - 스택 생성·삭제는 사람이 친다(ADR-0004 와 같은 자세).

## 결과

- `infra/demo-static.yaml`(비공개 S3 + OAC + CloudFront + 뷰어 함수 + 90일 로그 버킷,
  모델 경로는 `LlmOriginDomain` 이 빌 때 아예 생성되지 않는 조건부 리소스), `infra/README.md`.
- `scripts/Deploy-Aws.ps1`(빌드 → 자세 config → 번들 게이트 → s3 sync 2회 → 무효화 →
  확인 목록), `ui/public/config.aws.example.json`.
- `scripts/Test-ProxyAllowlist.ps1` 이 게이트 목록에 붙었다(9개). 클라이언트가 부르는
  업스트림 경로와 배포 예시의 허용목록이 어긋나면 exit 1 이다 - 실제로 어긋나 있었다
  (클라이언트는 `/api/chat`, 예시는 `/api/generate` 만 허용).
- 절차·비용·확인 목록: `docs/24-aws-demo.md`. `docs/21-deployment.md` 6절의 접속 로그
  항목이 8번으로 닫혔다.

## 재검토 조건

- 도메인과 ACM 인증서를 확보하면 5·6번을 다시 본다(오리진 https, 비밀 헤더 제거).
- 여러 사람이 각자 계정으로 접속해야 하면 5번을 다시 본다.
- 상시 운영 사본이 필요해지면 이 ADR 전체가 아니라 새 ADR 을 쓴다. 이것은 **시연 사본의
  자세**이지 배포 일반의 규칙이 아니다.
