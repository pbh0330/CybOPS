# ADR-0006. 파인튜닝 대신 RAG + 프롬프트 + 평가셋

**상태**: 채택 (2026-09-05)

## 맥락

"LLM 기반"이라고 하면 파인튜닝이 필수인 것처럼 보이지만, 이 과제에서 LLM에 맡긴 역할
(요약·설명·질의 변환)은 대규모 파인튜닝 코퍼스를 요구하지 않는다. 게다가 학습 데이터를
직접 얻기 어려운 상황이다.

## 결정

**파인튜닝하지 않는다.** RAG + 프롬프트 엔지니어링 + 평가셋 구조로 간다.

- 지식 계층: ATT&CK, CVE/CWE, 내부 플레이북, 자산 대장, 과거 사건 기록을 인덱싱
- 골든셋은 학습용이 아니라 **평가용**이다. 따라서 수백 건 규모로 충분하다.
- 소형 모델 파인튜닝은 **옵션으로만 남긴다**: 평가에서 RAG의 한계가 실측된 뒤 검토.

## 근거

- LLM의 역할이 탐지가 아니라 설명이므로(ADR-0003), 필요한 것은 도메인 지식 접근이지
  가중치 변경이 아니다.
- 파인튜닝하면 감사 추적성이 떨어지고(왜 그렇게 답했는지 근거 문서를 못 가리킴) 모델 갱신
  비용이 함께 오른다. 근거 인용 강제(ADR-0009)와 RAG의 궁합이 훨씬 좋다.
- 모델 교체 유연성(ADR-0007)을 유지할 수 있다. 파인튜닝하면 모델을 바꿀 때마다 재학습이다.
- 다만 소규모 파인튜닝이 효과적이라는 근거는 있다: 870개 세션 약 230만 이벤트로
  Qwen2.5-1.5B, Llama-3.2-3B, Phi-4-Mini를 LoRA 파인튜닝한 결과 청크 분류 정확도가
  기본 모델의 약 8%에서 90~97%로 올랐다는 보고. 그래서 **기각이 아니라 보류**다.

## 결과

- RAG 인덱스 품질이 LLM 계층 성능의 병목이 된다. 청킹 전략과 검색 품질을 별도로 평가한다.
- 학습 데이터 확보 부담이 사라진다. 이것이 "공개 데이터만으로 가능하다"의 실질적 근거다.
- 골든셋 구축 공수는 여전히 필요하다(수백 건 수작업).

## 대안

- **처음부터 LoRA 파인튜닝**: 보류. 위 근거대로 평가 결과가 먼저 필요하다.
- **프롬프트만, RAG 없음**: 기각. ATT&CK·플레이북 같은 도메인 지식을 프롬프트에 다 넣을 수 없다.

## 재검토 조건

트랙 C 평가에서 RAG 구성이 특정 과제(특히 ATT&CK 매핑, 구조화 질의 변환)에서 목표에 미달하고,
그 실패가 검색 품질이 아니라 모델 능력에서 오는 것이 확인되는 경우.
