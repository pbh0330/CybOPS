# ADR-0022. 검증은 발행의 일부다

- 상태: 채택
- 날짜: 2026-09-09
- 관련: ADR-0009(모든 응답은 근거를 인용한다), ADR-0003(LLM은 상태를 정하지 않는다),
  ADR-0018(정적 번들), ADR-0021(호스팅 배치)

## 맥락

`docs/20-e3-design.md` 10.8절이 실패 하나를 실측했다. 최우선 임무의 근거가 없을 때
모델이 두 번째 임무를 그 자리에 넣는다. qwen2.5:14b 는 8개 시각 중 6번 그렇게 했다.

문제는 그 브리핑이 **모든 검사를 통과한다**는 것이다.

```
tacnet-01 시각 08:45 (t+165분), 활성 단계는 기동, 표적 획득 [F1]{확신}.
임무 M-FIRE(화력지원, 우선순위 2)의 저하도는 0%다 [F2]{확신}.
링크 L-VHF-CO1(...)이(가) 단절, 원인은 지형, 비고 능선 차폐 [F4]{확신}.
TOC-SRV을(를) 격리하면 임무 저하도가 M-C2 +7.0%p, M-FIRE +40.0%p 변한다 [F8]{확신}.

Test-BriefingCitations.ps1  ->  RESULT: PASS   0 violations
```

문장 넷이 전부 참이고 인용도 전부 유효하다. 없는 것은 **우선순위 1인 지휘통제
임무에 대해 아는 바가 없다는 말** 하나다. 그리고 M-C2 가 마지막 줄에 격리 비용
증분으로 나오기 때문에, 빠진 것이 아니라 문제가 없어서 안 나온 것처럼 읽힌다.

지금 이 브리핑들은 번들에 그대로 들어간다. `ui/public/data/*.brief.json` 은
누군가 손으로 복사해 넣은 것이고, 생성과 번들 사이에 아무 관문이 없다.

UI 쪽에 검사가 조금 있기는 하다. 인용 없는 문장을 `미검증` 으로 표시하고 없는
id 를 붉게 칠한다. 그러나 그것은 **문장 단위**이고, 대체는 문장 단위로는 흠이
없다. 그리고 UI 가 검사를 더 하도록 만드는 것은 같은 규칙을 JavaScript 로 다시
구현하는 일이며, 두 구현은 언젠가 서로 다른 답을 낸다.

## 결정

**검사를 통과하지 못한 브리핑은 번들에 들어가지 않는다.** 검증은 발행 절차의
한 단계이고 선택 사항이 아니다.

`scripts/Publish-Briefings.ps1` 이 그 절차다.

1. 팩 생성 (`New-BriefingPack.ps1`)
2. 브리핑 생성 (`Invoke-Briefing.ps1`)
3. **검사 둘을 돌린다**
   - `Test-BriefingCitations.ps1` - 인용률, 유령 인용, 팩에 없는 숫자, 원인 격상,
     확신도 등급 존재
   - `Test-BriefingCoverage.ps1` - 서술 순서가 요구한 임무를 실제로 다뤘는가
4. 실패하면 다시 생성한다 (기본 3회)
5. 그래도 실패하면 **그 시각의 브리핑은 발행하지 않는다.** UI 는 브리핑이 없는
   시각을 이미 감당한다(패널을 숨긴다).
6. 통과한 브리핑에는 검증 결과를 함께 적어 넣는다.

### 왜 "미검증" 표시가 아니라 미발행인가

ADR-0009 는 근거를 못 붙인 응답을 **UI 에서 `미검증` 으로 표기**하라고 했고 UI 는
그렇게 한다. 그것은 **응답이 이미 존재하는 경우**의 규칙이다. 실시간 경로라면
그 길밖에 없다.

브리핑은 실시간이 아니다. **미리 만들어 번들에 넣는 산출물**이므로 다시 만들
수 있고, 못 만들면 안 넣을 수 있다. 나쁜 것을 알면서 넣고 딱지를 붙일 이유가
없다. 딱지는 고칠 수 없을 때 쓰는 것이다.

### 재생성은 발행 경로에만 있다. 평가 경로에는 절대 없다

4번이 이 문서에서 가장 위험한 줄이다. 실패하면 다시 돌린다는 것은 **통과할 때까지
돌린다**로 쉽게 번지고, 그 숫자를 평가로 가져가면 모델이 실제보다 좋아 보인다.

- **발행**은 산출물을 고르는 일이다. 재시도해도 된다. 고른 것이 어떤 것인지만
  정직하면 된다. 그래서 발행된 브리핑에는 **몇 번째 시도였는지**가 적힌다.
- **평가**는 모델을 재는 일이다. `Compare-BriefingModels.ps1`,
  `Invoke-AbstentionProbe.ps1`, `Invoke-InjectionProbe.ps1` 은 **한 번만 돌리고
  그 결과를 쓴다.** 재시도 옵션이 없고, 넣지 않는다.

두 경로가 같은 스크립트를 쓰지 않는 이유가 이것이다. `Publish-Briefings.ps1` 을
평가에 쓰면 안 된다.

### 모델 선택은 이 결정에 딸려 온다

`docs/20-e3-design.md` 10.8.3 절이 선택을 배치에 걸어뒀다.

| 배치 | 고르는 것 |
|---|---|
| 검사 둘 다 발행 경로에 | **gemma2:9b** |
| 검사가 평가에만 | qwen2.5:7b |

이 ADR 이 왼쪽을 골랐으므로 **기본 모델은 gemma2:9b 다.** 근거:

- 사실 정확성 74~75% (두 표본). 다음이 exaone 65~67%, qwen14b 63~64%,
  qwen7b 50%.
- ECE 0.200~0.209. 넷 중 가장 낮다.
- 유령 인용 8~9건은 `Test-BriefingCitations` 가 그 자리에서 잡는다. 이제 그것이
  발행을 막으므로 화면에 도달하지 않는다.
- 대체 7~8 / 16 은 `Test-BriefingCoverage` 가 잡는다. 같은 이유로 도달하지 않는다.

**qwen2.5:7b 는 대체가 0~1 로 가장 적지만 사실 정확성이 50%다.** 검사가 대체를
잡아주는 배치에서는 그 강점이 쓰이지 않고 약점만 남는다.

대가는 지연 5.6초(qwen14b 의 1.15배, qwen7b 의 3배)와 재시도 횟수다. **발행은
오프라인이므로 지연이 화면 응답에 영향을 주지 않는다.**

라이선스는 확인이 필요하다. gemma2 는 Gemma 사용 제한 정책 준수 의무가 붙는다
(`docs/01-datasets.md` 6절). **연구·데모 범위에서는 문제가 없지만, 배포 형태가
바뀌면 다시 본다.** Apache-2.0 인 qwen2.5 로 되돌리는 비용은 이 ADR 기준으로
`Publish-Briefings.ps1` 의 `-Model` 인자 하나다(ADR-0007).

## 결과

- **번들에 들어간 브리핑은 두 검사를 통과한 것뿐이다.** 통과하지 못한 시각은
  브리핑이 없고, UI 는 그 시각에 패널을 숨긴다.
- **발행 보고서가 남는다.** 어느 시각이 몇 번째 시도에 통과했는지, 어느 시각이
  버려졌는지, 왜 버려졌는지. `eval/results/briefing-publish.json`.
- **검사기를 고치면 발행을 다시 해야 한다.** 검사가 강해지면 전에 통과한 것이
  떨어질 수 있고, 그것이 정상이다.
- UI 는 바뀌지 않는다. 문장 단위 `미검증` 표시는 그대로 두고, 팩 단위 검증은
  발행 시점에 끝난다. **같은 규칙을 두 언어로 구현하지 않는다.**

## 대안과 기각 사유

- **UI 에서 대체를 검사한다.** 리플레이가 브라우저에 있으니 기술적으로는 가능하다.
  그러나 규칙이 PowerShell 과 JavaScript 두 곳에 살게 되고, 언젠가 두 답이 갈린다.
  검사는 결정론 계층에 하나만 둔다. 기각.
- **실패한 브리핑을 `미검증` 딱지와 함께 넣는다.** 실시간이라면 그 길뿐이지만
  이것은 미리 만드는 산출물이다. 다시 만들 수 있는 것에 딱지를 붙이지 않는다. 기각.
- **검사는 CI 에서만 돌리고 발행은 그대로 둔다.** CI 가 빨간불이어도 번들은
  이미 나가 있다. 관문은 발행 그 자체여야 한다. 기각.
- **모델을 qwen2.5:7b 로 유지한다.** 검사가 대체를 잡는 배치에서는 7b 의 유일한
  강점이 중복되고 사실 정확성 24점 손해만 남는다. 기각. 단, 라이선스나 지연
  제약이 바뀌면 `-Model` 하나로 되돌린다.

## 남는 문제

- **재시도 횟수의 상한을 3으로 정한 근거가 없다.** 실측 후 조정한다. 발행
  보고서에 시도 횟수 분포가 남으므로 몇 번 돌려보면 정해진다.
- **`Test-BriefingCoverage.ps1` 은 서술 순서 2번(최우선 임무)만 본다.** 3번(자산과
  링크)과 4번(격리 비용)에 대한 같은 검사는 아직 없다. 2번을 먼저 만든 것은
  거기서 대체가 실측됐기 때문이다.
