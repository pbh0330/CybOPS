# ADR-0027. 교전장 준비도 - 구조 둘, 그리고 엔진의 무공격 기준선

**상태**: 채택 (2026-09-23). 아무것도 대체하지 않는다. ADR-0026(교전 규칙)이 여는 교전의
**입장 조건**을 정한다. 결정 자체는 2026-09-21 교전장 A(브랜치 `ui/sandbox-a`)에서
내려 구현했고, 그때 `docs/23-sandbox.md` 가 이 번호를 전방 참조해 두었다. 이 문서가 그
빈자리를 채운다 - 새 결정이 아니라 이미 도는 코드의 근거를 제자리에 적는 것이다.

## 맥락

교전장 `sandbox-01` 은 임무·단계·작업·서비스만 물려받고 자산과 링크는 비어 있는
파생 시나리오다. 사용자가 자산을 놓고 링크를 잇고 서비스·작업에 붙인 뒤 교전(ADR-0026)을
연다. 문제는 **엔진이 빈 판을 정상으로 읽는다**는 것이다.

`engine.js` 의 `serviceDegFor` 는 제공자가 하나도 없는 서비스를 저하 0 으로 둔다
(`if (!providers.length) { svc[s.id] = 0; continue }`). 이것은 저작 시나리오에서는 맞는
규칙이다 - 제공자를 적지 않은 서비스는 "모델링하지 않은 것" 이지 "죽은 것" 이 아니다.
그런데 교전장에서는 같은 규칙이 **텅 빈 판을 임무 저하도 0% 로** 만든다. 지킬 것이 없는
판에서 교전을 열면 방어자가 아무것도 안 해도 hold 모드는 이긴다.

규칙을 "제공자 없음 = 저하 1" 로 뒤집는 선택지가 있었다. 그러면 저작 시나리오의 숫자,
PowerShell 참조 엔진, `parity.mjs` 가 지키는 1,622개 값이 한꺼번에 움직인다. 교전장 하나를
위해 엔진의 의미를 바꾸는 값이 아니다.

## 결정

**엔진을 고치지 않고 시작을 막는다.** `sandbox.js` 의 `readiness(graph)` 가 세 조건을 다
통과할 때만 `ready` 를 준다. 셋 다 교전장에서만 걸리고 저작 시나리오는 지나가지도 않는다.

| # | 조건 | 판정 | 카드 행 |
|---|---|---|---|
| 1 | **서비스 제공** | 서비스마다 `edges.provided_by` 가 그래프에 실제로 있는 자산을 가리킨다 | `서비스 제공 n/5` |
| 2 | **작업 배치** | 작업마다 `performed_at` 이 그래프에 실제로 있는 자산이다 | `작업 배치 n/8` |
| 3 | **도달성** | 1·2 가 찬 뒤, 엔진의 **무공격 기준선** `runChain(g, {}, { t: -1 })` 에서 모든 작업의 저하가 0 이다 | `도달성 n/8` |

### 1. 세 번째 조건이 왜 있는가 - 구조가 다 차도 판은 죽어 있을 수 있다

`serviceDegFor` 는 제공자의 침해도만 보지 않는다. **소비자에서 제공자로 링크가 닿는지**를
보고, 닿지 않으면 그 제공자를 침해도와 무관하게 저하 1 로 친다.

```js
const eff = providers.map((p) => (reach(snap, consumer, p.to) ? Number(imp[p.to] || 0) : 1))
```

주석이 그 자리에 달려 있다 - "닿지 않는 제공자는 소비자가 앉은 자리에서 죽은 제공자와
구별되지 않는다. 닿지 않는 이중화는 이중화가 아니다." 그래서 서비스 5/5, 작업 8/8 인
판이 공격 없이도 무너질 수 있다.

**실측이 근거다.** 조건 1·2 만으로 `준비 완료` 를 내주던 때, 8자산 7링크로 구조를 다 채운
판을 놓고 교전을 열었더니 **화력지원이 76.2% 저하로 시작**했다. 원인은 링크였다. 중계
게이트웨이가 종단 단말하고만 이어져 서버의 컴포넌트에 들어가지 못했고, 그 뒤에 매달린
워크스테이션과 관측반 단말이 제공자에 닿지 않았다. 구조상으로는 완성이고 기능상으로는
죽은 판이다. 공격자가 한 수도 두기 전에 방어자가 이미 3/4을 잃은 채 시작한다.

세 번째 조건은 그것을 **시작 전에 이름으로** 보인다. 잠금 문구도 갈린다 - 구조가 비어
있으면 `서비스 n·작업 m 이 비어 있다`, 구조는 찼는데 닿지 않으면
`작업 n 이 서비스에 닿지 않는다 (링크 확인)`. 고치는 방법이 다르기 때문이다. 비었으면
자산을 놓아야 하고, 안 닿으면 링크를 이어야 한다.

**구조가 찬 뒤에만 묻는다.** 반쯤 빈 그래프의 기준선은 잡음이다 - 제공자 없는 서비스는
어차피 저하 0 이라 도달성 판정이 아무것도 말해 주지 않는다.

### 2. 링크가 하나도 없는 판은 자기 루프 하나로 프로브한다

엔진의 `reach()` 는 첫 줄에서 `if (!snap.hasLinks) return true` 를 한다. **링크 계층이
없는 그래프는 전송로를 모델링하지 않은 것**으로 보고 전부 도달 가능으로 처리하는 규칙이다.
PowerShell 참조 엔진과 같은 값이고 `parity.mjs` 의 대조 대상이다. **이것은 고칠 버그가
아니라 지킬 동등성이다.**

교전장은 그 경우가 아니다. 자산이 둘 이상인데 링크가 없는 판은 전송로를 안 그린 것이
아니라 **아직 안 이은 것**이다. 그래서 게이트는 자산 2 이상·링크 0 인 판을 **자기 루프
하나**(`_probe`, 첫 자산에서 자기 자신으로)를 붙인 **사본**으로 엔진에 묻는다.

```js
const noLinks = !(g.links || []).length && (g.assets || []).length > 1
const probe = noLinks ? { ...g, links: [{ id: '_probe', a: g.assets[0].id, b: g.assets[0].id }] } : g
```

자기 루프는 연결성을 바꾸지 않는다(`reach` 의 `if (from === to) return true` 는 그
자산 자신에게만 해당한다). 바뀌는 것은 `snap.hasLinks` 하나이고, 그 순간 엔진이 자기
도달성 규칙을 적용하므로 제공자에 링크로 닿지 않는 수행 자산이 전부 잡힌다(9자산 0링크
판이면 8/8이 `닿지 않음`). **판 자체는 손대지 않는다** - `g.links` 는 그대로 `[]` 로
남고, 프로브는 `readiness` 안에서만 사는 사본이다.

자산 **하나**가 서비스와 작업을 전부 제공·수행하는 판은 프로브 없이 준비되고 그것이 맞다.
링크가 필요 없는 판이기 때문이다.

### 3. 막는 것과 세기만 하는 것을 구분한다

- **막는다**: 위 세 조건.
- **세기만 한다**: `고립 자산`(어떤 링크에도 붙지 않은 자산 수). 무채색 강조로 드러내되
  시작을 막지 않는다 - 임무에 안 붙은 예비 자산은 판의 흠이 아니다.
- **모드 하나만 막는다**: 보석 0 이면 `보석 방어` 모드만 잠기고 `버티기` 는 열린다.

## 하지 않는 것

- `serviceDegFor` 의 "제공자 없음 = 저하 0" 규칙을 바꾸지 않는다(저작 시나리오·참조
  엔진·parity 가 같이 움직인다).
- `reach()` 의 "링크 0 이면 전부 도달" 규칙을 바꾸지 않는다(PowerShell 참조와의 동등성).
- 준비도 판정에 `geo` 를 쓰지 않는다. 자산의 좌표는 표시 전용이고 엔진에 안 들어간다
  (ADR-0002, `Test-GeoInvariance`).
- 준비도를 자동으로 채워 주지 않는다. 게이트는 무엇이 비었는지 말할 뿐 링크를 대신 잇지
  않는다 - 무엇이 무엇을 필요로 하는지 배우는 것이 교전장의 절반이다.

## 결과

`ui/src/sandbox.js` `readiness(graph)`(순수), `ui/src/ui/Readiness.jsx`(레일 상단 카드,
교전장에서만), `ui/src/ui/Wargame.jsx` `StartCard` 의 잠금 문구 둘. vitest `sandbox.test.js`
23개가 세 조건·프로브·고립 자산·보석 0 을 덮는다. 상세와 화면은 `docs/23-sandbox.md` 1절,
구현 판단은 `docs/design/decisions.md` "2026-09-21" 절.

참모(ADR-0028)의 `readiness_gap` 질의가 같은 `readiness()` 를 불러 미충족 항목을 사실
문장으로 읽어 준다 - 게이트의 판정과 참모의 답이 두 벌이 되지 않게 함수는 하나다.

## 재검토 조건

- 교전장에 시간축이 들어오면(지금은 `t = -1` 정적) 기준선을 어느 시점에서 잡을지 다시
  정해야 한다. 단계마다 활성 작업이 달라지므로 "모든 작업 저하 0" 의 뜻이 시점에 따라
  달라진다.
- 엔진이 "제공자 없음" 과 "제공자가 안 닿음" 을 원인으로 분리하게 되면(지금은 둘 다 저하
  1 로 합쳐 나온다) 게이트가 엔진의 원인 코드를 읽어 조건 2·3 을 하나로 합칠 수 있다.
- 교전장이 아닌 저작 시나리오에도 이 게이트를 쓰자는 요구가 나오면 다시 본다. 지금은
  저작 시나리오가 게이트를 지나지 않는다 - `sandbox` 플래그가 붙은 판에서만 돈다.
