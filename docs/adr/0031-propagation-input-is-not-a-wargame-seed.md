# ADR-0031. 전파 입력은 교전 거점이 아니다 - 시나리오가 교전 거점을 따로 선언한다

**상태**: 채택 (2026-10-14). 아무것도 대체하지 않는다. ADR-0026(교전 규칙)이 쓰는
**시작 거점**이 어디서 오는지를 정하고, ADR-0003(상태 산출은 결정론 계층)이 말하는
"입력" 과 "출력" 의 경계를 데이터 한 칸에 적용한다.

## 맥락

시나리오의 침해 타임라인(`attack-timeline.json` 의 `steps[].state`,
`attack-chain.json` 의 `states[].state`)은 **엔진 입력**이다. `attack-chain.json` 의
`_states_note` 가 그것을 명시한다 - "결정론 계층이 각 시점에 내렸을 자산 침해 판정.
Invoke-MissionPropagation.ps1 의 입력이 된다." 리플레이에 박힌 저하도 수치는 이 값들의
함수이고, `node ui\tools\parity.mjs` 가 1,622개 값으로 그것을 못 박는다.

교전(ADR-0026)은 같은 그래프 위에서 **다른 것**을 한다. 공격자가 거점 하나에서 시작해
턴제로 수를 둔다. `game.js` 의 `defaultFoothold()` 는 그 시작 거점을 리플레이
타임라인의 **첫 침해 상태**에서 집어왔다.

두 용도를 한 값에 겹쳐 놓은 것이 문제였다. `attack.js` 는 거점 임계값
`FOOTHOLD = 0.5` 를 두고, 침해 수준이 그에 미달하는 자산에서는 아무 수도 내주지 않는다.
defnet-01 의 `states[0]` 은 WKS003 **0.3** 이다 - 초기 침해("메일 첨부 스크립트가
돌았다")의 판정이고, 사다리 0.3 → 0.6 → 0.9 → 1.0 이 `chain[]` 의 관측치에 대응한다.
그래서 **defnet-01 에서 자기 기본값으로 교전을 시작하면 공격자의 합법 수가 0 이었다.**
게임이 1턴 전에 끝난다. 아무 오류도 나지 않는다.

두 소비자가 각자 조용히 보정하고 있었다. 시작 카드는 수준 선택을 0.5/0.8 두 값으로
제한해 0.3 을 0.5 로 끌어올렸고, `verify-scenarios.mjs` 는 `Math.max(0.5, level)` 과
주석 두 줄을 달아 두었다. **주석은 게이트가 아니다.** 화면에서는 멀쩡해 보이고, 선언을
그대로 쓰는 코드는 빈 게임을 받는다.

## 결정

**전파 입력을 올려서 고치지 않는다.** 시나리오가 교전 거점을 따로 선언한다.

```json
"wargame": {
  "foothold": {"id": "WKS003", "level": 0.5}
}
```

1. `mission.json` 루트의 `wargame.foothold` 가 교전 시작 거점이다. 없으면 기존
   폴백(`defaultFoothold()`)이 그대로 돈다. 즉 선언은 **필수가 아니고**, 타임라인 첫
   침해가 이미 쓸 수 있는 수준인 시나리오(tacnet-01, CO2-VEH 0.5)는 적지 않아도 된다.
2. `ui/src/ui/Wargame.jsx` 의 `startFoothold(graph, payload)` 가 선언을 먼저 보고
   없을 때만 폴백한다. 시작 카드의 기본값이 그것이다.
3. `ui/tools/verify-scenarios.mjs` 의 `checkWargameFoothold` 가 **선언으로 실제 게임을
   시작해 합법 수를 센다.** 0 이면 게이트가 실패한다. 선언이 없는 시나리오에는 폴백
   값에 대해 같은 검사가 돈다. 검사가 공허하지 않다는 것도 같이 확인한다 - 같은 자산을
   0.01 로 두면 합법 수가 0 이어야 한다.
4. `wargame` 블록은 **엔진이 읽지 않는다.** 저하도·우선순위·색상 등급 어느 것도 이
   값을 보지 않는다. 교전을 열 때만 쓰인다.

## 근거

**출력을 고치려고 입력을 바꾸지 않는다.** 0.3 을 0.5 로 올리면 게임은 시작되지만
`states[0]` 은 더 이상 결정론 계층의 판정이 아니다. 리플레이 t=0 의 산출값이 따라
움직이고, 같은 값을 쓰는 `synthetic/states.jsonl` 과 어긋난다. 무엇보다 **0.3 이
임계값 아래인 것은 틀린 서술이 아니라 맞는 서술이다** - 스크립트가 돌았다는 관측
하나로는 아직 쓸 수 있는 거점이 아니다. 두 값이 다른 것이 의도이고, 그 의도를 데이터가
말하게 한다.

**`game.js` 를 고치는 선택지는 기각됐다.** `defaultFoothold()` 안에서
`Math.max(FOOTHOLD, level)` 로 바닥을 깔면 모든 시나리오가 조용히 playable 해진다.
그러면 "선언한 거점에서 교전이 열리는가" 라는 질문을 **다시 아무도 못 묻게 된다** -
0.3 이든 0.01 이든 같은 게임이 열리고, 시나리오가 무엇을 의도했는지는 코드가 삼킨다.
보정이 아니라 선언이 필요했다.

**검사기가 지킨다.** 이 결정은 필드 하나와 폴백 하나이고, 둘 다 조용히 틀릴 수 있는
모양이다. 그래서 게이트가 매 실행마다 실제 게임을 한 번 시작해 본다. 같은 파일의
`checkGraphMirror` 는 `mission.json` 과 리플레이에 박힌 `graph` 사본이 같은지 본다 -
UI 는 `mission.json` 을 열지 않으므로(ADR-0003) 재export 없이 고친 선언은 화면에
도달하지 않는다.

## 결과

- defnet-01 에서 교전이 자기 선언으로 열린다. 그 전에는 열리지 않았다.
- `verify-scenarios.mjs` 에서 `Math.max(0.5, ...)` 보정이 사라졌다. 게이트는 보정한
  값이 아니라 **선언한 값**을 연주한다.
- 시나리오 스키마에 루트 블록 하나(`wargame`)가 늘었다. 엔진은 읽지 않는다.
- 엔진 입력은 하나도 바뀌지 않았다. `parity.mjs` 는 전후 모두 1,622 값 / 불일치 0 이다.

## 대안

| 안 | 왜 아닌가 |
|---|---|
| `states[0]` 을 0.5 로 올린다 | 출력을 위해 입력을 바꾼다. 리플레이 t=0 산출값과 `synthetic/states.jsonl` 이 따라 움직이고, 초기 침해가 쓸 수 있는 거점이라는 **틀린 서술**이 데이터에 들어간다 |
| `game.js` `defaultFoothold()` 에 바닥을 깐다 | 모든 시나리오가 조용히 playable 해져 같은 질문을 다시 못 묻게 된다. 시나리오의 의도를 코드가 삼킨다 |
| `attack.js` 의 `FOOTHOLD` 를 0.3 으로 내린다 | 교전 규칙(ADR-0026)을 데이터 한 칸 때문에 바꾼다. 거점/측면이동/거부 임계값의 간격이 무너진다 |
| 아무것도 안 하고 주석만 고친다 | 이미 그 상태였다. 주석 두 줄이 있었고 아무것도 막지 못했다 |

## 재검토 조건

- 교전 거점이 여럿인 프리셋(`presets.js` 의 다중 거점)을 시나리오가 선언하고 싶어질 때.
  지금 `wargame.foothold` 는 하나이고, `startGame` 은 `footholds[]` 도 받는다.
- `defaultFoothold()` 폴백을 쓰는 시나리오가 셋 이상이 될 때. 폴백이 우연히 맞는 것에
  의존하는 시나리오가 늘면 선언을 필수로 돌리는 쪽이 낫다.
