# ADR-0010. 데이터셋 원본은 임시 자원, 파생 후 삭제

**상태**: 채택 (2026-09-05)

## 맥락

이 과제가 쓰는 공개 데이터셋은 합치면 테라바이트급이다. OpTC만 해도 호스트 이벤트 87억 건,
Zeek 플로우 5.3억 건 규모다. 로컬 디스크에 영구 보관하는 것은 불가능하고, 대부분은 재배포도
제한된다.

## 결정

**원본은 임시 자원으로 취급한다. 영구 자산은 원본에서 뽑아낸 파생물이다.**

수명주기: ACQUIRE → DISTILL → VERIFY → PURGE. 상세 절차는 `../05-data-lifecycle.md`.

핵심 규칙:

1. 파생물(OCSF 정규화 이벤트, 데모 슬라이스, 라벨, 엔티티 사전, 집계 통계, 학습된 모델,
   평가 산출물)이 영구 자산이며 백업 대상이다.
2. **VERIFY 게이트를 통과해야만 삭제한다.** 파생물만으로 데모가 돌고 평가가 재계산되며
   재취득 매니페스트가 완비된 상태여야 한다.
3. `data/processed/`, `models/`, `eval/results/`는 어떤 정리 스크립트도 건드리지 않는다.
4. 삭제는 사람이 확인 후 실행한다. 자동 정리 크론을 만들지 않는다.
5. 취득 즉시 `MANIFEST.json`(URL, 부분 지정자, 해시, 라이선스, 재배포 가능 여부)을 쓴다.
   이것은 원본 삭제 후에도 저장소에 남는 재취득 지시서이자 출처 증빙이다.
6. 작은 데이터셋부터 처리해 파이프라인을 검증하고, 대용량은 마지막에 받아 체류 시간을
   최소화한다. 권장 순서: AIT → LANL → DARPA TC → OpTC.

## 근거

- 용량 제약이 실재한다. 전량 보관은 선택지가 아니다.
- 대부분의 데이터셋이 재배포 제한이므로, 원본을 오래 들고 있을 이유가 라이선스 측면에서도
  약하다.
- 집계 통계를 반드시 뽑아두면 원본 없이도 **비슷한 성질의 합성 데이터를 재생성**할 수 있다.
  AIT의 테스트베드 재생성 경로와 직접 연결된다.
- 파생 스크립트를 단일 순회로 설계하고 뽑을 항목을 사전 확정하면, 삭제 후 재취득 필요성이
  크게 준다.

## 결과

- **파생 항목 목록을 파이프라인 작성 전에 확정해야 한다.** 이것이 이 결정의 실질적 비용이다.
  나중에 "그것도 뽑을걸" 하면 수백 GB를 다시 받아야 한다.
- 모든 파생물에 `_provenance.json`(입력 매니페스트 해시, 코드 커밋, 파라미터)이 필요하다.
- 새 실험 아이디어가 원본을 요구하면 재취득한다. 파생물을 원본처럼 재해석하지 않는다
  (파생 과정에 이미 필터·샘플링이 들어갔다).
- 논문 부록에 실을 수 있는 것은 대개 집계 통계와 평가 지표뿐이다.

## 대안

- **전량 보관**: 기각. 용량상 불가.
- **클라우드 오브젝트 스토리지에 원본 보관**: 보류. 비용과 반출 문제가 동시에 걸린다.
  필요해지면 재검토.

## 재검토 조건

대용량 스토리지가 확보되고 라이선스상 보관에 문제가 없음이 확인되는 경우.
