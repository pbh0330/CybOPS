# ADR-0018. 상황도 UI 스택 - Cytoscape.js + 정적 웹 번들

**상태**: 채택 (2026-09-06)

`99-open-questions.md` **Q5를 확정한다. 이로써 미결 사항이 모두 닫힌다.**

## 맥락

ADR-0014(데모 1순위)로 상황도 UI가 임계 경로가 됐고, ADR-0013(2525 준용)이 이미 선택지를
웹 쪽으로 좁혀놨다 - 2525/APP-6 심볼을 직접 그리는 것은 비현실적이고, 쓸 만한 오픈소스
렌더러(`milsymbol` 계열)가 JS다.

선정 기준은 세 가지였다: **심볼 렌더링을 포함한 성능**, **저대역폭 델타 동기화**,
**오프라인 동작**(ADR-0012 6항의 DIL 제약).

## 결정

### 1. 그래프 렌더링은 Cytoscape.js

- 임무 그래프의 실제 규모는 **수십~수백 노드**다. tacnet-01이 자산 13 + 서비스 5 + 작업 8,
  defnet-01이 16 + 5 + 4다. 실규모로 늘려도 수백 단위다. WebGL이 필요한 규모가 아니다.
- 심볼은 **milsymbol이 만든 SVG를 노드 배경 이미지로** 얹는다. 커스텀 셰이더나 텍스처
  아틀라스를 짜지 않는다. 이것이 Sigma.js 대비 결정적인 차이다.
- 복합 노드(compound node)로 **부대·임무 묶음**을 표현할 수 있다. 임무 좌표계(ADR-0001)를
  화면에 그대로 옮기는 데 필요한 기능이 기본 제공된다.
- 레이아웃(dagre/cose/preset)과 그래프 알고리즘이 내장이라 의존 경로 강조·기여도 표시를
  라이브러리 밖에서 다시 짜지 않아도 된다.

**시간축 스크럽은 재레이아웃 없이 스타일만 갱신한다.** 노드 위치가 시간에 따라 튀면
읽을 수 없다 - 위상은 고정하고 색·테두리·배지만 바꾼다.

### 2. 산출물은 브라우저 정적 번들 (Vite build)

`vite build` 결과 `dist/`를 브라우저로 열면 끝이다. 서버가 없다.

- **DIL 전제와 정합한다**(ADR-0012 6항). 시연 노트북에 폴더만 복사하면 동작하고,
  네트워크가 없어도 된다.
- 데이터는 JSON을 동봉한다. 지금 파이프라인의 산출(`mission.json`,
  `attack-timeline.json`, 엔진 `-Json` 출력)이 그대로 입력이 된다.
- CDN에 의존하지 않는다. 라이브러리는 번들에 포함한다.

> **나중에 서버에 올려 여러 사람이 접속하게 할 계획이 있다**(2026-09-06 책임자 확인).
> 이 결정은 그것과 충돌하지 않는다 - 정적 번들은 그대로 웹서버에 얹으면 되고, 오히려
> 서버 측 런타임 의존이 없어 배포가 단순하다. 다만 그 시점에 **두 가지가 새로 생긴다**:
> 접근 통제(누가 어느 시나리오를 보는가)와, 데이터가 동봉본이 아니라 서버에서 오게 되면서
> 필요해지는 델타 동기화(3항). 둘 다 별도 ADR 대상이며 지금 앞당겨 설계하지 않는다.

### 3. 델타 동기화는 렌더러가 아니라 데이터 계층의 문제다

저대역폭 델타 동기화는 Cytoscape든 Sigma든 라이브러리가 해주지 않는다. **그래프 전체가
아니라 변경분만 실어 나르는 것은 프로토콜 설계**이고, 정적 번들 단계에서는 필요하지
않다(데이터가 동봉돼 있다). 실시간 연동이 생기는 시점에 별도 ADR로 다룬다.

이번 결정에서 이 기준이 한 일은 **서버 상주를 전제한 스택을 배제한 것**까지다.

## 근거

- 성능 기준은 "얼마나 큰가"가 아니라 **"이 과제의 그래프가 얼마나 큰가"**로 판단해야 한다.
  수만 노드를 위한 WebGL 스택을 고르면 심볼 적용 공수를 그 대가로 낸다. 실제 규모에서는
  치를 이유가 없는 비용이다.
- 시연 환경이 항상 연결돼 있다고 가정할 수 없다. 서버 기동이 필요한 형태는 시연장에서
  실패할 여지를 하나 더 만든다.
- ADR-0001을 지키기 쉬운 쪽이다. 지리 레이어가 기본 스택에 들어오면(deck.gl) 지도가
  주화면으로 되돌아가는 압력이 생긴다.

## 결과

- **Node.js 설치가 선행 조건이다.** 현재 미설치이고, Python 3.12 / Git 2.55만 있다.
  `winget install OpenJS.NodeJS.LTS`로 설치한 뒤 PATH를 확인한다.
- UI 코드는 저장소 안 별도 디렉터리(`ui/`)에 둔다. 데이터 파이프라인(PowerShell/Python)과
  섞지 않는다.
- 엔진의 `-Json` 출력이 **UI의 계약**이 된다. 필드를 바꾸면 UI가 깨지므로 스키마를
  문서화한다.
- ADR-0013의 SIDC 매핑 테이블이 렌더링 직전 단계에서 필요해진다.
- E4(상황인지 비교)의 지리형 대조 화면을 나중에 만들 수 있도록, 레이아웃 계층을
  교체 가능하게 짠다(ADR-0014 3항).

## 대안

- **Sigma.js(WebGL)**: 기각. 수천~수만 노드에서 유리하지만 2525 심볼 적용 비용이 가장 크고,
  이 과제의 실규모가 그 이점을 쓰지 못한다.
- **deck.gl**: 기각. 지리 레이어 통합이 강점인데 이 과제는 지리가 기본 뷰가 아니다
  (ADR-0001). 그래프 인터랙션은 직접 구현해야 한다.
- **Electron 데스크톱 앱**: 기각. 시연 편의는 낫지만 빌드 체인이 무거워진다. 정적 번들로
  부족해지면 그때 감싼다(정적 번들은 Electron으로 감싸는 것이 쉽다. 역방향은 어렵다).
- **로컬 웹서버 + Python API**: 보류. 엔진 포팅 후 실시간 연동이 필요해지면 자연스러운
  다음 단계다. 데모 단계에서는 구동 절차만 늘린다.
- **먼저 벤치마크**: 기각. 노드 수백 규모에서는 세 후보 모두 통과할 것이 거의 확실해
  벤치마크가 결정을 바꾸지 못한다. 규모가 수천으로 커지면 그때 실측한다(재검토 조건).

## 재검토 조건

- 임무 그래프가 **수천 노드**를 넘는 경우 - 심볼 포함 렌더링을 실측하고 WebGL 계열을
  다시 본다.
- 실시간 서버 연동이 요구사항이 되는 경우 - 델타 동기화 프로토콜을 별도 ADR로 정한다.
- `milsymbol`이 2525D/E 요구 범위를 못 채우는 것으로 확인되는 경우(ADR-0013 2항의
  검증 항목) - 렌더러 선택이 다시 열린다.
