# ADR-0030. 모바일 컴팩트 모드 - 신호 하나, 하단 시트, 폰 기본 뷰는 지도

**상태**: 채택 (2026-09-26). **어떤 ADR 도 대체하지 않는다.** 결정 3 은 **ADR-0001 의 예외를
기록한다** - 모바일 한정이고, ADR-0001 자체는 그대로 유효하다.

## 맥락

390×844 에서 화면은 쓸 수 없었다. `.main` 이 `grid-template-columns: 1fr 380px` 이라 레일이
폭의 대부분을 가져가고, 그래프 캔버스에 남은 것은 **약 80px 짜리 조각**이었다. 상황도라고
부를 것이 화면에 없었다.

데모가 1순위이고(ADR-0014) 시연 사본은 링크 하나로 열린다(ADR-0029). 링크를 폰으로 받아
여는 사람이 처음 보는 것이 그 조각이다.

번들은 하나다(ADR-0018). 그러므로 모바일 전용 번들이나 라우트가 아니라 **같은 번들 안의
모드**로 풀어야 하고, 그 조건에서 가장 크게 걸리는 것은 데스크톱이 한 픽셀도 바뀌지 않는
것이다.

## 결정

1. **컴팩트 신호는 하나다.** `useCompact()` 가 `matchMedia('(max-width: 860px)')` 를
   구독해서 `.app` 에 `data-compact="1"` 을 달고, CSS 는 `[data-compact="1"]` 과
   `@media (max-width: 860px)` 로만 건다. 미디어 쿼리로 못 하는 것 - 어떤 뷰로 열지, 시트를
   만들지, 겹친 마커 목록을 띄울지 - 은 같은 훅의 불리언을 읽는다. **"컴팩트" 의 정의를 두
   군데 두지 않는다.** 하나면 둘이 어긋날 수 없다. 860px 은 폰 가로와 태블릿 세로를
   포함하고, 그 위는 지금 레이아웃 그대로다. 560px 아래의 추가 축소(타임라인 스파크라인
   숨김)는 순수 CSS 이고 별도 신호가 아니다.
2. **레일은 하단 시트가 든다. 인스턴스는 하나이고 부모만 둘이다.** App 이 레일 노드를 한 번
   만들고, 데스크톱에서는 `.main` 안에, 컴팩트에서는 `Sheet` 안에 넣는다. 시트의 단은
   엿보기 56px / 절반 50dvh / 전체 86dvh 세 개이고 손잡이를 끌면 가장 가까운 단으로 선다.
   **두 벌로 렌더하면 상태도 두 벌이 된다** - 열린 탭, 선택, 참모 질의 기록이 화면 폭에
   따라 갈라진다. 참모 드로어도 같은 규칙으로 폰에서는 레일의 탭이 된다(ADR-0028,
   `docs/25-staff.md` 5절).
3. **폰의 기본 뷰는 지도다. 이것은 ADR-0001 의 모바일 한정 예외다.** ADR-0001 은 좌표계가
   임무-자산 의존성 그래프이고 지리는 기본 뷰가 아니라고 못 박았다. 390px 폭에서 dagre
   그래프는 노드 라벨이 서로 겹쳐 읽히지 않고, **읽히지 않는 좌표계는 좌표계로 기능하지
   않는다.** 지도는 같은 폭에서도 방향 감각을 준다. 뷰 전환은 무대 위에 늘 떠 있으므로
   그래프는 **한 번의 탭 거리**에 있다. 범위는 좁다.
   - **데스크톱 기본 뷰는 그대로 그래프다.** 이 예외는 `data-compact="1"` 안에서만 산다.
   - **georef 가 없는 시나리오는 컴팩트에서도 그래프로 연다.** `defnet-01` 이 그렇다 -
     없는 뷰를 기본으로 둘 수 없다.
   - **기본값이지 교정이 아니다.** 사람이 뷰 컨트롤을 한 번 건드렸거나 `?view=` 링크로
     들어왔으면 그 뒤로 다시 끼어들지 않는다.
   - ADR-0001 은 폐기되지도 대체되지도 않는다. 바뀐 것은 **무엇을 먼저 보여 주는가** 하나
     이고, 엔진은 여전히 geo 를 읽지 않는다(ADR-0002, `Test-GeoInvariance`).
4. **컴팩트에서 손가락이 누르는 것은 최소 44px 로 한다. 이벤트 스트림의 로그 행은
   예외이고 34px 이다.** 규칙은 레일·시트·인스펙터 표면에 한 줄로 걸고 항목마다 재지 않는다.
   예외를 둔 이유는 로그가 **읽는 것**이지 항목마다 누르는 것이 아니기 때문이다 - 일괄
   규칙이 48행 목록의 스크롤 길이를 2,119px 로 늘렸고, 34px 로 되돌리면 1,650px 이다.
   34px 도 의도한 타깃이다(행은 전폭 띠이고, 탭 한 번이 하는 일은 replay 이동뿐이다).
5. **데스크톱은 바이트 단위로 같아야 한다.** 그래서 이 ADR 의 모든 규칙은 예외 없이
   컴팩트 게이트 뒤에 있다 - `[data-compact="1"]`, `@media (max-width: 860px)`, 또는
   `compact` 불리언. 새 규칙을 공통 블록에 쓰지 않는다. 확인 방법은 주장이 아니라 측정이다:
   1600×900 에서 개편 전후의 요소 사각형과 `outerHTML` 길이를 비교해 같음을 확인했다.

## 하지 않는 것

모바일 전용 번들·라우트, 새 UI 라이브러리와 제스처 라이브러리, 데스크톱 레이아웃 변경,
그래프 레이아웃 알고리즘 교체, PWA·오프라인, 가로 모드 전용 레이아웃(가로로 돌려 860px 을
넘으면 데스크톱 레이아웃으로 자연히 돌아간다), **겹친 마커를 지도 위에서 흩뿌리는 것**
(심볼을 실제 자리에서 옮기는 것은 위치에 대한 거짓말이다 - 대신 탭이 그 자리에 있는 것을
전부 목록으로 보고한다).
