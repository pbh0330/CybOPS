# ADR-0003. 상태 산출은 결정론 계층 전담, LLM은 설명 전담

**상태**: 채택 (2026-09-05)

## 맥락

"LLM 기반 상황도"라는 이름 때문에 LLM이 판단의 중심에 오는 설계로 흐르기 쉽다. 그러나 실측
근거는 반대 방향을 가리킨다.

## 결정

**상태값의 유일한 출처는 결정론 계층(규칙 + 그래프 알고리즘 + 경량 ML)이다.**

- 결정론 계층 담당: 자산 상태, 임무 저하도, 우선순위 스코어, UI 색상 등급
- LLM 계층 담당: 상황 요약, 브리핑 초안, 상관 가설 생성, 자연어 질의 변환, ATT&CK 매핑 서술
- **LLM 출력이 상태값을 직접 결정하는 코드 경로를 만들지 않는다.** 데이터 흐름은
  결정론 계층 → LLM 계층 단방향이다.
- 결정론 계층의 모든 산출물은 `(입력 이벤트 ID 집합, 적용 규칙 ID, 중간값, 출력)`을 감사
  로그에 남긴다. 상황도의 모든 색깔은 이 경로로 역추적 가능해야 한다.

## 근거

- SOC 경보 분류 실측: 대부분의 모델이 recall 90% 이상이었으나 **우선순위 결정은 precision이
  일관되게 낮아** 상당한 노이즈와 높은 오탐률을 유발했다. 경량 ML이 경쟁력 있는 성능을 냈고
  **Linear SVM 베이스라인이 전체 F1 최고**를 기록했다.
- 지연: 기존 LLM 접근은 경보당 3~5초 지연이 발생해 실시간 트리아지에 비용 과다.
  상황도의 목표 응답은 단순 조회 0.11초, 복합 조회 1.07초 수준이다. 자릿수가 다르다.
- 감사 추적성: NIST SP 800-61r3 기준의 추적성을 유지하려면 판단 근거가 결정론적이어야 한다.
- 증강에서 자율로 넘어가는 순간 고전 ML에는 없던 환각과 프롬프트 인젝션 위험이 생긴다.

## 결과

- 상황도의 상태 갱신이 LLM 응답을 기다리지 않는다. LLM 응답은 별도 패널에서 스트리밍된다.
- 경량 ML 베이스라인이 필수 구성요소가 된다(장식이 아니라 주력).
- **프롬프트 인젝션 전제**: 텔레메트리의 파일명·커맨드라인·HTTP 헤더·UA는 공격자가 쓰는
  필드다. LLM 컨텍스트에 들어가는 모든 텔레메트리 문자열은 신뢰 불가 데이터로 표시해 감싼다.
- LLM이 틀려도 상황도의 상태는 오염되지 않는다. 이것이 이 결정의 핵심 이득이다.

## 대안

- **LLM이 우선순위를 매기고 사람이 검토**: 기각. precision이 낮으면 검토 부담이 오히려 는다.
- **LLM과 ML의 앙상블로 상태 산출**: 보류. 앙상블 자체는 가능하나 감사 추적성이 훼손되고,
  평가에서 경량 ML 단독을 이긴다는 증거가 먼저 필요하다.

## 재검토 조건

트랙 C 평가에서 특정 모델이 상태 산출 과제에 대해 캘리브레이션과 precision 모두 경량 ML
베이스라인을 유의하게 상회하고, 지연 예산 안에 들어오는 것이 실측되는 경우.
