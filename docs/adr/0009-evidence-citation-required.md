# ADR-0009. LLM 응답의 근거 스팬 인용 강제

**상태**: 채택 (2026-09-05)

## 맥락

LLM이 생성한 상황 요약은 그럴듯하게 읽힌다. 지휘관이 그 서술을 근거로 판단하는데 그것이
환각이면 최악이다. 상용 도구에서도 "그럴듯하지만 때때로 부정확한 권고"가 보고되고 있다.

## 결정

**LLM이 내는 모든 사실 주장은 근거를 인용한다.**

- 인용 단위: 이벤트 ID, 지식 문서 ID + 스팬. 자유 서술만 있는 응답은 허용하지 않는다.
- 근거를 붙이지 못한 문장은 UI에서 **"미검증"으로 시각적으로 구분**한다. 숨기지 않되
  같은 무게로 보이게 하지 않는다.
- 인용을 클릭하면 원본 이벤트/문서로 이동한다.
- **근거 인용률과 인용 정합성을 평가 지표로 삼는다**(`../04-evaluation.md`). 인용률만 높고
  정합성이 낮은 실패 모드를 잡기 위해 두 지표를 함께 본다.
- 근거가 부족하면 "모름"이라고 답하는 것을 허용하고, 거부율(abstention)도 측정한다.

## 근거

- 감사 추적성 요구(NIST SP 800-61r3 맥락)를 LLM 계층에서도 유지해야 한다. 결정론 계층만
  감사 가능하고 설명 계층은 불투명하면 반쪽이다.
- 환각은 근거 강제만으로 사라지지 않지만, **검증 가능해진다.** 사용자가 30초 안에 확인할 수
  있는 형태로 만드는 것이 목표다.
- RAG 구조(ADR-0006)와 자연스럽게 맞물린다. 검색된 문서가 곧 인용 후보다.

## 결과

- 프롬프트 템플릿이 인용 형식을 강제해야 하고, 출력 파서가 인용을 구조적으로 추출해야 한다.
- 인용 ID의 유효성을 코드에서 검증한다(존재하지 않는 ID를 지어내는 경우 차단).
- UI에 인용 표시·이동 기능이 필수 구성요소가 된다.
- 응답이 길어지고 지연이 늘어난다. 상태 갱신 경로와 분리되어 있으므로 감수 가능하다(ADR-0003).

## 대안

- **사후 검증만**: 기각. 생성 시점에 강제하지 않으면 사후 매칭 정확도가 떨어진다.
- **신뢰도 점수만 표시**: 기각. 캘리브레이션이 검증되지 않은 상태에서 숫자만 보여주면
  근거 없는 안심을 준다.

## 재검토 조건

없음. 이 과제의 성격상 상시 유효하다.
