# ADR-0021. 호스팅 배치와 모델 엔드포인트

- 상태: 채택
- 날짜: 2026-09-07
- 관련: ADR-0018(정적 번들), ADR-0007(온프렘·교체 가능 모델), ADR-0003(LLM은 상태를 정하지 않는다)

## 맥락

번들을 서버에 올려 다른 사람이 접속할 수 있게 하기로 했다. 그런데 UI 안에서 모델을
호출하는 곳이 하나 있다 - 교전 모드의 LLM 공격자다. 이것이 **브라우저에서** Ollama 호환
엔드포인트를 부른다.

노트북에서 `http://127.0.0.1:11434` 는 "내 모델"이다. 같은 번들을 공개 호스트에서 서비스하면
그 주소는 여전히 "**접속한 사람의 PC**"를 뜻한다. 결과는 둘 중 하나다.

- 접속자에게 Ollama 가 없다 → 클릭하면 연결 타임아웃만큼 멈췄다가 실패한다.
- 접속자에게 Ollama 가 있다 → 남의 서버에서 보고 있는 시나리오를 자기 GPU 가 돌린다.

**둘 다 아무도 의도하지 않은 동작이다.** 그리고 이 문제는 코드가 아니라 배치의 문제다.
같은 파일이 세 곳(개발기, 네트워크 없는 데모 노트북, 웹 서버)에서 돌아야 하고, 세 곳이
같은 질문에 다른 답을 원한다.

## 결정

**빌드 시점 상수가 아니라 런타임 설정 파일로 둔다.** `ui/public/config.json` 을 시작 시
읽고, 없으면 기본값을 쓴다. 편집은 배포 단계이지 재빌드가 아니다.

빌드 플래그로 했다면 같은 산출물의 빌드가 세 벌이 되고, **데모 당일에 안 쓴 빌드가 그
세 벌 중 하나일 확률**이 생긴다. 그것이 이 결정의 실질적인 이유다.

세 가지 배치 형태를 지원한다.

| 형태 | 설정 | 쓰는 곳 |
|---|---|---|
| `local` | `endpoint: http://127.0.0.1:11434` | 개발기, 데모 노트북 (기본값) |
| `proxied` | `endpoint: /api/llm` | 서버가 모델을 소유. 리버스 프록시가 Ollama 로 넘긴다 |
| `off` | `enabled: false` | 모델 없이 공개 배포 |

`proxied` 는 CORS 문제도 같이 없앤다. 같은 오리진이기 때문이다.

**시작 시 한 번 프로브한다.** `/api/tags` 를 2.5초 타임아웃으로 부르고, 실패하면 교전
패널에서 LLM 선택지를 **사유와 함께** 비활성화한다. 클릭한 뒤에 알게 되면 사용자가
할 수 있는 일이 없다.

## 결과

**모델이 없어도 화면의 대부분이 그대로다.** 이것은 우연이 아니라 ADR-0003 의 결과다.

- 임무 저하도, 원인 분해, 단절, 봉쇄 비용, 지형, 교전의 greedy·random: 전부 결정론 계층이고
  모델과 무관하다.
- 브리핑: `scripts/New-BriefingPack.ps1` 이 미리 생성한 JSON 이 번들에 들어간다. 근거 인용도
  함께 들어간다. **호스팅본에서도 브리핑은 그대로 보인다.**
- 사라지는 것은 **실시간 LLM 공격자 하나**다.

LLM 출력이 상태값을 정하는 경로가 있었다면 모델이 없는 배포본은 숫자가 다르거나 아예
비었을 것이다. 그 경로를 만들지 않았기 때문에 배치 선택지가 생겼다.

## 대안과 기각 사유

- **모델 호출을 서버로 옮긴다(항상 프록시).** 데모 노트북이 네트워크 없이 돌아야 한다는
  ADR-0012 의 DIL 전제를 깬다. 기각.
- **빌드 시 `import.meta.env` 로 분기한다.** 위에 적은 "세 벌 중 하나" 문제. 기각.
- **호스팅본에서 교전 모드를 통째로 숨긴다.** greedy 대조군은 이 과제의 핵심 결과
  (docs/13)이고 모델 없이 돈다. 그것까지 숨길 이유가 없다. 기각.

## 남는 문제

- **프록시 경로의 인증·유량 제한을 정하지 않았다.** 공개 호스트에서 `/api/llm` 을 그대로
  열면 남의 GPU 를 무료 추론 API 로 내주는 것이다. 실제로 올릴 때 정해야 한다.
- 기본값이 `local` 이므로 **호스팅하면서 config.json 을 안 고치면 위에 적은 두 가지 나쁜
  동작이 그대로 난다.** `ui/public/config.hosted.example.json` 을 옆에 두는 것으로는
  부족하고, 배포 절차서에 넣어야 한다.
