# ADR-0002. IP 지오로케이션을 판단 로직에서 배제

**상태**: 채택 (2026-09-05)

## 맥락

공격 출발지를 지도에 표시하려면 IP 지오로케이션이 필요하다. 그러나 그 정확도가 상황도의
신뢰도를 그대로 깎아먹는다.

## 결정

외부 IP 지오로케이션 결과는 **어떤 판단 로직에도 입력되지 않는다.**

- 정규화 단계에서 `enrichment.geo.country`(국가 코드)만 보관한다.
- 스코어링, 우선순위, 임무 저하도, 자동 대응 어느 것도 이 필드를 읽지 않는다.
- UI에 표시할 때는 참고값임을 명시한다. 도시 수준 표시는 하지 않는다.
- 자산의 물리적 위치(`Asset.geo`)는 별개다. 그것은 자산 대장에서 오는 신뢰 가능한 정보다.

## 근거

- ARIN이 인용한 연구에 따르면 도시 수준 정확도 상한이 약 75%다. 최소 4개 중 1개가 틀리며,
  해당 연구는 **DB 종류와 무관하게** 도시 수준 정확도를 신뢰하지 말 것을 권고한다.
- MaxMind 기준 국가 수준은 99.8%지만, 미국 IP의 도시 수준은 50km 반경 내 약 66%다.
- 결정적 사례: 공격자가 지역 차단을 우회하려 `us-east-1`에 VM을 띄우면 IP는 정상적으로
  북버지니아로 지오로케이션되어 필터를 통과한다.
- 즉 세계지도 위 화살표는 "어디서 왔는가"가 아니라 "어느 클라우드 리전에서 나갔는가"를
  보여준다. 이를 판단에 쓰면 상황도가 체계적으로 오도한다.

(수치 검증 상태는 `../02-research-plan.md`의 출처 검증 체크리스트 참조)

## 결과

- "공격 출발지 지도"라는 익숙한 화면을 포기한다. 시연 시 이 부재를 **설계 결정으로 설명**해야
  하며, 그 설명 자체가 기여(C1)의 일부다.
- 국가 단위 통계는 사후 분석·보고서용으로 남는다.

## 대안

- **가중치를 낮춰 판단에 포함**: 기각. 오류가 체계적(클라우드 리전 편향)이라 가중치를 낮춰도
  편향은 그대로 남는다.
- **상용 고정밀 DB 구매**: 기각. 인용된 연구가 DB 종류와 무관하다고 명시했다.

## 재검토 조건

지오로케이션 정확도에 대한 새로운 1차 근거가 나오고, 그것이 판단 경로에 넣을 만한 수준을
입증하는 경우.
