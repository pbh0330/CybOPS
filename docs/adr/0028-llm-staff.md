# ADR-0028. LLM 의 역할은 참모다 - 닫힌 질의 카탈로그, 검증된 인자, 모델 없이도 답

**상태**: 채택 (2026-09-23). ADR-0019(적대 행위자 시뮬레이션)를 **폐기하지 않는다** -
공격자 엔진과 그 프롬프트는 코드에 그대로 남고 기본 UI 에서만 빠진다. ADR-0003(상태는
결정론 엔진이 정한다)·ADR-0004(실행은 사람이 승인한다)·ADR-0009(모든 응답은 근거를
인용한다)의 적용이지 예외가 아니다.

**이 ADR 이 정하는 것은 설계 전체이고, 지금 코드에 있는 것은 S1(결정론 절반)과
S2(라우팅·서술·기권·평가셋)다. 남은 것은 S3 의 교전 흡수다.** 무엇이 구현됐고 무엇이
아직 아닌지는 "실제로 구현한 범위" 표에 적는다. 아직 없는 것을 있는 것처럼 쓰지 않고,
**측정하지 않은 것을 측정한 것처럼 쓰지도 않는다.**

## 맥락

지금까지 모델이 이 시스템에서 한 일은 둘이었다.

- **공격자**(`attack-llm.mjs`, ADR-0019). 엔진이 열거한 합법수 중 하나를 고른다. 판정은
  시드 난수이고 모델은 수를 발명하지 못한다. 설계로서는 건전하지만, **심사·시연에서
  사람이 보고 싶어 하는 것은 공격자가 아니라 참모다.** 그리고 2026-09-23 의 greedy 동률
  수정(ADR-0019 개정) 뒤로는 대조군인 greedy 가 강해져서 LLM 공격자의 옛 우위 수치도
  그대로 쓸 수 없게 됐다.
- **참모**(`staff-llm.mjs`, ADR-0026 §4). 교전의 방어 페이즈에서 격리 순위표 상위 5줄을
  2~3문장으로 읽어 준다. 그게 전부다. 교전 밖에서는 존재하지 않는다.

그리고 브리핑은 **사전 생성**이다. `tacnet-01-t{120,300,390}.{pack,brief}.json` 세 시각뿐
이고, 그래프를 한 번이라도 편집하면 "해당 브리핑이 없다" 가 뜬다(`Rail.jsx`). 교전장
`sandbox-01` 은 정의상 항상 편집된 그래프라 **모델이 닿는 경로가 하나도 없다.**

사실 생성이 이미 결정론적이라는 구조는 옳다(ADR-0003). 바꿀 것은 **사실을 어디서
뽑느냐**다 - 오프라인 팩 세 개가 아니라, 화면에 떠 있는 그래프에서 지금.

## 결정

### 1. 역할을 공격자에서 참모로 옮긴다. 공격자는 지우지 않고 감춘다

LLM 의 기본 역할은 상주 참모다. 공격자 LLM 은 코드에 남기되 `config.json` 의
`llm.attacker_enabled`(기본 `false`) 뒤로 숨기고, 그 값이 참일 때만 시작 카드에 LLM
공격자 선택지를 그린다. ADR-0019 는 유효하다 - **결정을 뒤집는 것이 아니라 기본값을
옮기는 것이다.** (S2 에서 넣었다. `DEFAULTS.llm.attacker_enabled`, 기본 `false`.)

### 2. 질의는 닫힌 카탈로그다. 모델은 그 안에서 id 를 고를 뿐이다

`staff.js` 의 `QUERIES` 는 유한 집합이고, `catalog(ctx)` 가 지금 상황에서 말이 되는 것만
돌려준다(`needs`: `'graph'` 항상, `'game'` 교전 중에만, `'sandbox'` 교전장에서만). 교전이
없으면 교전 질의는 목록에 아예 없고, **따라서 모델이 고를 수도 없다.** 카탈로그가
곧 게이트다.

`run` 은 카탈로그가 내보내는 명세에 들어 있지 않다. 질의를 실행하는 경로는 `ask` 하나뿐
이고, `ask` 는 반드시 `validate` 를 먼저 통과한다.

### 3. 인자는 그래프 id 로 검증한다. 거부하지, 고쳐 주지 않는다

`validate` 는 없는 질의, 지금 쓸 수 없는 질의, 그래프에 없는 자산·임무 id, 정수가 아닌
`k`, 서로 같아야 할 리 없는 비교 쌍을 **사유 문장과 함께 거부**한다.

**틀린 인자를 조용히 기본값으로 바꾸지 않는다.** 없는 인자만 기본값을 받고, 명시된
`null` 이나 `'5'` 는 값이며 틀린 값이다. 이유는 둘이다 - 사람에게는 컨트롤이 애초에
나쁜 값을 못 만들므로 이 메시지를 볼 일이 없고, 모델에게는 **읽을 수 있는 거부가 교정
이지 조용한 강제 변환은 "틀린 인자가 맞았다" 는 학습**이기 때문이다.

### 4. 모델이 없으면 빠지는 것은 기능이 아니라 서술이다

이것이 이 ADR 의 핵심 주장이고, S1 이 그것을 **주장이 아니라 실증으로** 남겼다.

- 질의 버튼은 `ask` 를 직접 부른다. 사실·표·인용 참조가 전부 나온다.
- 모델이 있으면 그 위에 문장이 얹힌다. 없으면 문장만 없다.
- 그래서 GPU 없는 정적 배포본(ADR-0029, 자세 `off`)에서도 참모는 온전히 동작한다.
  **꺼진 상태는 고장이 아니다.**

S1 의 브라우저 확인은 **전부 모델 서버 없이** 돌렸다. 드로어의 어떤 경로도 모델을
호출하지 않았고, 호출하지 않아도 답이 나왔다.

### 5. 모든 문장은 `[F#]` 을 인용한다. 사실은 번호가 붙은 엔진 산출이다

`facts.js` 는 엔진 산출 한 조각을 짧은 한국어 문장으로 바꾸고 `numbered()` 가 `F1..Fn` 을
붙인다. 각 사실은 원값(`value`)·단위(`unit`)와, 그 사실이 가리키는 노드(`ref: {kind, id}`)를
들고 다닌다. **근거 체인은 별도 기능이 아니라 인용 그 자체다** - `ref` 가 있는 사실은
UI 에서 누를 수 있는 버튼이고, 누르면 그래프·지도에서 그 노드가 잡힌다.

표시 형식은 화면이 쓰는 `derive.js` 의 `pct` 를 그대로 쓴다. 사실이 같은 숫자를 옆의
패널과 다르게 반올림하는 일이 없게 하려는 것이다.

인용 없는 문장의 `미검증` 배지와 인용률 지표는 ADR-0009 그대로이고, 문장이 생긴
S2 에서 붙었다 - 브리핑·교전·참모가 `ui/src/ui/cite.jsx` 한 벌을 같이 쓴다.

### 6. 기권은 실패가 아니라 정답의 일부다

카탈로그 밖의 질문("이 장비 가격이 얼마냐")에는 답하지 않고 이유를 말한다. 라우팅이
실패하면 `state_summary` 로 떨어뜨리고 `note` 에 "질의를 고르지 못해 요약으로
답했다" 를 적는다 - 조용히 넘어가지 않는다. 떨어뜨리는 계기는 **둘**이다.

1. **응답을 읽지 못한 경우.** `routeQuestion` 이 한 번 재시도하고도 JSON 이 아니거나
   형식이 틀리거나 카탈로그에 없는 id 를 골랐을 때 (`unparsable` / `bad_shape` /
   `bad_args` / `unknown_query` / `empty`).
2. **`staff.validate` 가 인자를 거부한 경우 - 한 번이면 곧바로 떨어진다.** 재시도하지
   않는다: 이 그래프에 없는 자산 id 는 다시 물어도 없다. 카드에는 어느 질의의 인자가
   거부됐는지까지 적는다(`fallbackNote`, `StaffDock.jsx`).

전송 실패와 시간 초과는 예외로, 요약을 대신 보여 주지 않고 오류로 남긴다. 닫힌 포트에
두 번 거는 것은 같은 답을 두 번 기다리는 일이고, 묻지 않은 요약을 화면에 올리는 것보다
"모델에 닿지 못했다"가 정직하다.

기권율과 기권 정확도를 지표로 재고,
accuracy 는 쓰지 않는다(ADR-0008). **S2 에서 구현했다. 지표는 골든셋에 들어 있고,
측정은 모델이 있는 기계에서 해야 한다 - 아직 돌리지 못했다.**

### 7. 실행 경로는 없다

`Answer.actions` 는 S1 에서 항상 `[]` 이고, 드로어에는 그것을 누를 코드 경로 자체가
없다. 격리는 교전 패널에서 사람이 누르는 버튼이다(ADR-0004). S3 에서 교전을 흡수할 때
`actions` 가 채워져도 누르는 것은 사람이고, 모델은 채우지도 누르지도 않는다.

### 8. 그래프 문자열은 데이터이지 지시가 아니다

자산 이름·부대·site 는 사용자가 편집 모드에서 아무 값이나 넣을 수 있다(ADR-0019 8절과
같은 위협 모델). 출력 채널이 **닫힌 질의 id + 검증된 인자**이므로 자유 문장 안에 행동
경로가 없다. S2 의 프롬프트는 `<facts>`/`<catalog>` 안의 문자열이 데이터임을 명시한다.

**S2 로 참모는 모델을 쓸 수 있게 됐지만, 그 품질은 아직 수치가 없다.** 골든셋 38문항과
러너는 돌아가고 카탈로그 회귀(30건)는 통과하지만, **이 기계에는 Ollama 가 없어
라우팅 precision@1·인용률·기권 정확도가 한 번도 측정되지 않았다.**
`eval/results/staff-nomodel-2026-09-26.json` 은 그 자리에 **0 이 아니라 `null`** 을 적는다.
모델을 붙인 기계에서 실측하기 전까지 이 문서는 라우팅 정확도에 대해 여전히 아무것도
주장하지 않는다. 명령 한 줄은 `docs/25-staff.md` 8절에 있다.

## 하지 않는 것

- 파인튜닝(ADR-0006). 문서 RAG. 질문 하나에 질의 여럿을 엮는 다단계 도구 연쇄.
- LLM 이 상태값을 정하거나 순위를 다시 매기는 경로(ADR-0003). 참모는 `staffTable` 의
  순서를 **읽을 뿐 바꾸지 않는다.**
- LLM 이 행동을 고르거나 실행하는 경로(ADR-0004).
- 서버측 상태(ADR-0029). 질의 기록은 브라우저 `localStorage` 에만 남고 교전 `history` 에는
  들어가지 않는다 - **물어본 질문은 판이 처한 상태가 아니다.**
- 공격자 프롬프트 변경. ADR-0019 의 공격자는 그대로다.

(facts 20, staff 28, staffdock 12 = 신규 60).

**S2**: `ui/src/staff-llm.mjs` 확장(라우팅·서술·주입 가능한 전송), `ui/src/ui/cite.jsx`
신설(인용 렌더 한 벌), 질문 상자와 기권·실패·폴백 표시, `eval/golden/staff/tacnet-01.jsonl`
(38문항)과 `ui/tools/staff-eval.mjs`, `llm.attacker_enabled` 플래그. vitest 261개.

두 단계 모두 `parity.mjs` 불일치 0(1,622값), `Invoke-Gates.ps1` 9/9. **엔진·게임·교전
코드는 한 줄도 바뀌지 않았다** - 참모는 그 위에 얹힌 읽기 전용 계층이다.

화면·질의표·한계·평가 상태는 `docs/25-staff.md`, 설계 전문은

`docs/design/decisions.md` "2026-09-23 - 참모 S1"·"2026-09-26 - 참모 S2" 절.

## 재검토 조건

- **카탈로그가 열 종을 넘어가면** 라우팅 난이도가 달라진다. 지금 설계는 모델이 유한한
  목록에서 하나를 고르는 분류 문제를 전제한다 - 목록이 길어지면 그 전제가 흔들린다.
- **S2 의 골든셋에서 라우팅 precision@1 이 낮게 나오면** 원인을 먼저 가린다. 질의 라벨이
  모호한 것인지 모델이 약한 것인지. 파인튜닝은 ADR-0006 에 따라 RAG·프롬프트의 한계가
  실측된 뒤에만 검토한다.
- **공격자 LLM 을 다시 기본으로 올리자는 요구**가 나오면 ADR-0019 와 이 문서를 같이 본다.
  코드는 남아 있으므로 되돌리는 비용은 플래그 하나다.
