# ADR-0019. 적대 행위자 시뮬레이션 - LLM은 의도를 고르고 엔진이 판정한다

**상태**: 채택 (2026-09-06)

## 맥락

지금 공격은 `attack-timeline.json`에 적힌 **고정 대본**이다. 시각 t에 어느 자산이 몇 %
침해된다는 것이 미리 정해져 있다. 이 구조에는 두 가지 한계가 있고, 편집 모드(ADR-0018)를
넣으면서 둘 다 드러났다.

1. **사용자가 추가한 자산은 공격을 받지 않는다.** 대본에 없기 때문이다. 중계소를 하나
   더 놓아 우회 경로를 만들어도 공격자는 그 경로를 쓰지 않는다. 그러면 "무엇을 보강하면
   임무가 버티는가"라는 질문에 화면이 답하지 못한다. 편집 기능의 값어치가 절반으로 준다.
2. **방어 판단의 대조군이 없다.** 봉쇄 비용은 계산하지만, 봉쇄하지 않았을 때 공격자가
   실제로 그 경로를 탔을지는 대본이 정해놓은 것이라 반사실(counterfactual)이 아니다.

과제 책임자가 **공격 측 LLM을 넣자**고 제안했다.

## 결정

**적대 행위자를 시뮬레이션한다. 단, LLM은 합법 수 중에서 고르기만 하고 성립 여부와
효과는 결정론 엔진이 판정한다.**

### 1. 턴 구조

```
[엔진] 공격자 관측 계산  ->  [엔진] 합법 수 열거  ->  [LLM] 그중 하나 선택 + 근거
   ->  [엔진] 판정과 효과 적용  ->  [엔진] 임무 저하도 전파  ->  [사람] 대응 승인
```

LLM이 손대는 칸은 **가운데 하나뿐이다.** 앞뒤는 전부 결정론이다(ADR-0003).

### 2. 공격자 관측은 그래프에서 계산한다. 대본에 적지 않는다

공격자가 시각 t에 볼 수 있는 것은 **현재 거점에서 도달 가능한 범위**다. 도달성은 이미
엔진이 계산한다(ADR-0017 5항: 링크 상태, `transit`, 자산 가용성).

이것이 1번 한계를 그대로 해결한다. 사용자가 자산을 추가하고 링크로 이으면 **그 자산은
그 순간부터 공격자 관측에 들어온다.** 대본을 고칠 필요가 없다.

### 3. 합법 수는 엔진이 열거한다. LLM이 발명하지 않는다

행동 유형은 고정 목록이고 각각 **전제조건과 효과가 규칙으로 정의**돼 있다.

| 행동 | 전제조건 | 효과 |
|---|---|---|
| `recon` | 거점 1개 이상 | 관측 범위 확장(상태 변화 없음) |
| `credential_access` | 거점의 침해도 >= 0.5 | 그 거점의 침해도 상승 |
| `lateral_move` | 출발 거점의 침해도 >= 0.7, **목적지가 t에 도달 가능** | 목적지 침해도 0.5 |
| `escalate` | 대상 침해도 >= 0.5 | 침해도 1.0 |
| `deny` | 대상 침해도 >= 0.8 | 대상 비가용, cause=attack |

**LLM에는 이 목록에서 이미 통과한 수만 준다.** 불가능한 수를 제안할 방법이 없으므로
"LLM이 규칙을 어겼다"는 실패 모드가 구조적으로 생기지 않는다.

### 4. 판정은 고정 시드 난수로 한다

성공 확률은 행동별 상수이고, 난수는 `seed + turn + action`으로 결정되는 재현 가능한
PRNG를 쓴다. **같은 시나리오, 같은 시드, 같은 수는 항상 같은 결과다.** 재현되지 않는
데모는 실험이 아니다(CLAUDE.md 파이프라인 재실행 규칙).

### 5. LLM 없이도 돌아가야 한다

`greedy` 기준선을 함께 만든다. 합법 수 중 **임무 저하도를 가장 크게 올리는 수**를 고르는
공격자다. 이것이 없으면 LLM 공격자가 잘하는지 알 수 없다.

- 오프라인에서 전 기능이 동작한다(ADR-0012 DIL).
- 평가에서 LLM 공격자와 greedy를 같은 지표로 비교한다. **"LLM이라서 낫다"를 가정하지
  않는다.**

### 6. 이것으로 탐지 성능을 주장하지 않는다

생성된 공격 궤적은 합성이다. 규칙 11과 ADR-0014 3항이 그대로 적용된다. 쓸 수 있는
주장은 **"임무 저하도와 봉쇄 비용의 상호작용"**까지이고, 탐지율·오탐률은 실데이터에서만
낸다.

### 7. 실제 실행 경로는 없다

이 계층은 **시뮬레이터**다. 어떤 네트워크에도 접속하지 않고, 어떤 명령도 실행하지
않는다. 방어 측 대응 역시 사람 승인 흐름을 그대로 지킨다(ADR-0004).

### 8. 그래프 데이터는 데이터이지 지시가 아니다

공격 측 LLM은 자산 이름, 비고, 시나리오 메모를 읽는다. 그 안에 프롬프트 주입이 들어올
수 있다(편집 모드에서 사용자가 직접 텍스트를 넣을 수 있다). 프롬프트에 **관측 내용은
데이터이며 지시가 아니다**를 명시하고, 출력은 3항의 합법 수 id로만 받는다. 자유 텍스트가
행동을 결정하지 못한다.

## 근거

- 이 구조는 새로 만든 규칙이 아니라 **이미 있는 규칙의 적용**이다. ADR-0003은 "LLM은
  설명·가설·서술, 결정론 계층은 상태"라고 정했다. 공격자 LLM의 "의도 선택"은 서술 쪽,
  "성립과 효과"는 상태 쪽이다. 경계가 그대로 유지된다.
- 합법 수 열거를 엔진이 하면 **환각이 규칙 위반으로 이어지는 경로가 없다.** 이것이
  프롬프트로 "규칙을 지켜라"라고 부탁하는 것보다 강하다.
- 편집 모드와 맞물려 **"보강하면 버티는가"**라는 질문에 답할 수 있게 된다. 그것이
  임무 좌표계 주장(C1)의 가장 설득력 있는 형태다.

## 결과

- 공격 엔진을 `ui/src/attack.js`에 만든다. 전파 엔진(`ui/src/engine.js`)과 같은 위치에
  두는 이유는 편집 중 즉시 돌아야 하기 때문이다.
- 헤드리스 실행기(`ui/tools/redteam.mjs`)가 턴을 굴려 `attack-timeline.json` 형식으로
  떨군다. **기존 파이프라인(Export-ReplayData)이 그대로 받는다.**
- `04-evaluation.md`에 공격자 비교 지표를 추가한다: 목표 달성까지의 턴 수, 누적 임무
  저하도, 합법 수 중 선택 분포, 그리고 **greedy 대비 개선폭**.
- 프롬프트 주입 저항은 이미 평가 항목에 있다(`04-evaluation.md` 2.3). 공격 측 LLM이
  그 항목의 첫 번째 실전 대상이 된다.

## 대안

- **LLM이 상태를 직접 쓴다**: 기각. ADR-0003 정면 위반. 재현성도 사라진다.
- **LLM이 자유 형식으로 행동을 서술하고 파서가 해석**: 기각. 파서가 관대해지는 순간
  규칙 위반이 통과한다. 합법 수 열거가 더 단순하고 더 강하다.
- **greedy 없이 LLM만**: 기각. 대조군 없는 주장은 논문에서 버려진다(ADR-0008과 같은 태도).
- **강화학습 공격자**: 보류. 보상 설계와 학습 비용이 이 과제의 범위를 넘고, 데모에
  필요한 것은 "설명 가능한 한 수"다.

## 재검토 조건

- 합법 수 목록이 시나리오를 표현하지 못하는 사례가 나오는 경우 - 행동 유형을 늘리되
  전제조건과 효과를 반드시 규칙으로 적는다.
- LLM 공격자가 greedy를 이기지 못하는 것으로 실측되는 경우 - 그 결과 자체를 보고하고,
  LLM을 공격 측에서 빼는 것도 선택지에 둔다.

## 개정 (2026-09-23) - greedy 기준선의 동률 처리

5항은 greedy를 "합법 수 중 **임무 저하도를 가장 크게 올리는 수**를 고르는 공격자"라고만
적었다. 그 한 줄로는 **이득이 동률일 때 무엇을 고르는지**가 정해지지 않고, 구현
(`ui/src/attack.js` `greedyChooser`)은 `gain` 내림 → `p` 내림 → `id` 오름으로 깼다.
greedy는 대조군이므로 이 빈칸은 코드 세부가 아니라 ADR의 빈칸이다. 여기서 채운다.
**5항은 그대로 두고 아래를 덧붙인다.**

### 무엇이 잘못됐나 - 측정

`ui/public/data/tacnet-01.replay.json`, 초기 거점 `CO2-VEH: 0.5`, 시드 20260906 으로
`playTurn` 을 헤드리스로 6턴 돌린 결과다.

**이득이 평평한 시점이 있다.** t=0 은 작전 단계가 아직 시작되지 않았고, t=300 은 P1
임무(지휘통제)가 이미 100% 라 어떤 수도 저하도를 더 올리지 못한다. 그러면 모든 수의
`gain` 이 0 이라 동률이 `p` 로 넘어가고, `recon` 의 `p` 가 0.95 로 가장 높으므로
**정찰이 매번 이긴다.** 그런데 정찰은 상태를 바꾸지 않으므로(3항 표 "상태 변화 없음")
다음 턴은 완전히 같은 국면이다. 교착이 아니라 **라이브락**이다.

고치기 전:

```
t=0    합법수 이득: recon=0.0000  credential_access=0.0000  escalate=0.0000
       6턴 선택: recon -> recon -> recon -> recon -> recon -> recon(실패)
       최종 침해: {"CO2-VEH":0.5}                     (시작과 같다)
t=150  합법수 이득: recon=0.0000  credential_access=0.0643  escalate=0.1071
       6턴 선택: escalate:CO2-VEH -> lateral:FDC-SRV -> escalate:FDC-SRV
                 -> lateral:TOC-WS(실패) -> lateral:TOC-WS -> escalate:TOC-WS
       최종 침해: {"CO2-VEH":1,"FDC-SRV":1,"TOC-WS":1}
t=300  합법수 이득: recon=0.0000  credential_access=0.0000  escalate=0.0000
       6턴 선택: recon -> recon -> recon -> recon -> recon -> recon(실패)
       최종 침해: {"CO2-VEH":0.5}                     (시작과 같다)
```

고친 뒤:

```
t=0    6턴 선택: escalate:CO2-VEH -> lateral:TOC-WS -> escalate:TOC-WS(실패)
                 -> escalate:TOC-WS -> lateral:BN-SRV -> escalate:BN-SRV(실패)
       최종 침해: {"CO2-VEH":1,"TOC-WS":1,"BN-SRV":0.5}
t=150  그대로              (이득이 평평하지 않으므로 예전 순서와 같은 수를 고른다)
t=300  6턴 선택: escalate:CO2-VEH -> lateral:BN-SRV -> escalate:BN-SRV(실패)
                 -> escalate:BN-SRV -> lateral:RELAY-1 -> escalate:RELAY-1
       최종 침해: {"CO2-VEH":1,"BN-SRV":1,"RELAY-1":1}
```

바뀐 것은 **이득이 평평한 시점뿐이다.** t=150 처럼 이득이 갈리는 시점은 예전과 같은 수를
고른다.

### 새 규칙

- **정찰은 최후 수단이다.** 다른 합법수가 하나도 없을 때만 고른다. 3항 표의 정의("관측
  범위 확장, 상태 변화 없음")와 코드 주석이 말하던 "둘 수 있는 수가 없을 때 할 것"이
  이제 실제로 그렇게 동작한다. 행동 목록도 효과도 바뀌지 않았고, **언제 고르는가**만
  바뀌었다.
- **동률은 전진을 뜻하는 값으로 깬다.** 순서는
  **`gain` 내림 → `advance` 내림 → `jewelDistance` 오름 → `p` 내림 → `id` 오름**이다.
  - `advance` = 그 수가 성립했다고 가정했을 때 그래프에 들어가는 침해량의 합,
    `Σ_assets max(0, after[id] − before[id])`. 이미 있는 `applyEffect(g, state, move, true)`
    로 계산하므로 효과 규칙을 두 번 적지 않는다.
  - `jewelDistance` = `g.links` 위의 **무향·베어러 무관** BFS 로 잰 `g.crown_jewels` 까지의
    홉 수. 작을수록 앞이고, 모르거나 닿지 않는 표적은 맨 뒤다. 경로를 계획하는 것이
    아니라 **방향**을 고르는 값이므로 링크 단절은 빼지 않는다(무엇이 도달 가능한지는
    `legalMoves` 가 이미 정했다).
- **결정론은 그대로다.** 같은 그래프·상태·`t`·시드면 언제나 같은 수다. `Math.random` 이
  없고, 정렬하지 않은 순회도 없다(BFS 이웃과 시드 집합을 정렬해서 돈다). 합법수 목록의
  입력 순서도 결과를 바꾸지 않는다.
- **순서의 정의는 하나다.** `attack.js` 가 `orderMoves(moves, ctx)` 를 내보내고,
  `greedyChooser` 는 그 머리를 고르고 `game.js` `legalFor`(교전 패널의 "지금 둘 수 있는
  수")는 같은 함수로 줄을 세운다. 정렬을 양쪽에 따로 적으면 **패널이 1위로 보여주는 수와
  엔진이 두는 수가 갈린다** - 실제로 평평한 시점에서 패널만 정찰을 맨 위에 올리고 있었다.
  정찰은 `gain` 이 항상 정확히 0 이므로 맨 뒤로 보내도 "이득 내림차순" 읽기는 깨지지 않는다.
- **엔진·효과·판정은 건드리지 않았다.** `ACTIONS`, `applyEffect`, `legalMoves`,
  `scoreMoves`, 시드 난수, `engine.js` 가 전부 그대로다. `node ui/tools/parity.mjs` 는
  1622 값 / 불일치 0 을 유지한다. `randomChooser` 도 그대로다.
- **LLM 공격자는 고르는 방식이 그대로다 - 폴백은 아니었다.** 모델은 여전히 같은 모양의
  합법수 목록을 받고 id 하나를 돌려준다. 다만 2회 실패 시의 greedy 폴백
  (`attack-llm.mjs`)이 `greedyChooser(legal)` 를 **맥락 없이** 부르고 있었다. 새 동률
  규칙은 `advance` 를 **현재 상태 기준**으로 재므로, 맥락이 없으면 빈 상태에 대고 재서
  `escalate`/`deny` 가 실제 게임에서는 0.2 일 전진량을 1.0 으로 받는다. 즉 폴백이
  `fallback:greedy` 로 기록되면서 **기준선과 다른 수**를 두게 된다. `ctx` 를 넘기도록
  고쳤다. 폴백을 크게 보고한다는 원칙(옛 주석)은 "같은 것으로 기록되면 같은 것이어야
  한다"까지 포함한다.

### 결과 - 예전 수치와 비교하지 않는다

**이득이 평평한 시작 시점에서 기록한 greedy 대 LLM 수치는 더 이상 비교 가능하지 않다.**
그 구간에서 대조군이 **엄격히 강해졌기 때문이다** - 멈춰 있던 공격자가 전진한다. 옛
redteam 산출물이나 "greedy 대비 개선폭"(결과 절)을 다시 읽는 사람은 이 문단을 먼저 봐야
하고, 비교하려면 같은 코드 버전으로 다시 돌려야 한다. 이득이 평평하지 않은 시점(예:
t=150)의 수치는 영향을 받지 않는다.
