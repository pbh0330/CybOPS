# ADR-0035. 임무 그래프와 동기화하는 작전 화면, 표시 전용 플랫폼 모형

상태: 채택 (2026-11-10), 사용자 요청. 기존 ADR-0001/0003/0004/0018/0024/0025 유지.

## 맥락

사용자가 제공한 참고 영상에는 지도와 3D 플랫폼 관측, 상태 패널, 시간 이동이 함께 있다.
추가 요청은 공군 전투기다. 기존 그래프와 상태 엔진을 지리나 비행 시뮬레이터로 대체할
필요는 없다. 클로드가 같은 시점에 SOC 화면을 작업하므로 별도 브랜치에서 구현한다.

## 결정

1. 기존 기본 뷰는 임무 의존이다. 넓은 화면의 관측 모드에서 `통합 작전`을 선택하면
   임무 그래프, 보조 지도, 자산 관측 패널을 병렬 배치한다. 선택과 시계는 App의 한 상태를 쓴다.
   `?studio=1`은 이 화면의 명시적 진입 링크다. 모바일에서는 기존 단일 뷰로 돌아간다.
2. 3D 모형은 자체 저작 절차적 도형이며 Three.js를 로컬 정적 번들에 포함한다.
   모형은 별도 청크로 지연 로드하고 입력·크기·상태 변경 때만 그린다. 외부 모형 URL,
   텍스처 CDN, 실제 장비 제원, 외부 엔진은 없다. 실패하면 자산 정보는 남는다.
3. `asset.visual_model`은 표시 전용 선택자다. 기존 사이버 `type`과 SIDC는 유지한다.
   전투기/조기경보통제기 아이콘은 플랫폼 오버레이이고 표준 군사 심볼의 대체물이 아니다.
   임무 그래프의 기체 자산은 탑재 임무 단말/상황정보 게이트웨이를 대표한다.
4. `airnet-01`은 6자산·2임무의 자체 저작 합성 훈련이다. 지휘통제 이중화와 전송 단절의
   상호작용을 보여준다. 항적·고도·기체 형상은 표시값이고 판단 엔진은 읽지 않는다.
   실제 비행역학·전투·센서 탐지·무장 운용 시뮬레이션이라는 주장을 하지 않는다.
5. 추이는 원본 리플레이 값만 사용하며 편집된 구성에서는 숨긴다. 결측값은 0으로 채우지
   않는다. 주요 시점은 침해뿐 아니라 환경 단절과 복구도 포함한다.
6. 대응 버튼은 기존 비교·승인 건의 패널로 이동한다. 차단·격리 실행 경로를 추가하지 않는다.

## 비용과 검증

Three.js 청크가 추가되고 통합 화면에서 지도 WebGL과 자산 WebGL을 함께 쓴다.
자산 렌더러는 유휴 반복 렌더링을 하지 않고 언마운트할 때 자원을 해제한다.
기존 화면의 타일 지연 초기화는 유지된다. 통합 작전 진입은 보조 지도 열기를 포함한다.

시나리오는 Python으로 저작하고 기존 PowerShell 참조 엔진으로 리플레이를 만든다.
JS 엔진 parity, 전체 시나리오 불변식, 항공 시나리오 원인 분리·복구 회귀,
좌표/모형 변경 불변성, 링크 규칙, 모형 자원 해제, 브라우저 상호작용을 검증한다.
