# 02. 연구·과제 계획서

## 1. 문제 정의

기존 사이버 상황도는 두 가지 방식으로 실패한다.

1. **지리형 상황도**: 세계지도 위에 공격 화살표가 날아가는 화면. 데모는 화려하지만 운영에서
   못 쓴다. IP 지오로케이션의 도시 수준 정확도 상한이 약 75%로 보고되며(최소 4개 중 1개는
   틀림), 해당 연구는 DB 종류와 무관하게 도시 수준 정확도를 신뢰하지 말라고 권고한다.
   국가 수준은 99.8%로 높지만 미국 IP의 도시 수준은 50km 반경 내 약 66% 수준이다.
   결정적으로, 공격자가 지역 차단을 우회하려 `us-east-1`에 VM을 띄우면 IP는 정상적으로
   북버지니아로 지오로케이션되어 필터를 통과한다. 결국 그 화면은 "어디서 왔는가"가 아니라
   "어느 클라우드 리전에서 나갔는가"를 보여준다.
2. **경보 나열형 콘솔**: 무엇이 임무에 중요한지 알 수 없다.

**연구 질문**: 임무-자산 의존성 그래프를 좌표계로 삼고 LLM을 설명 계층으로 배치한 사이버
공동상황도가, (a) 임무 관점의 상황인지를 개선하고 (b) 감사 가능성과 재현성을 유지하면서
그것을 달성할 수 있는가.

## 2. 선행 연구와 위치

**이미 구현된 영역이라는 점이 실현 가능성의 근거다.**

- 스페인 발렌시아 공대·국방부의 **CyCOP**: SIEM 등 기존 센서에서 얻은 사이버 도메인 정보
  (위협, 공격, 취약점)를 물리 도메인 C2 시스템의 지리참조 정보와 융합하는 fusion module이 핵심.
- 국내 **국방과학연구소(ADD) 2기술연구원**: OODA 루프 기반으로 자산 상태, 조직 네트워크
  토폴로지, 위협 상황을 뷰로 제공하는 CyCOP (VizSec 2019).
- **정량적 설계 기준**: 5종 시각화 화면 프레임워크 연구에서 단순 조회 응답속도 평균 0.11초,
  복합 조회 평균 1.07초로 측정. UI·객체 심볼·객체 크기·응답속도 기준을 지키면 신속한
  상황인지가 가능하다고 보고. → 목표 지연시간 벤치마크가 이미 존재한다.

**본 연구의 차별점 (기여 주장)**

| # | 기여 | 근거 |
|---|---|---|
| C1 | 지리 좌표계 대신 임무-자산 의존성 그래프를 1차 좌표계로 채택하고, 지오로케이션을 판단 경로에서 배제한 설계 | 위 정확도 한계 |
| C2 | 결정론 계층과 LLM 계층의 엄격한 단방향 분리. LLM이 상태값을 쓰지 못하는 구조 | SOC 우선순위 결정의 낮은 precision 실측 |
| C3 | 국방 오픈소스 시뮬레이터에 상황도 시각화·임무 오버레이를 결합한 what-if | Cyberwheel이 지적한 "시각화 도구 부재" |
| C4 | 공개 데이터만으로 군용 상황도를 구성·평가하는 재현 가능한 방법론 + 데이터 수명주기 정책 | 실데이터 반출 제약 |
| C5 | 캘리브레이션·근거 인용률을 주지표로 삼은 LLM 평가 프로토콜 | 벤치마크가 캘리브레이션을 측정하지 않는다는 지적 |

C2와 C5가 가장 방어하기 쉬운 기여다. C1은 설계 논거가 강하지만 "그냥 지도를 안 쓴 것"으로
읽힐 수 있으므로, **임무 좌표계가 지리 좌표계보다 나은 상황인지를 준다는 것을 실험으로**
보여야 한다(전문가 대상 비교 과제).

## 3. LLM 역할 분담의 근거

이 과제의 핵심 설계 결정이므로 근거를 모아 둔다. (→ ADR-0003, ADR-0004)

- SOC 경보 분류 실측: 대부분의 모델이 recall 90% 이상을 보였으나 **우선순위 결정은 precision이
  일관되게 낮아** 상당한 노이즈와 높은 오탐률을 유발. 경량 ML이 경쟁력 있는 성능을 냈고
  **Linear SVM 베이스라인이 전체 F1 최고** 기록.
- 지연: 기존 LLM 접근은 경보당 3~5초 지연이 발생해 실시간 SOC 트리아지에는 비용 과다.
- 보안: NIST SP 800-61r3에 따라 감사 추적성을 유지하면서 프롬프트 인젝션, 모델 회피,
  안전하지 않은 출력 처리 위험을 완화해야 한다.
- 증강에서 자율로 넘어가는 순간 고전 ML에는 없던 환각과 프롬프트 인젝션 위험이 생긴다.
- 캘리브레이션: 벤치마크는 능력을 측정하지 캘리브레이션을 측정하지 않는다. 경보의 94%를
  정확히 분류하는 모델도 무시했어야 할 6%를 포함해 97%에 대해 차단을 실행할 수 있다.
- 상용도 완벽하지 않다: 보안팀들이 Copilot의 "그럴듯하지만 때때로 부정확한 권고"를 보고.

**결론적 분담**

| 계층 | 담당 | 이유 |
|---|---|---|
| 상태 산출 (색, 임무 저하도, 우선순위) | 규칙 + 그래프 알고리즘 + 경량 ML | 재현성, 감사 가능, 지연 |
| 상관·가설 생성, 자연어 질의, 브리핑 초안, ATT&CK 매핑 설명 | LLM | 문맥 이해 강점 |
| 대응 실행 (차단, 격리) | 사람 승인 필수 | 캘리브레이션 미검증 |

## 5. 실험 설계

### E1. 탐지·상태 산출 (트랙 A)
- 데이터: OpTC 레드팀 구간, LANL 레드팀 이벤트
- 비교: 규칙 / Linear SVM / GBDT / (제안) 그래프 결합
- 지표: PR-AUC, precision@k, MTTD → `04-evaluation.md`

### E2. 임무 저하도 타당성 (트랙 B)
- 전파 함수 3종(max / weighted-flow / noisy-OR) 비교
- 시뮬레이터 상 실제 격리 결과 대비 예측 정합성
- 전문가 순위 상관

### E3. LLM 계층 품질 (트랙 C)
- 골든셋 수백 건, 모델 3~4종(온프렘 가능 모델 중심) 비교
- 주지표: 사실 정확성, 근거 인용률·정합성, ECE/Brier
- 별도 프롬프트 인젝션 레드팀 셋

### E4. 상황인지 비교 (C1 방어용)
- 참가자에게 동일 사건을 (a) 지리형 화면, (b) 임무 그래프형 화면으로 제시
- 측정: 임무 영향 판단 정확도, 판단까지 걸린 시간, 주관적 확신도
- n이 작아도 방향성 근거로 충분하다. 반드시 사전에 IRB/윤리 검토 필요 여부 확인.

| 대용량 데이터 취급 부담 | 디스크·시간 | 수명주기 정책, 부분 취득, 작은 것부터 |

| 전술망 대상일 경우 공개 데이터 부적합 | 방법론 변경 | AIT 테스트베드 재생성 경로 |
