5. **설명 바가 세로 공간을 영구 점유.** 한 문장짜리 설명이 항상 떠 있었다.

7. **저하도 휘도 램프가 좁아 80% 와 53% 가 구분되지 않았다**(1차 시안 자체 결함).
   → 램프를 `0.085 + d*0.40` 으로 넓혔다.
8. **높은 저하도 노드에서 % 텍스트 대비 부족**(2차 시안 자체 결함). → `text/primary`
   72% 불투명도로 교체.

### 저하도와 원인의 채널 분리

기존 규칙은 "노드 **색**은 임무 저하도, **테두리**는 그 원인"이었다. 규칙은 유지하되
저하도 채널을 **무채색 휘도 램프**로 고정했다. 저하도가 색상환을 타고 빨강에 도달하면
ADR-0012 와 충돌하기 때문이다. 밝을수록 나쁘다.

- 저하도: `rgb(0.085 + d*0.40)` 계열 무채색. 색상 없음.
- 원인: 테두리 색. 공격은 파선(dashed)까지 더한다.

### 레일 정보구조

6개 패널을 세로로 쌓던 것을 **고정 블록 + 탭**으로 바꿨다.

- 고정: 임무 저하도(항상 보인다. 스크롤되지 않는다)
- 탭: 단절 / 대응 / 브리핑 / 선택
- 고정: 실행 경로 없음 주석 (ADR-0004)

### 봉쇄 비용은 빨강을 쓰지 않는다

"격리 시 임무 +8.2%p"는 나쁜 숫자지만 **공격이 아니다.** 빨강은 공격 전용이므로
비용은 `text/primary` 로만 표기하고 크기로 무게를 준다.

### 미확정

- Pretendard 유지 여부 (시안은 IBM Plex Sans KR)
- 지리 뷰 라벨 배치 (위 3, 4번)

## 2026-09-10 (2) - 시간축 비율, 한국어 라벨, 지리 직접조작

### 시간축이 가로로 1.84배 늘어나 있었다

SVG `viewBox` 는 `0 0 900 64` 인데 요소는 1660px 로 그려지고 있었다. `preserveAspectRatio="none"`
이라 **가로만** 늘어났고, 단계 라벨과 시각 눈금이 다른 UI 보다 넓어 보였다.

원인은 측정 시점이다. `Timeline` 은 그래프가 로드되기 전에 조기 반환하므로 리본 요소가
첫 렌더에 존재하지 않는다. `useRef` + `useEffect([])` 조합은 그 시점에 아무것도 관측하지
못하고 다시 실행되지 않아, 폭이 초기값 900 에 고정됐다.

→ **콜백 ref** 로 바꿔 요소가 붙는 순간 `ResizeObserver` 를 건다. 폭이 측정되기 전에는
아무것도 그리지 않는다. `viewBox` 와 렌더 폭이 일치하는지는 픽셀로 확인했다(1660/1660).

### 자산 id 는 이름이 아니다

`CO2-VEH`, `FDC-SRV` 는 화면에서 유일한 표기였는데 읽어서 뜻을 알 수 없다.
**데이터에는 이미 한국어가 있었다** - `site`("2중대 지휘차", "여단 TOC"), `unit`→`units[].name`.
영어였던 것은 자산 `type` 뿐이고, 그 한국어명은 편집 팔레트(`editor.js` PALETTE)에 이미 있다.

→ `src/labels.js` 로 어휘를 한 곳에 모으고 전 화면에 적용했다.

- 노드 라벨: `site` 를 첫 줄, `id` 를 둘째 줄. **타입은 라벨에 넣지 않는다** - 장비 아이콘이
  이미 그 일을 한다.
- 레일·단절 목록: 한국어 이름 + 작은 회색 `id`
- 원인 라벨(`attack`/`mobility`/…)과 종류(`asset`/`service`/…)도 한국어로
- 임무 비용 표기가 `M-C2 +40.0%p` 였던 것을 임무 이름으로

**id 는 지우지 않았다.** 로그·엔진 산출물과 대조하는 키다. 이름이 아니었을 뿐이다.

### 지리 뷰 직접조작

- 끌기 → 회전(`az`). `geo.js` 는 2D 에서 `pitch` 를 90 으로 고정하지만 `az` 는 그대로
  쓰므로 **2D 에서도 회전이 유효**하다. 그래서 회전 슬라이더를 2D 에서도 보이게 했다.
- 3D 에서 세로 끌기 → 고도각(`pitch`). 아래로 끌면 지평선 쪽으로 눕는다.
- **Ctrl+끌기 → 확대/축소.** 카메라 파라미터가 아니라 완성된 그림에 거는 CSS transform 이다.
  재투영이 아니라 스타일 한 줄이므로 싸다.
- `원래대로` 버튼으로 카메라와 배율을 함께 되돌린다.

**requestAnimationFrame 으로 throttle 하면 안 된다.** 처음에 rAF + "이미 예약됨" 가드로
짰는데, 프레임이 오지 않으면 그 가드가 영영 세워진 채로 남아 **드래그가 중간에 얼어붙는다.**
rAF 는 페이지가 렌더되지 않는 동안 정지하므로 가정이 아니라 실제로 재현됐다
(로그에서 `raf=748` 이 5초간 그대로였다). 시각(`performance.now()`) 기반 throttle 로
바꿨다. 타임스탬프는 멈추지 않는다. 마지막 이동은 `pointerup` 에서 한 번 더 적용한다.

### 새로 생긴 문제

**지리 뷰 라벨 겹침이 더 심해졌다.** 라벨이 한 줄에서 두 줄이 되면서 밀집 구역의
충돌 면적이 커졌다. 시안의 군집 축약이 아직 코드에 없어서 그대로 드러난다.
우선순위를 올려야 한다.

## 2026-09-10 (3) - 고도각 방향, 그리고 계층 띠가 거짓말을 하고 있었다

### 고도각 드래그 방향을 뒤집었다

아래로 끌면 `pitch` 가 90(평면도) 쪽으로 올라가고, 위로 끌면 지평선 쪽으로 눕는다.
장면이 아니라 판을 기울이는 감각이다. 검증: 55° 에서 아래로 끌어 88°, 위로 끌어 12°.

### 계층 띠는 고정돼 있었고, 그래서 틀렸다

지적받은 증상은 "화면을 잡고 움직이면 축이 같이 움직인다" 였는데, 재보니 **정반대**였다.
화면을 `(-171, -196)` 만큼 끌었을 때 띠는 `107/237/402/574` 에서 **1px 도 움직이지
않았다.** 띠가 화면에 못 박혀 있고 노드만 빠져나가므로, 팬을 한 번이라도 하면 "임무"
라벨은 그 순간 화면 위쪽 5분의 1에 있는 것이 무엇이든 그것을 가리키게 된다.

**더 큰 문제가 그 아래에 있었다. 띠의 전제가 사실이 아니다.**

`docs/design/screens/` 와 온보딩에 "위에서 아래로 임무 → 작업 → 서비스 → 자산" 이라고
적어 두었지만, dagre 는 종류가 아니라 **의존 깊이**로 순위를 매긴다. tacnet-01 의 실제
순서는 **임무 → 작업 → 자산 → 서비스 → 자산** 이다. 작업을 수행하는 단말은 작업 바로
아래에 오고, 서비스를 떠받치는 서버는 훨씬 밑에 온다. 종류별로 띠를 그리자
`자산@286` 이 `서비스@532` 보다 위로 나왔다 - 라벨이 엉뚱한 노드를 가리키고 있었다.

→ 종류로 묶지 않는다. **레이아웃이 만든 행을 y 로 군집화하고, 각 종류가 처음 나타나는
행에만 이름을 붙인다.** 지금 tacnet-01 에서는 `임무 / 작업 / 서비스·자산` 세 개가 나온다.
자산은 세 행에 흩어져 있지만 "자산" 을 세 번 쓰지 않는다.

띠는 `pan`·`zoom`·`layoutstop` 에 다시 측정된다. 라벨은 왼쪽 가장자리에 고정되고 화면
밖으로 밀리지 않도록 클램프된다 - 읽을 수 있는 위치에 있되, 가리키는 대상은 진짜다.

**이 항목은 설계 문서 쪽도 고쳐야 한다.** 온보딩 3번 문장과 `screens/` 의 "임무 → 작업
→ 서비스 → 자산" 서술은 레이아웃이 실제로 하는 일과 다르다.

## 2026-09-12 - 지리 뷰 라벨 충돌: 군집을 접고, 라벨이 자리를 고른다

`screens/geo.md` 의 "군집 축약" 과 "라벨 방향 명시 배치" 를 코드로 옮겼다. 시안과 다른
점은 방향을 유닛별로 손으로 고정하지 않았다는 것이다. 카메라가 돌면(회전·고도각) 같은
유닛의 이웃이 바뀌므로 손으로 고정한 방향은 한 자세에서만 맞는다.

**군집은 접힌 채로 시작한다.** `geo.js` 는 이미 근접 자산을 격자 셀(장면 폭의 2%)로
묶어 링 위에 펼치고 있었다. 링만으로는 부족했다 - 60px 링에 두 줄 라벨 셋이 올라가면
서로 덮는다. 이제 2개 이상인 셀은 **마커 하나 + 개수 배지**로 그리고, 누르면 링으로
펼친다. 접힌 마커는 구성원 중 **가장 나쁜 상태**를 테두리에 보인다(공격 > 단절 > 정상).
TOC 안의 침해된 서버가 조용한 배지 뒤로 사라지면 안 된다. 선택된 자산이 든 군집은
항상 펼쳐진다 - 레일에서 고른 것을 지도가 접어 두면 안 된다.

**라벨은 여덟 자리 중 비는 곳을 고른다.** 아래 → 오른쪽 → 왼쪽 → 위 → 대각선 넷.
장애물은 모든 마커, 이미 놓인 라벨, 그리고 가중치 절반으로 지명(능선·하곡·건물 이름).
전부 겹치면 가장 덜 겹치는 자리에 놓고 **숨기지 않는다** - 숨긴 라벨은 지도에 없는
부대다. 선택된 것과 손상된 것을 먼저 놓아서 물러나는 쪽은 조용한 것들이다.

글자 폭은 측정하지 않고 추정한다(CJK 1em, 라틴 0.58em). `renderGeo` 는 DOM 이 아니라
문자열을 만들기 때문이다. 오차는 몇 px 이고 칩 패딩이 흡수한다.

**CSS 에서 `text-anchor` 를 뺐다.** 스타일시트 규칙은 프리젠테이션 속성을 이기므로,
`.geo-label { text-anchor: middle }` 이 남아 있으면 오른쪽·왼쪽 배치가 전부 가운데
정렬로 그려진다. 앵커는 `geo.js` 가 라벨마다 속성으로 준다.

확인: tacnet-01 2D 에서 8 마커 중 3 군집(여단 TOC 4, 대대 지휘소 2, 포병 FDC 2),
라벨 겹침 0. 펼친 4-링에서도 0(대각선 슬롯이 없을 때는 1건 겹쳤다). defnet-01 은 셀이
6 m 라 접히는 것이 없고, 3D 에서 층별로 쌓인 마커의 라벨이 좌우로 흩어진다. parity
1,269/0, 게이트 7/7. 번들 1,637 kB.

남은 것: 편집 인스펙터의 임무 연결 컨트롤. 온보딩 3번 문장은 고쳤다(레이아웃이 실제로
하는 일로).

## 2026-09-14 (2) - defnet-01 의 공격 경로가 화면에 없었다

- chain 형식은 `steps` 형식으로 정규화한다(`off/60` → `t`, `chain` 의 관측·기법 id 를

- UI: `graph.timeline` 이 없어도 스텝이 둘 이상이면 리본을 체인 시계로 그린다(`+N분`,

  "재밍인지 기상인지 알 수 없다" 는 문장이 데이터에만 있었다.

## 2026-09-14 (3) - ATT&CK 기법은 id 만으로는 아무 뜻이 없다

`T1021.002` 라고만 찍혀 있던 것을 **id · 한국어 이름 · 전술 · 관측 · 한 문장 풀이**로 읽어
준다. 자산 id 와 같은 규칙이다 - id 는 데이터와 대조하는 키라서 남기고, 읽는 것은 이름이다.

- 표는 `configs/attack-techniques.ko.json`. 두 시나리오·교전 모드·탐지 근거 카드가 쓰는
  기법 19종과 전술 14종. `name_ko` 는 공식 번역이 아니라 이 프로젝트의 표기이고, `meaning`
  은 "여기서는 이렇게 나타난다" 까지 적은 한 문장이다. 한국어는 코드가 아니라 데이터에
  둔다(CLAUDE.md 인코딩 규칙). 시나리오에 새 기법을 넣으면 여기 한 줄을 더한다.
- `attack-chain.json` 의 관측(`msg`)은 로그 어휘 그대로 영문이라 `msg_ko` 를 저작했다.
  리플레이 내보내기는 문장을 조립하지 않고 **구조화된 `gt` 목록**(technique, tactic, msg,
  host)을 내보내며, 한국어로 푸는 것은 화면의 일이다.
- 단절 탭 스텝 카드: `T1021.002 SMB 관리 공유 접속 [측면 이동]` / `DC01 에서 svc_backup
  계정으로 DC02 원격 로그온 · DC02` / `관리자 권한 계정으로 다른 호스트의 숨은 공유에 붙어…`.
  tacnet 은 관측 문장이 없고 `note` 가 그 자리를 채운다. 리본 표시의 툴팁과 교전 모드의
  턴 결과(`T1021 원격 서비스 접속`), 탐지 카드의 신호 줄도 같은 표를 쓴다.

하나 잡았다: `payload.attack.steps` 는 저작 파일 그대로라 tacnet 의 `gt` 가 객체 하나이고
defnet 의 정규화본은 목록이다. `.map` 을 객체에 걸어 tacnet 화면이 통째로 비었다.
둘 다 받도록 했다. **저작 파일과 내보낸 파일의 형태가 다르면 UI 는 둘 다 받아야 한다.**

## 2026-09-14 (4) - 경로 둘: 공격이 지나간 길, 선택한 노드가 떠받치는 길

의존 그래프는 상태(색·테두리)만 보이고 **경로**는 안 보였다. 붉은 테두리 셋이 어느 순서로
생겼는지, 이 서버가 죽으면 어느 임무가 흔들리는지는 사람이 머릿속에서 이어야 했다.

**공격 경로.** 현재 시점까지의 스텝을 훑어 침해값이 처음 0 을 넘는 순서로 자산을 세우고,
연속한 두 자산 사이에 붉은 파선 화살표를 긋는다. 라벨은 그 스텝의 기법 한국어 이름과
시각(`SSH 접속 +345분`). tacnet: CO2-VEH → BN-SRV → TOC-SRV, defnet: WKS003 → DC01 →
DC02 → DB01. **저작된 침해 순서를 읽은 것이지 엔진의 추론이 아니다** - 범례에 `저작 순서`
라고 적고 툴팁에도 적었다. 붉은색은 공격 전용이라(ADR-0012) 자산 사이의 붉은 화살표는
다른 뜻이 있을 수 없다. 전송로 뷰에도 그린다(호스트 사이의 이동이므로). `derive.js`
`attackHops`.

dagre 에는 안 넣는다. 자산→자산 엣지를 레이아웃에 주면 rank 가 바뀐다. 레이아웃이 끝난
위에 얹고, 레이아웃을 돌릴 때는 `.attack-hop` 을 뺀다.

**기여 경로.** 노드를 고르면 구조 엣지를 따라 위(predecessors: 이 노드가 떠받치는 것)와
아래(successors: 이 노드가 딛고 선 것)를 남기고 나머지를 16% 로 흐린다. 지우지 않고
흐리는 이유는 경로를 맥락 안에서 읽어야 하기 때문이다. 전송로는 다른 그림이라 제외.
인스펙터의 "노드를 클릭하면 기여 경로가 나온다" 가 이제 참이다.

BN-SRV 를 고르면 전술 C2 메시징을 거쳐 작업 대부분과 지휘통제가 밝다. 넓지만 사실이다 -
그 서비스가 그만큼 많은 작업을 떠받친다.

딥링크에 `select=` 를 더했다(`?scenario=tacnet-01&t=300&select=BN-SRV`).

## 2026-09-20 - 교전 모드 2차 (ADR-0026)

교전 모드를 게임으로 만들었다. 설계는 `docs/superpowers/specs/2026-09-20-wargame-v2-design.md`,
규칙은 `docs/22-wargame.md`.

- **격리가 공격자의 거점이었다.** 옛 `wargame.js` 는 격리를 `state[id]=1` 로 넣었고
  `attack.js` `footholds()` 는 0.5 이상을 전부 거점으로 봤다. 방어자가 격리한 자산에서
  공격자가 측면 이동을 시작했다. 승패와 턴을 붙이자 첫 턴에 드러났다 - 게임이 아니었을 때는
  아무도 눈치채지 못했다. 이제 격리는 두 뜻을 갖는다: 임무 엔진에는 `compromise=1`(미가용,
  대응 탭과 같은 엔진 what-if - 다만 게임은 우선순위 가중합, 대응 탭은 최악 임무 하나의 delta 라 숫자는 다를 수 있다), 공격자에게는 없는 자산(`legalMoves`·`footholds`·
  `reachableFrom` 의 `isolated` 옵션). 기본값이 빈 배열이라 관측 모드의 공격 경로와
  `parity.mjs` 는 한 값도 안 바뀐다.
- **게임을 순수 코어로 옮겼다.** `game.js` 는 DOM 도 네트워크도 모른다. 게임은 값이고 모든
  행동은 새 값을 돌려준다. 이유 둘. 첫째, 재현성을 테스트로 잡을 수 있다(같은 시드 두 판 =
  같은 history). 둘째, 그래프·지도·상단 띠가 같은 `game` 값을 읽으므로 패널과 그림이 어긋날
  길이 없다. LLM 공격자의 한 번 `await` 는 패널이 세대 카운터로 막는다 - 늦게 온 응답이 옛
  게임을 되살리지 못한다.
- **참모는 읽기만 한다.** 순위는 규칙(`gainBlocked − cost`, 동률은 `blocks`)이 매기고 모델은
  그 표를 2~3 문장으로 읽어 주며 문장마다 `[F#]` 를 단다. 모델이 순위를 바꾸거나 행동을
  고르게 하지 않은 이유는 ADR-0003 이다 - 상태를 정하는 경로에 모델이 서면 안 된다. 카드에
  "표를 읽은 것이지 표를 만든 것이 아니다" 라고 적은 이유는, 모델 문장이 붙는 순간 사람은
  문장을 결정으로 읽기 때문이다. 문장은 `history` 에 남지 않는다.
- **hold 와 jewel 은 점수 방향이 반대다.** hold 는 누적 저하도(낮을수록 좋음), jewel 은 버틴
  턴 × 100 − 격리 비용(높을수록 좋음). 하나로 맞추려면 hold 를 "예산 − 저하도" 로 뒤집어야
  하는데 그러면 숫자가 임무 수치와 멀어진다. 대신 시작 카드와 AAR 에 방향을 글로 적었다.
  상단 띠의 점수 칸에는 자리가 없어 안 적었다 - 모드를 알고 읽어야 한다(docs/22 5절).
- **상단 띠의 "침해 자산" 이 격리를 세고 있었다.** 엔진이 격리 자산을 침해 1 로 보므로
  `kpiOf` 가 그것을 침해로 셌다. 게임 중에는 격리 수를 빼고 `격리 N` 을 따로 붙인다. 그래프·
  지도도 같은 이유로 격리 자산을 붉게 칠하지 않는다(무채 이중선, `outage` 색 마커).
- **그림.** 후보수 상위 6 은 빨강 저불투명도 점선(공격자의 수이므로 빨강, ADR-0012), 판정은
  표적 노드의 0.8초 번쩍임(성공 빨강, 실패 회색), 격리는 무채 이중선. 교전 중에는 시간축을
  잠근다(`교전 중 · 시점 고정`) - 시점이 움직이면 패널의 턴 루프와 그림이 다른 `t` 를 본다.

확인: 스크린샷 3장(`docs/design/screens/2026-09-20-wargame-{start,play,aar}.png`), vitest
43개(game 13), `parity.mjs` 불일치 0, `Invoke-Gates.ps1` 8/8.

## 2026-09-21 - 교전장 A (ADR-0027, 초안은 B 단계에서)

빈 망에서 시작해 임무가 요구하는 것을 직접 채우는 시나리오 `sandbox-01`. 설계는
`docs/superpowers/specs/2026-09-21-sandbox-and-analysis-design.md`, 규칙과 화면은
`docs/23-sandbox.md`. 브랜치 `ui/sandbox-a`.

- **파생이지 파일이 아니다.** `sandbox-01` 은 `scenarios/` 에 없고 브라우저가 tacnet-01 replay
  에서 `makeSandbox` 로 만든다. 임무·단계·작업·서비스·부대·`requires`·AO 는 물려받고 자산·링크·
  보석·시간축·공격은 비운다. 파일로 두면 셋이 따라온다 - exporter 에 경로 하나, 게이트에 케이스
  하나, 그리고 템플릿의 임무 계층을 고칠 때마다 두 벌을 맞추는 일. 파생이면 셋 다 없다. 대가는
  "sandbox-01 의 정본이 무엇인가" 에 답이 없다는 것인데, 답은 "없다" 가 맞다 - 정본은 사용자의
  구성(작업본·플랜·내보낸 파일)이고 그것은 임무 계층 위의 망이다.
- **준비도 게이트가 엔진 수정을 대신한다.** `serviceDegFor` 는 제공자 없는 서비스를 저하 0 으로
  본다. 그 규칙을 "제공자 없음 = 저하 1" 로 바꾸면 저작 시나리오의 숫자, PowerShell 참조, parity
  가 같이 움직인다. 대신 시작을 막는다 - 서비스마다 제공자, 작업마다 수행 자산. 게이트는 덤으로
  "임무가 무엇을 필요로 하는가" 를 가르친다. 빈 카드에 이름이 다섯 개 여덟 개 적혀 있으니.
- **도달성 조건을 더했다(a5dcb3d).** 구조가 찬 "준비된" 8자산 7링크 판을 놓고 보니 공격 없이
  화력지원 저하 76 % 였다. 중계 게이트웨이가 종단 단말하고만 이어져 서버 컴포넌트에 못 들어갔고,
  그 뒤의 워크스테이션·관측반 단말이 제공자에 닿지 않았다 - 엔진은 닿지 않는 제공자를 저하 1 로
  본다. 구조상 완성, 기능상 사망. 그래서 게이트가 셋째로 엔진의 **무공격 기준선**을 묻는다
  (`runChain(g, {}, { t: -1 })`, 모든 작업 저하 0). 구조가 찬 뒤에만 묻는 이유는 반쯤 빈 그래프의
  기준선은 잡음이기 때문이고, 잠금 문구가 갈리는 이유는 고치는 방법이 다르기 때문이다(비었으면
  자산을, 안 닿으면 링크를). 링크 0 인 판은 엔진 `reach()` 가 참을 돌려주므로(parity 대상,
  엔진은 손대지 않는다) 게이트가 자산 둘 이상·링크 0 인 판을 자기 루프 하나(`_probe`)를 붙인
  사본으로 묻는다 - 연결성은 그대로이고 엔진의 도달성 규칙이 적용돼 링크로 닿지 않는 수행
  자산이 전부 잡힌다. 자산 하나가 전부 제공·수행하는 판은 링크 없이 준비되고 그것이 맞다.
  고립 자산 행은 세되 막지 않는다.
- **규칙 밖을 막지 않는다.** 규칙표(`configs/link-rules.json`)는 후보를 고르고 순위를 매기는
  데이터이지 스키마가 아니다. 링크 도구로 어떤 두 자산이든 이을 수 있고 인스펙터가 `규칙 밖`
  을 붙일 뿐이다. 막으면 두 가지가 생긴다 - 규칙표가 틀렸을 때 사용자가 막히고, 규칙표를
  고치는 것이 UI 를 고치는 일이 된다. 경고면 판은 사용자의 것이고 표는 표의 의견이다.
- **`'신규'` 는 site 가 아니다(c2c6f1d).** 새 자산의 자리표시 site 끼리 "같은 위치" 로 유선
  후보가 되던 것. `siteOf` 하나로 후보와 경고가 같은 기준을 읽는다.
- **프리셋은 코드다.** `presets.js` 의 셋(내부자·위성링크 침해·다중 거점)은 그래프를 읽어
  표적을 고르고, 해당 자산이 없으면 null 을 돌려줘 버튼이 비활성이 된다. 규칙표처럼 JSON 으로
  빼려면 "해당 없음" 을 말하는 조건 언어가 필요한데 셋을 위해 그것을 만들 이유가 없다.
- **`footholds[]` 는 하위 호환이다.** `startGame` 은 `footholds[]` 가 비어 있지 않으면 그것을,
  아니면 `foothold` 를 쓴다. 둘 다 같은 `attacker` 맵이 되므로 게임의 나머지는 어느 쪽인지
  모른다. 기존 호출·테스트·"같은 시드로 다시"(`game.cfg` 재사용)는 한 줄도 안 바뀌었다. 시작
  카드는 프리셋이 켜져 있을 때만 `footholds` 를 cfg 에 넣는다 - 저작 시나리오의 cfg 는 전과
  같다.
- **배치는 결정론이고 표시 전용이다.** `placeFree`(2 km 격자의 빈 칸)와 `placeNear`(150 m 링,
  60 m 간격)는 같은 그래프면 같은 점을 준다. 드래그는 편집 모드에서만이고 undo 에 들어간다.
  엔진은 `geo` 를 안 읽는다(ADR-0002).

확인: vitest 75개(sandbox 23, game 17, editor 5), `parity.mjs` 불일치 0, `Invoke-Gates.ps1`
8/8, 스크린샷 4장(`docs/design/screens/2026-09-21-sandbox-{empty,build,map,play}.png`).

## 2026-09-23 - 참모 S1 (ADR-0027, ADR-0028)

LLM 의 역할을 공격자에서 참모로 옮겼다. S1 은 **결정론적 절반**이다 - 모델 호출이 한 줄도
없고, 라우팅·서술·기권·평가셋은 S2, 교전 흡수는 S3 다. ADR-0028 안에 구현/미구현을 줄 단위로
가른 표가 있다.

**왜 지금인가.** 브리핑이 사전 생성이라 `tacnet-01` 의 세 시각 밖에는 없었고, **편집된
그래프에는 아예 없었다.** 교전장은 정의상 전부 편집된 그래프라 LLM 이 닿지 않았다.

**폰에서 참모는 드로어가 아니라 레일 탭이다.** 모바일 M1 의 하단 시트가 이미 그 자리를
쓰고 있어서 고정 드로어를 또 두면 둘이 가린다. 그래서 컴포넌트를 하나만 만들고 부모만
바꾼다(M1 의 `railEl`, M2 의 포털과 같은 규칙). 두 벌로 렌더하면 질의 기록도 두 벌이 된다.
측정: 390px 에서 `.staff-dock` 0개 + 레일에 `참모` 탭, 1600px 에서 그 반대.

**인자는 거부하지 고쳐 주지 않는다.** `k='3'`, `k=0`, `k=2.5` 는 이유와 함께 거부하고,
인자가 아예 없을 때만 기본값을 채운다. 근거는 S2 다 - 읽을 수 있는 거부 사유는 모델에게
교정 신호이지만 조용한 보정은 "틀린 인자가 맞았다"고 가르친다.

**비용 정의는 하나다.** 교전 중이면 `game.staffTable` 을 그대로 부르고, 관측 모드에서는
`game.js` 의 `weightedOf` 를 **import 해서** 같은 식을 세운다. 복제했으면 교전과 관측이
서서히 다른 말을 하게 됐을 것이다.

**답은 언제 기준인지 말한다.** 답변 카드는 계산된 시나리오 시각을 들고 있고, 화면이 옮겨
가면 "기준 시각이 다름"으로 표시된다. 06:00 에 질의하고 06:45 로 옮겨 카드가 뒤집히는 것,
다시 실행한 새 카드는 표시되지 않고 옛 카드는 남는 것까지 브라우저에서 확인했다. 낡은 숫자에
확신에 찬 문장이 매달리는 것이 ADR-0009 가 막으려는 실패이고, S2 에서 문장이 붙으면 더 그렇다.

**모델 없이 전 경로가 돈다.** S1 의 브라우저 확인은 전부 모델 서버가 없는 상태에서 통과했다
(콘솔에 Ollama 연결 거부가 계속 찍힌 채로). 주장이 아니라 확인이다. 이것이 GPU 없는 AWS
시연 사본이 제 기능을 하는 근거다.

**ADR-0027 은 예약 번호를 다른 용도로 채웠다.** 당초 "교전장 B(분석)"으로 예약했으나 준비도
규칙이 먼저 필요해졌다. 근거는 측정값이다 - 구조가 다 찬 "준비 완료" 판이 화력지원 76.2%
저하로 시작했고, 원인은 제공자가 작업 수행 자산에서 링크로 닿지 않는 것이었다.

## 2026-09-23 - AWS 시연 사본 (ADR-0029)

심사·시연용 공개 사본의 저장소 자산(템플릿·배포 스크립트·문서). 설계는
`docs/superpowers/specs/2026-09-23-aws-demo-design.md`, 절차는 `docs/24-aws-demo.md`,
브랜치 `aws/static-0`. AWS 자원은 하나도 만들지 않았다.

- **엔진을 서버로 옮기지 않기로 한 판단, 그리고 그 측정값.** tacnet-01(자산 13, 링크 12,
  서비스 5, 작업 8, 임무 2)에서 `runChain` 1회가 **0.07 ms** 다(Node 24, 1000회 평균).
  서울 리전 왕복은 **10~50 ms**. 옮기면 계산 한 번이 **100~700배** 느려지는데, 더 나쁜 것은
  호출 횟수다 - 마커 드래그와 시간 슬라이더가 매 프레임 재계산이라 조작 한 번이 요청
  수십 개가 된다. 두 번째 이유는 정합이다. 지금 구현은 둘(PowerShell 참조, 브라우저 JS)이고
  `parity.mjs` 가 그 사이 1,622개 값을 지킨다. 서버 엔진은 **구현을 셋으로 만들고 그 게이트
  비용을 그대로 늘린다.** 무거운 배치가 필요하면 같은 `engine.js` 를 Node 에서 돌리면 된다 -
  구현은 둘 그대로다. **"서버가 더 빠를 것" 이라는 직관이 두 자릿수 틀렸다는 것이 이 항목의
  전부다.**
- **프록시 허용목록이 클라이언트와 어긋나 있었다.** 클라이언트는 `${endpoint}/api/chat` 을
  부르는데(`staff-llm.mjs:33`, `attack-llm.mjs:213`; `probeLlm` 는 `/api/tags`)
  `deploy/nginx.example.conf` 와 `deploy/Caddyfile.example` 은 `/api/generate` 만 열어 뒀다.
  **`proxied` 자세로 올렸으면 모든 모델 호출이 403** 이고, 화면에는 "모델 없음" 으로 보였을
  것이다 - 설정이 의도대로 동작하는 모습과 구분이 안 된다. 허용목록은 옳은 선택이지만
  **허용목록은 양쪽이 같은 경로를 말할 때만 방어**이고, 한쪽은 코드고 다른 쪽은 문서라
  조용히 갈라진다.
- **그래서 고친 것을 검사기로 묶었다.** `scripts/Test-ProxyAllowlist.ps1` 이 `ui/src/` 의
  `.js`/`.mjs` 에서 `${endpoint}/api/...` 를 긁어 두 예시 파일과 대조하고 하나라도 빠지면
  exit 1 이다. 게이트 8 → 9개. **막는 것은 지식이 아니라 검사기다**(CLAUDE.md 의 대소문자
  충돌 항목과 같은 교훈이다). 클라이언트가 새 엔드포인트를 부르기 시작하는 날 게이트가 먼저
  운다.
- **계획서가 들고 있던 틀린 명령 둘을 실행해 보고 걷어냈다.**
  - `python -m cfn_lint` 은 **없는 모듈이다.** cfn-lint 1.x 의 패키지 이름은 `cfnlint` 이고
    `__main__` 이 없다. `Scripts\cfn-lint.exe` 를 직접 부르거나
    `python -c "from cfnlint import runner"` 로 설치만 확인한다. 검증 명령이 틀리면
    "검증했다" 가 "usage 를 봤다" 와 같은 뜻이 된다.
  - PowerShell 5.1 의 `Set-Content -Encoding utf8` 은 **BOM 을 붙인다.** 계획은 그것으로
    `config.json` 을 쓰게 돼 있었다. JSON 앞의 BOM 은 `fetch().json()` 을 통과하기 때문에
    **그 다음에 raw 텍스트를 `JSON.parse` 하는 쪽에서 처음 죽는다.** `Deploy-Aws.ps1` 은
    `[IO.File]::WriteAllText(..., New-Object Text.UTF8Encoding($false))` 로 쓴다.
    (CLAUDE.md 인코딩 규칙 2 는 한글 `.ps1` 에 BOM 을 **붙이라**고 한다. 그것은 스크립트
    파일 이야기이고, 스크립트가 **생성하는 데이터 파일**은 반대다.)
- **확인 목록을 두 곳에 두지 않았다.** `Deploy-Aws.ps1` 마지막 단계가 찍는 여섯 줄은
  `docs/24-aws-demo.md` 7.1 절과 **같은 번호**다. GPU 가 있어야 볼 수 있는 넷(7~10)은 문서의
  7.2 절에만 있고 스크립트는 안 찍는다 - 지금 확인할 수 없는 항목을 출력하면 목록 전체가
  "대충 읽고 넘기는 것" 이 된다.

## 2026-09-26 - 모바일 컴팩트 (ADR-0030)

M1(껍데기)·M2(터치 동등성)은 main 에 있고, M3 은 문서다(`docs/26-mobile.md`, ADR-0030).
여기에는 다음 사람이 알아야 할 판단만 적는다.

- **마우스로 통과한 터치 드래그가 깨져 있었다. 이 절에서 가장 중요한 항목이다.**
  `touchend` 뒤에 브라우저가 합성하는 `click` 이 선택을 가로챘는데, 드래그 가드가
  `setTimeout(0)` 으로 풀렸기 때문이다. **마우스는 그 뒤의 click 이 같은 태스크에
  떨어지므로 가드가 살아 있고, 손가락은 최대 300ms 뒤라 타이머가 이미 끝나 있다.** 즉
  마우스로 아무리 눌러 봐도 이 결함은 **원리상** 보이지 않는다. 폰에서 마커를 끌 때마다
  끌던 마커가 선택됐다(390px, CO1-VEH 선택 상태에서 RELAY-1 을 `pointerType: touch` 로
  끌면 선택이 RELAY-1 로 튄다). 지금은 타이머가 아니라 **다음 접촉의 `pointerdown`**
  (포인터 이벤트가 없는 브라우저는 `touchstart`)에서 풀린다 - 터치 뒤의 호환용
  `mousedown` 은 `pointerdown` 을 만들지 않으므로 초기화를 `mousedown` 에 둘 수 없다.
- **그리고 그 검증을 포인터 이벤트로 썼다면 아무것도 증명하지 못했다.** **MapLibre 5 는
  마커 드래그를 `mouse*`/`touch*` 에 걸고 `pointer*` 를 보지 않는다.** 순수 포인터
  시퀀스로는 마커가 **0px** 움직인다 - 통과해도 실패해도 그것은 드래그에 대한 말이 아니다.
  교훈 두 줄로: **입력 종류가 다르면 검증도 다른 입력으로 해야 하고**, 합성 이벤트로 재기
  전에 **대상 라이브러리가 어떤 이벤트에 귀를 대고 있는지**부터 읽어야 한다. "포인터
  이벤트는 마우스와 터치를 통합한다" 는 명제는 참이지만, **그 라이브러리가 구독하지 않으면
  통합이 아니라 무음**이다.
- **`browser_resize` 가 이 환경에서 페이지에 닿지 않는다.** 그래서 모든 측정은 같은
  오리진의 `<iframe>`(390×844, 1600×900) 안에서 `contentDocument` 를 읽어서 했다. 폭은
  흉내 내지만 DPR·safe-area·관성 스크롤·실제 손가락은 재현하지 않는다는 것을 알고 쓴다.
- **데스크톱 불변은 주장이 아니라 측정이다.** 1600×900 에서 개편 전후의 요소 사각형과
  `outerHTML` 길이를 비교해 같음을 확인했다. 그래서 컴팩트 규칙을 공통 CSS 블록에 쓰지
  않는다 - 전부 `[data-compact="1"]`/`@media (max-width: 860px)`/`compact` 불리언 뒤다.
- **컴포넌트는 하나, 부모만 둘.** 레일은 폰에서 하단 시트 안으로, 참모 드로어는 레일의
  탭으로 들어간다. 상단바에서 밀려난 컨트롤도 `createPortal` 로 `⋯` 패널에 **옮긴다**.
  두 벌로 렌더하면 열린 탭·선택·질의 기록이 화면 폭에 따라 갈라진다(ADR-0028 의 S1 에서
  이미 같은 규칙을 썼다).
- **일괄 규칙에 예외를 하나 뒀고, 그 예외가 옳다.** 44px 타깃을 레일·시트·인스펙터에 한
  줄로 걸었더니 이벤트 스트림 48행의 스크롤이 **2,119px**(190px 창에 4.3행)이 됐다. 로그는
  읽는 것이지 항목마다 누르는 것이 아니라서 34px 로 되돌렸다(**1,650px**). 실측 없이
  "이미 44px 이겠지" 로 넘겼으면 반대쪽으로 틀렸을 것이다 - 레일 탭은 계획서가 적은 46px 이
  아니라 **42.4px** 이었고, 로그 행은 **22.66px** 이었다.
- **계획서가 없는 기능을 고치라고 하고 있었다.** "폰에 `Delete` 키 경로가 없다" 고 썼는데
  **`Delete` 키 경로는 데스크톱에도 없었다.** 지우개 도구뿐이었다. 그래서 인스펙터 삭제
  버튼은 "터치 대체물" 이 아니라 그냥 없던 기능이고, 같은 `removeAsset` 을 부른다.
- **겹친 마커를 흩뿌리지 않기로 했다.** 390px 에서 22px 안의 마커 쌍이 18개, 지휘소에는
  1px 안에 5개가 겹쳐 있어 `elementFromPoint` 가 언제나 하나만 돌려줬다. 그래도 심볼을
  실제 자리에서 옮기는 것은 **위치에 대한 거짓말**이라, 탭이 그 자리의 전부를 보고하고
  시트가 `이 위치에 자산 N` 목록으로 묻는다.
- **폰 기본 뷰를 지도로 둔 것은 ADR-0001 의 예외이므로 ADR 에 적었다.** 대화에만 남기면
  다음 사람이 "확정 결정을 조용히 깬 코드" 로 읽는다(ADR-0025 를 쓸 때와 같은 자세다).
  범위는 셋으로 좁혔다 - 컴팩트에서만, georef 가 있는 시나리오에서만, 사람이 뷰를 고르기
  전까지만.
## 2026-09-26 - 참모 S2 (ADR-0028)

닫힌 카탈로그 위에 라우팅과 서술을 얹었다. 상세는 `docs/25-staff.md`, 구현/미구현 표는
ADR-0028. 여기에는 판단만 적는다.

- **가장 중요한 항목: 이 단계는 수치를 내려고 했는데, 수치가 없다.** 골든셋 38문항과
  러너는 있고 카탈로그 회귀 30건은 통과하지만, **이 기계에 Ollama 가 없어 라우팅
  precision@1·인용률·기권 정확도를 한 번도 재지 못했다.** `eval/results/staff-nomodel-
  2026-09-26.json` 은 그 자리에 **0 이 아니라 `null`** 을 적는다 - 0 은 "쟀더니 0" 이라는
  뜻이고, 안 잰 것을 0 으로 적으면 그때부터 그 파일은 거짓말을 한다. 계획서가 "나쁘면
  나쁜 대로 적는다" 고 했던 자리에 들어갈 정직한 답은 **"모른다, 그리고 이 명령을 돌리면
  알 수 있다"** 다(`docs/25-staff.md` 8절).
- **공격자 LLM 은 지우지 않고 플래그 뒤로 보냈다.** `llm.attacker_enabled`(기본 `false`)
  가 참일 때만 시작 카드에 선택지가 뜬다. `attack-llm.mjs`·프롬프트·`getLlmChooser` 는
  한 줄도 건드리지 않았다. ADR-0019 를 폐기하는 것이 아니라 기본값을 옮기는 것이므로,
  되돌리는 비용이 **플래그 하나**여야 한다는 것이 조건이었다. 확인도 그렇게 했다 -
  탐지가 성공한(모델이 닿는) 상태에서도 선택지가 없고, `config.json` 한 줄을 `true` 로
  바꾸면 그 자리에 다시 나타난다. **감춘 주체가 탐지가 아니라 플래그라는 것**을 그렇게
  갈랐다.
- **한 번 재는 탐지는 이 배치와 맞지 않았다.** AWS 시연 사본의 GPU 는 시연 시간에 켜진다
  (`docs/24-aws-demo.md`). 즉 **세션 도중에 모델이 올라오는 것이 정상 경로**인데, 마운트당
  한 번 재는 구현에서는 그때부터 새로고침 전까지 질문 상자가 죽어 있었다. 잠긴 입력 옆에
  `다시 확인` 을 뒀다. 폴링은 하지 않는다 - 대부분의 배치에서 그 주소는 실행 내내 비어
  있을 예정이다.
- **그리고 그 버튼이 StrictMode 에서 한 번 영구히 멈췄다.** "마운트됐나" 를 `useRef(true)`
  로 두고 정리 함수에서만 `false` 로 내렸는데, 개발 모드의 마운트→언마운트→재마운트가
  그 값을 내린 채로 두어서 `.finally()` 가 통째로 걸러졌다. 버튼이 `확인 중` 에서 영원히
  돌아오지 않았다. **들어올 때 다시 `true` 로 올려야 한다.** 단위 테스트로는 안 보였고
  (jsdom 이 없다) 브라우저에서 눌러 보고 나서야 나왔다 - 3초 뒤 라벨을 다시 읽는 한 줄이
  잡은 것이다.
- **모델 없음 안내문이 교전 이야기만 하고 있었다.** `unavailable_note` 는 S1 까지 교전
  패널 하나가 읽었으므로 "greedy 와 random 은 그대로 동작한다" 로 충분했는데, S2 에서
  참모 질문 상자가 같은 문장을 읽기 시작했다. **비활성 질의창을 보는 사람에게 필요한 말은
  그것이 아니다** - 질의 버튼·사실·표·사전 생성 브리핑이 그대로라는 것이다. 기본값과 두
  예시(`config.hosted.example.json`, `config.aws.example.json`), 그리고 번들에 실제로 실리는
  `ui/public/config.json` 을 같이 고쳤다. 안내문 하나가 네 곳에 복제돼 있었다는 것 자체가
  이번에 드러난 사실이다.
- **질문 상자가 데스크톱에서 180px 였다.** 264px 열을 `묻기` 와 나눠 쓰고 있었고, 자리
  표시 문장(275px)이 "질문을 쓴다 (예: TOC-SR" 에서 잘렸다. **자리 표시 문장은 이 상자가
  낱말이 아니라 문장을 받는다는 것을 가르치는 유일한 줄**이라 잘리면 안 된다. 입력을
  열 전체로 내리고(229px, 글자 폭 211px) 버튼을 아래 오른쪽으로 보낸 뒤, 접두어를 떼서
  예문만 남겼다(208px). 재는 방법은 캔버스 `measureText` 에 **화면에 실제로 적용된 폰트**를
  물려서다 - 눈으로 "잘린 것 같다" 가 아니라 px 두 개를 비교한 것이다.

## 2026-10-14 - 평가 무결성 (ADR-0032)

같은 전시에 나오는 다른 프로젝트 저장소를 읽고, 거기서 본 **측정처럼 보이지만 측정이
아닌 산출물**의 유형을 금지 목록으로 적었다. 상세와 출처는 ADR-0032 다. 여기에는 판단만
적는다.

- **남을 깎는 문서가 아니다. 그러면 쓸모가 없어진다.** 각 항목에 저장소명과 함수명까지
  적되 평가 문장은 쓰지 않았다. 이유는 하나다 - 이 목록의 독자는 우리이고, 독자가
  "우리는 저러지 않는다" 로 읽으면 목록이 하는 일이 사라진다. 그래서 **자기검사 절을
  본문에 넣었고, 거기서 우리 사례 한 건이 나왔다.**
- **그 한 건이 이 문서의 요점이다.** `defnet-01` 의 80.5% / 70.1% 는 `notes[6]` 에
  **"실측 확인"** 으로 적혀 있었지만 ADR-0020 이전 규칙에서 나온 값이고, 그 뒤로 아무도
  다시 재지 않은 채 시나리오·리플레이·문서 넷·ADR 본문으로 퍼졌다. **거짓말을 한 사람이
  없는데 문서가 거짓이 됐다.** 네 글자가 출처 역할을 했고, 옮겨 적은 사람은 그 네 글자를
  믿었다. 금지 2번("측정하지 않은 KPI 를 표로 제시하지 않는다")이 막으려는 것이 정확히
  이 모양이다.
- **그래서 `docs/15` 5.2절의 숫자를 덮어쓰지 않았다.** 그 절은 ADR-0020 **이전** 공식의
  손검산이고, 0.805 를 0.844 로 바꾸면 바로 아래의 `1 - (1-0.945)(1-0.983)` 가 설명하려는
  것이 사라진다. 고칠 것은 숫자가 아니라 **표시**였다. 표 바로 아래에 "현재 엔진은 0.844
  를 낸다, 시나리오 문서로 옮겨 적지 말 것" 을 달았다. 11절에 이미 전역 주의가 있었지만
  **문서 끝에 있어서 5.2절을 읽는 사람에게 도달하지 않았다** - 주의는 복사가 일어나는
  자리에 있어야 한다.
- **ADR 본문은 고치지 않고 개정 절을 붙였다.** ADR-0014 의 66·75 행이 70.1% 를 현재값
  으로 적고 있다. 그 줄은 2026-09-06 의 기록이고, 지우면 "왜 그때 그 숫자를 근거로
  삼았나" 에 답할 수 없다. 대신 **그 두 줄을 인용하지 말라**고 가리키는 절을 끝에 붙였다.
  ADR-0019 가 같은 방식(2026-09-23 개정)으로 선례를 만들어 두었다.
- **숫자 둘을 한 숫자로 합치지 않았다.** 카탈로그는 8종이고 골든셋이 덮는 클래스는 7종
  이다. "8종을 평가한다" 로 적는 것이 문장은 짧아지지만, 그것이 바로 금지 2번이 막는
  동작이다. `docs/04-evaluation.md` 2.3.3 이 두 줄로 나눠 적고 2.3.4 가 빠진 한 종
  (`decision_why`)과 **닫히는 조건**을 적는다.
- **`decision_why` 문항은 일부러 넣지 않았다.** 하네스의 `ctxFor()` 가 리플레이 step
  으로 ctx 를 만들고 `ctx.game` 을 넣지 않으므로 넣으면 채점이 던진다. 던지지 않게
  만드는 길은 골든셋이 교전 이력을 선언하고 하네스가 그것을 재생하는 것이고, 그것은
  문서가 아니라 코드다. **미측정을 미측정으로 적는 것**이 이번에 고른 답이다.
- **`mission_attribution` 은 넣었다.** 관측 ctx 에서 돌므로 기존 하네스가 그대로 채점
  한다. 문항 셋(39~41)을 더하고 러너의 클래스 목록에 그 id 를 올렸다. 러너 주석이
  "클래스 목록에 id 를 먼저 올리면 검사가 실패한다, 그 순서가 의도다" 라고 적어 둔
  대로, **문항과 id 를 같이** 넣었다.
