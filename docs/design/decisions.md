5. **설명 바가 세로 공간을 영구 점유.** 한 문장짜리 설명이 항상 떠 있었다.

6. **패널마다 붙은 fineprint 문단 6개.** → 레일 하단에 고정된 한 줄로 통합.

7. **저하도 휘도 램프가 좁아 80% 와 53% 가 구분되지 않았다**(1차 시안 자체 결함).
   → 램프를 `0.085 + d*0.40` 으로 넓혔다.
8. **높은 저하도 노드에서 % 텍스트 대비 부족**(2차 시안 자체 결함). → `text/primary`
   72% 불투명도로 교체.

### 저하도와 원인의 채널 분리

기존 규칙은 "노드 **색**은 임무 저하도, **테두리**는 그 원인"이었다. 규칙은 유지하되
저하도 채널을 **무채색 휘도 램프**로 고정했다. 저하도가 색상환을 타고 빨강에 도달하면
ADR-0012 와 충돌하기 때문이다. 밝을수록 나쁘다.

- 저하도: `rgb(0.085 + d*0.40)` 계열 무채색. 색상 없음.
- 원인: 테두리 색. 공격은 파선(dashed)까지 더한다.

### 레일 정보구조

6개 패널을 세로로 쌓던 것을 **고정 블록 + 탭**으로 바꿨다.

- 고정: 임무 저하도(항상 보인다. 스크롤되지 않는다)
- 탭: 단절 / 대응 / 브리핑 / 선택
- 고정: 실행 경로 없음 주석 (ADR-0004)

### 봉쇄 비용은 빨강을 쓰지 않는다

"격리 시 임무 +8.2%p"는 나쁜 숫자지만 **공격이 아니다.** 빨강은 공격 전용이므로
비용은 `text/primary` 로만 표기하고 크기로 무게를 준다.

### 미확정

- Pretendard 유지 여부 (시안은 IBM Plex Sans KR)
- 지리 뷰 라벨 배치 (위 3, 4번)

## 2026-09-10 (2) - 시간축 비율, 한국어 라벨, 지리 직접조작

### 시간축이 가로로 1.84배 늘어나 있었다

SVG `viewBox` 는 `0 0 900 64` 인데 요소는 1660px 로 그려지고 있었다. `preserveAspectRatio="none"`
이라 **가로만** 늘어났고, 단계 라벨과 시각 눈금이 다른 UI 보다 넓어 보였다.

원인은 측정 시점이다. `Timeline` 은 그래프가 로드되기 전에 조기 반환하므로 리본 요소가
첫 렌더에 존재하지 않는다. `useRef` + `useEffect([])` 조합은 그 시점에 아무것도 관측하지
못하고 다시 실행되지 않아, 폭이 초기값 900 에 고정됐다.

→ **콜백 ref** 로 바꿔 요소가 붙는 순간 `ResizeObserver` 를 건다. 폭이 측정되기 전에는
아무것도 그리지 않는다. `viewBox` 와 렌더 폭이 일치하는지는 픽셀로 확인했다(1660/1660).

### 자산 id 는 이름이 아니다

`CO2-VEH`, `FDC-SRV` 는 화면에서 유일한 표기였는데 읽어서 뜻을 알 수 없다.
**데이터에는 이미 한국어가 있었다** - `site`("2중대 지휘차", "여단 TOC"), `unit`→`units[].name`.
영어였던 것은 자산 `type` 뿐이고, 그 한국어명은 편집 팔레트(`editor.js` PALETTE)에 이미 있다.

→ `src/labels.js` 로 어휘를 한 곳에 모으고 전 화면에 적용했다.

- 노드 라벨: `site` 를 첫 줄, `id` 를 둘째 줄. **타입은 라벨에 넣지 않는다** - 장비 아이콘이
  이미 그 일을 한다.
- 레일·단절 목록: 한국어 이름 + 작은 회색 `id`
- 원인 라벨(`attack`/`mobility`/…)과 종류(`asset`/`service`/…)도 한국어로
- 임무 비용 표기가 `M-C2 +40.0%p` 였던 것을 임무 이름으로

**id 는 지우지 않았다.** 로그·엔진 산출물과 대조하는 키다. 이름이 아니었을 뿐이다.

### 지리 뷰 직접조작

- 끌기 → 회전(`az`). `geo.js` 는 2D 에서 `pitch` 를 90 으로 고정하지만 `az` 는 그대로
  쓰므로 **2D 에서도 회전이 유효**하다. 그래서 회전 슬라이더를 2D 에서도 보이게 했다.
- 3D 에서 세로 끌기 → 고도각(`pitch`). 아래로 끌면 지평선 쪽으로 눕는다.
- **Ctrl+끌기 → 확대/축소.** 카메라 파라미터가 아니라 완성된 그림에 거는 CSS transform 이다.
  재투영이 아니라 스타일 한 줄이므로 싸다.
- `원래대로` 버튼으로 카메라와 배율을 함께 되돌린다.

**requestAnimationFrame 으로 throttle 하면 안 된다.** 처음에 rAF + "이미 예약됨" 가드로
짰는데, 프레임이 오지 않으면 그 가드가 영영 세워진 채로 남아 **드래그가 중간에 얼어붙는다.**
rAF 는 페이지가 렌더되지 않는 동안 정지하므로 가정이 아니라 실제로 재현됐다
(로그에서 `raf=748` 이 5초간 그대로였다). 시각(`performance.now()`) 기반 throttle 로
바꿨다. 타임스탬프는 멈추지 않는다. 마지막 이동은 `pointerup` 에서 한 번 더 적용한다.

### 새로 생긴 문제

**지리 뷰 라벨 겹침이 더 심해졌다.** 라벨이 한 줄에서 두 줄이 되면서 밀집 구역의
충돌 면적이 커졌다. 시안의 군집 축약이 아직 코드에 없어서 그대로 드러난다.
우선순위를 올려야 한다.

## 2026-09-10 (3) - 고도각 방향, 그리고 계층 띠가 거짓말을 하고 있었다

### 고도각 드래그 방향을 뒤집었다

아래로 끌면 `pitch` 가 90(평면도) 쪽으로 올라가고, 위로 끌면 지평선 쪽으로 눕는다.
장면이 아니라 판을 기울이는 감각이다. 검증: 55° 에서 아래로 끌어 88°, 위로 끌어 12°.

### 계층 띠는 고정돼 있었고, 그래서 틀렸다

지적받은 증상은 "화면을 잡고 움직이면 축이 같이 움직인다" 였는데, 재보니 **정반대**였다.
화면을 `(-171, -196)` 만큼 끌었을 때 띠는 `107/237/402/574` 에서 **1px 도 움직이지
않았다.** 띠가 화면에 못 박혀 있고 노드만 빠져나가므로, 팬을 한 번이라도 하면 "임무"
라벨은 그 순간 화면 위쪽 5분의 1에 있는 것이 무엇이든 그것을 가리키게 된다.

**더 큰 문제가 그 아래에 있었다. 띠의 전제가 사실이 아니다.**

`docs/design/screens/` 와 온보딩에 "위에서 아래로 임무 → 작업 → 서비스 → 자산" 이라고
적어 두었지만, dagre 는 종류가 아니라 **의존 깊이**로 순위를 매긴다. tacnet-01 의 실제
순서는 **임무 → 작업 → 자산 → 서비스 → 자산** 이다. 작업을 수행하는 단말은 작업 바로
아래에 오고, 서비스를 떠받치는 서버는 훨씬 밑에 온다. 종류별로 띠를 그리자
`자산@286` 이 `서비스@532` 보다 위로 나왔다 - 라벨이 엉뚱한 노드를 가리키고 있었다.

→ 종류로 묶지 않는다. **레이아웃이 만든 행을 y 로 군집화하고, 각 종류가 처음 나타나는
행에만 이름을 붙인다.** 지금 tacnet-01 에서는 `임무 / 작업 / 서비스·자산` 세 개가 나온다.
자산은 세 행에 흩어져 있지만 "자산" 을 세 번 쓰지 않는다.

띠는 `pan`·`zoom`·`layoutstop` 에 다시 측정된다. 라벨은 왼쪽 가장자리에 고정되고 화면
밖으로 밀리지 않도록 클램프된다 - 읽을 수 있는 위치에 있되, 가리키는 대상은 진짜다.

**이 항목은 설계 문서 쪽도 고쳐야 한다.** 온보딩 3번 문장과 `screens/` 의 "임무 → 작업
→ 서비스 → 자산" 서술은 레이아웃이 실제로 하는 일과 다르다.

## 2026-09-12 - 지리 뷰 라벨 충돌: 군집을 접고, 라벨이 자리를 고른다

`screens/geo.md` 의 "군집 축약" 과 "라벨 방향 명시 배치" 를 코드로 옮겼다. 시안과 다른
점은 방향을 유닛별로 손으로 고정하지 않았다는 것이다. 카메라가 돌면(회전·고도각) 같은
유닛의 이웃이 바뀌므로 손으로 고정한 방향은 한 자세에서만 맞는다.

**군집은 접힌 채로 시작한다.** `geo.js` 는 이미 근접 자산을 격자 셀(장면 폭의 2%)로
묶어 링 위에 펼치고 있었다. 링만으로는 부족했다 - 60px 링에 두 줄 라벨 셋이 올라가면
서로 덮는다. 이제 2개 이상인 셀은 **마커 하나 + 개수 배지**로 그리고, 누르면 링으로
펼친다. 접힌 마커는 구성원 중 **가장 나쁜 상태**를 테두리에 보인다(공격 > 단절 > 정상).
TOC 안의 침해된 서버가 조용한 배지 뒤로 사라지면 안 된다. 선택된 자산이 든 군집은
항상 펼쳐진다 - 레일에서 고른 것을 지도가 접어 두면 안 된다.

**라벨은 여덟 자리 중 비는 곳을 고른다.** 아래 → 오른쪽 → 왼쪽 → 위 → 대각선 넷.
장애물은 모든 마커, 이미 놓인 라벨, 그리고 가중치 절반으로 지명(능선·하곡·건물 이름).
전부 겹치면 가장 덜 겹치는 자리에 놓고 **숨기지 않는다** - 숨긴 라벨은 지도에 없는
부대다. 선택된 것과 손상된 것을 먼저 놓아서 물러나는 쪽은 조용한 것들이다.

글자 폭은 측정하지 않고 추정한다(CJK 1em, 라틴 0.58em). `renderGeo` 는 DOM 이 아니라
문자열을 만들기 때문이다. 오차는 몇 px 이고 칩 패딩이 흡수한다.

**CSS 에서 `text-anchor` 를 뺐다.** 스타일시트 규칙은 프리젠테이션 속성을 이기므로,
`.geo-label { text-anchor: middle }` 이 남아 있으면 오른쪽·왼쪽 배치가 전부 가운데
정렬로 그려진다. 앵커는 `geo.js` 가 라벨마다 속성으로 준다.

확인: tacnet-01 2D 에서 8 마커 중 3 군집(여단 TOC 4, 대대 지휘소 2, 포병 FDC 2),
라벨 겹침 0. 펼친 4-링에서도 0(대각선 슬롯이 없을 때는 1건 겹쳤다). defnet-01 은 셀이
6 m 라 접히는 것이 없고, 3D 에서 층별로 쌓인 마커의 라벨이 좌우로 흩어진다. parity
1,269/0, 게이트 7/7. 번들 1,637 kB.

남은 것: 편집 인스펙터의 임무 연결 컨트롤. 온보딩 3번 문장은 고쳤다(레이아웃이 실제로
하는 일로).

- 관측 모드: 서비스 제공 / 작업 수행 / 피의존 / 게스트 행. 연결이 없으면 경고 문장
  ("이 자산만으로 임무 수치가 움직이지 않는다").
- 편집 모드: 서비스 체크박스, 작업 체크박스(다른 자산이 맡고 있으면 `지금: BN-CP` 표기),
  중계 체크박스. 전부 `editor.js` 의 `setProvidedBy / setPerformedAt / setTransit` 을
  부르므로 **되돌리기·다시 실행·localStorage 에 다른 편집과 같은 경로로 들어간다.**
  React 쪽에는 상태가 없다. 그래프가 바뀌면 다시 계산해서 그린다.
- 확인: TOC-SRV 에 위치보고(BFT)를 붙이자 그래프가 다시 배치되고 대응 6 -> 5, 되돌리기
  활성. 되돌리기로 체크가 풀린다.

**보드 툴바가 두 줄로 깨지고 있었다.** 편집 상태 문구가 나타나면 1,537px 폭에서 "임무
의존" 버튼이 세로로 접혔다. 버튼·세그먼트·체크박스는 `nowrap; flex: none`, 줄어드는
것은 상태 문구 하나(`.tb-state`, 말줄임). 958px 폭에서는 여전히 레이아웃이 무너진다
(팔레트 210 + 레일 380 을 빼면 캔버스가 370). 좁은 화면은 설계 범위 밖이었지만
적어 둔다.

## 2026-09-14 (2) - defnet-01 의 공격 경로가 화면에 없었다

`scenarios/defnet-01/attack-chain.json` 에 ATT&CK 12단계와 시점별 침해 상태가 저작돼
있었는데 리플레이에는 스텝이 하나(`t=-1`, 침해 없음)뿐이었다. `Export-ReplayData.ps1` 의
`-Timeline` 기본값이 **시나리오와 무관하게 tacnet 의 파일**을 가리켰고, defnet 을 내보낼
때 그 파일을 쓰지 않았으니 공격 입력이 비었다. 데이터는 있었고 배관이 없었다.

- 기본값을 비우고 **시나리오 파일 옆에서** `attack-timeline.json`(분, tacnet) 또는
  `attack-chain.json`(초, defnet)을 찾는다.
- chain 형식은 `steps` 형식으로 정규화한다(`off/60` → `t`, `chain` 의 관측·기법 id 를
  `note` 로). 지어내는 것은 없다 - 저작 파일에 있는 문장 그대로다.
- `timeline` 이 없는 시나리오에 공격 체인이 있으면 **체인 상태마다 스냅샷 하나**를 낸다.
  엔진은 `-At` 없이 돈다(단계 창이 없으므로 전부 활성). ADR-0017 1항의 단일 스냅샷 의미를
  시점마다 적용한 것이고, tacnet 출력은 타임스탬프 외 바이트 단위로 같다.
- UI: `graph.timeline` 이 없어도 스텝이 둘 이상이면 리본을 체인 시계로 그린다(`+N분`,
  단계 레인 없음, 단절 띠 없음, 공격 표시만). 표시 옆에 단계 이름을 쓴다(자리가 있을 때).
  단절 탭 맨 위에 현재 스텝의 이름과 `note`(T1021.002 lateral-movement: remote logon
  from DC01 [DC02]) 를 보인다. **tacnet 의 스텝 note 도 이제야 화면에 나온다** - 그동안
  "재밍인지 기상인지 알 수 없다" 는 문장이 데이터에만 있었다.

확인: `?scenario=defnet-01&t=55&tab=cuts` 에서 DC01 100% / DC02 70% / WKS003 100%,
지휘통제 59.1%(상호작용), 리본에 10단계 표시. parity 1,622개 값(defnet 10스텝 추가)
불일치 0.

엣지가 없어 dagre 가 맨 위 행에 놓는다. 레이아웃이 그렇게 만든 것이니 라벨은 사실이지만
