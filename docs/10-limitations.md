# 10. 못하는 것

작성: 2026-09-06 (전술망 확정 직후, [ADR-0012](adr/0012-target-network-is-tactical.md))

논문의 한계 절은 마지막에 쓰는 것이 아니라 **처음부터 관리하는 목록**이다. 여기 적힌
것을 할 수 있다고 쓰면 심사에서 그대로 무너진다. 세 종류로 나눈다.

---

## A. 구조적으로 불가능 - 자원이 생겨도 안 된다

### A1. 전술망 텔레메트리로 탐지 성능을 주장할 수 없다

그라운드트루스를 갖춘 **공개 전술망 데이터셋이 존재하지 않는다.** LANL·OpTC·AIT는
전부 엔터프라이즈 IT 망이다.

- 쓸 수 없는 문장: "전술망 환경에서 탐지 성능을 검증했다"
- 쓸 수 있는 문장: "임무 계층을 전술망 구조로 설계하고, 탐지 계층은 공개 엔터프라이즈
  텔레메트리로 평가했다"

계층별 출처를 표로 명시한다(ADR-0012 3항). 숨기면 데이터셋을 열어보는 순간 드러난다.

### A2. LANL로는 측면이동 탐지를 평가할 수 없다

라벨에 측면이동이 **없다.** 출발지 호스트 4개와 목적지 301개의 교집합이 0이다
([08-lanl-ground-truth.md](08-lanl-ground-truth.md), ADR-0011).

측면이동·전파 연쇄 검증은 **OpTC로만** 가능하다. OpTC를 못 받으면 E1-b는 수행하지
않는다 - 합성 데이터로 대체하지 않는다(`CLAUDE.md` 규칙 11).

### A3. 기동에 의한 단절과 공격에 의한 저하의 구분을 실데이터로 검증할 수 없다

전술망 확정으로 생긴 새 요구사항인데(ADR-0012 2항), **원인이 라벨링된 공개 데이터가
없다.** 엔터프라이즈 데이터셋에는 애초에 기동이 없다.

합성 시나리오로 기능이 동작함은 보일 수 있으나, **탐지 성능 수치를 주장할 수는 없다.**
이 구분 능력은 설계 기여(C1)로 제시하고 실증은 합성 범위로 한정한다.

### A4. 합성 데이터로 탐지 성능을 주장할 수 없다

`CLAUDE.md` 규칙 11. 합성 데이터의 악성 비율은 0.15%로 실데이터(LANL 0.0000713%)보다
**두 자릿수 높다.** 여기서 잘 도는 탐지기가 실데이터에서 무너지는 것이 정상이다.

합성 트랙의 용도는 개발·회귀 테스트·구성 타당성 검사까지다.

### A5. 상황인지 우월성을 **검증하지 않는다**

전문가 평가를 수행하지 않기로 확정했다(ADR-0015). E4(지리형 화면 vs 임무 그래프형
화면 비교)는 폐기됐다.

- 쓸 수 없는 문장: "임무 좌표계가 더 나은 상황인지를 준다"
- 쓸 수 있는 문장: "임무 좌표계는 경보 심각도 순위와 **다른 순위**를 산출한다"

대체 지표는 두 순위의 불일치도(Kendall tau, top-k 겹침률)다. 사람 없이 계산되고
재현 가능하며, **기각 가능하다** - 두 순위가 거의 같게 나오면 C1은 그 자리에서
기각된다. 기각 불가능한 주장보다 낫다.

## B. 자원 때문에 불가능 - 자원이 생기면 된다

### B1. Kyoushi로 전술 토폴로지를 재생성할 수 없다

AIT의 테스트베드 생성기는 OpenStack에 **최소 30 vCPU / 디스크 800GB / RAM 60GB**를
요구한다. 가용 장비는 워크스테이션 1대이고 전체 RAM이 63.7GB다. RAM만으로도 성립하지
않는다.

`99-open-questions.md`가 이 경로를 "사실상 유일한 현실적 경로"라고 적어뒀던 것은
**하드웨어를 확인하지 않고 쓴 문장이었다.** 클라우드 자원이 확보되면 재검토 대상이다.

### B2. OpTC 전량(약 1TB)을 받을 수 없다

회선 실측 0.6~1.0 MB/s. 1TB면 12~19일이고, F: 여유 906GB에 AIT 130GB까지 감안하면
애초에 들어가지 않는다.

→ 30개 호스트 × 3일의 **최소 세트**로 간다([09-optc-acquisition.md](09-optc-acquisition.md)).
전량 취득을 전제로 한 실험은 설계하지 않는다.

### B3. 회선이 느리다 - 취득 자체가 일정 리스크다

약 12 Mbps(1.5 MB/s)가 상한이고 실효는 0.6~1.0 MB/s다.

실측된 사고: `auth.txt.gz`(7.1GB)는 **세 번째 시도**에 성공했다. 2차 시도는 99.91%에서
브라우저가 이어받기에 실패해 7.62GB를 잃었다. 대용량 취득은 항상 이어받기·정체 감지가
있는 스크립트로 한다(`scripts/fetch-lanl.ps1`).

### B4. LLM 모델 크기 상한이 14B다

확정 사양: RTX 2080 Ti **11GB**(Turing sm_75), Xeon W-2123 4코어, RAM 63.7GB
(ADR-0016). 4비트 양자화 기준 **7~14B가 상한**이고 20B 이상은 CPU 오프로딩이 필요한데
4코어에서는 실용 속도가 안 나온다.

Turing이라 bfloat16 네이티브 미지원, FlashAttention-2 등 Ampere 이상 요구 커널을
쓸 수 없다. 최신 서빙 스택을 그대로 얹으면 막힌다.

**이것이 아키텍처를 강제한다.** 경보마다 LLM을 호출하는 트리아지는 이 하드웨어에서
산술적으로 불가능하다(LANL만 인증 이벤트 10.5억 건). ADR-0003(LLM은 설명 전담)이
원칙이자 강제되는 결론이다.

### B5. Figma 반복 작업 - 해소 예정

Starter 플랜 View 좌석 기준 읽기 도구 월 20회였다. **Pro 구매 예정**이므로 해소된다.
그전까지는 정적인 것만 Figma, 데이터 붙는 것은 코드.

## C. 아직 정하지 않아서 못하는 것 - 판단만 하면 된다

2026-09-06에 Q1·Q2·Q3·Q6이 한꺼번에 확정되면서 **남은 미결은 둘뿐**이다.

| # | 미결 | 막고 있는 것 |
|---|---|---|
| **Q5** | UI / 그래프 렌더링 스택 ★최우선 | **상황도 구현 = 데모 그 자체**. ADR-0013이 2525 렌더러 있는 웹 스택으로 이미 좁혔다 |
| Q4 | LLM 배치 사양 | 모델 선정, 지연 예산. 전술망 확정으로 엣지 하드웨어 상한이 추가 제약 |

닫힌 것: Q1 전술망(ADR-0012) · Q2 2525 준용(ADR-0013) · Q3 데모 1순위(ADR-0014) ·
Q6 전문가 평가 없음(ADR-0015).

## 그래서 무엇을 주장할 수 있는가

한계를 걷어내고 남는 것이 실제 기여다.

| 주장 | 근거 | 상태 |
|---|---|---|
| 임무 좌표계가 경보 심각도와 **다른** 우선순위를 낸다 (더 낫다는 아님 - ADR-0015) | 합성 리플레이(DC01 단독 침해 = 저하 0%, DC02까지 뚫려야 55.9%) + LANL 301개 동시 표적의 순위 불일치도 | 부분 실증 |
| 봉쇄가 공격보다 비쌀 수 있다 | ESX01 격리 what-if = 시작부터 100.0% 저하 (ADR-0020 이전 70.1%) | 실증 완료 |
| 자명 베이스라인이 recall을 무의미하게 만든다 | LANL 실측: recall 100%, precision 1.46% | **실증 완료** |
| 결정론 계층과 LLM 계층의 단방향 분리 | SOC 우선순위 결정의 낮은 precision 실측 | 설계 기여 |
| 공개 데이터만으로 군용 상황도를 구성하는 재현 가능한 방법론 | 취득·검증·수명주기 문서 + 스크립트 일체 | 진행 중 |
| 캘리브레이션·근거 인용률 중심 LLM 평가 프로토콜 | 벤치마크가 캘리브레이션을 측정하지 않는다는 지적 | 설계 기여 |

**가장 방어하기 쉬운 것은 자명 베이스라인 발견과 봉쇄 비용이다.** 둘 다 숫자가 있고
재현 스크립트가 있다. 가장 약한 것은 상황인지 우월성(E4)이다 - 표본이 작다.
