## 2. 골든셋을 손으로 수백 건 쓰지 않는다

계획서 9절이 최대 위험으로 "수작업 부담" 을 적었다. 골든셋 수백 건을 손으로 쓰면 그
위험이 그대로 현실이 된다.

**그럴 필요가 없다.** ADR-0003 이 LLM 의 역할을 이미 좁혀놨기 때문이다.

> LLM 은 요약, 설명, 상관 가설 생성, 자연어 질의, ATT&CK 매핑 서술만 담당한다.
> **LLM 출력이 상태값을 직접 결정하는 경로를 만들지 않는다.**

즉 브리핑의 사실 부분은 **결정론 엔진이 이미 계산해 놓은 것**이다. "t+300 에서 지휘통제
저하도가 얼마이고 공격·환경·상호작용 기여가 각각 얼마인가" 의 정답은 의견이 아니라
`Invoke-MissionPropagation.ps1` 의 출력이다. 단절된 링크와 그 원인 라벨, 침해 자산 목록,
격리 비용도 마찬가지다.

**그래서 요약 과제의 골든 정답은 리플레이에서 기계적으로 유도한다.** 시나리오 2종 x 28
스텝 x 질문 유형 여러 개면 수백 건이 손 안 대고 나온다.

이것이 값싼 우회가 아니라 **이 설계가 애초에 그렇게 되어 있어서 가능한 것**이라는 점이
중요하다. LLM 이 상태를 정하는 구조였다면 정답이 없어 손으로 써야 했을 것이다.

### 자동 유도로 만들 수 없는 것

| 과제 | 정답 출처 | 자동 유도 |
|---|---|---|
| 상황 요약 | 엔진 출력 | **가능** |
| 원인 분해 서술 | 엔진 출력 | **가능** |
| 봉쇄 비용 서술 | 엔진 what-if | **가능** |
| 자연어 질의 | 엔진 상태 조회 | **가능** |
| 상관 가설 | 저작된 공격 타임라인 | 부분 - 시나리오는 가능, 실데이터는 불가 |
| ATT&CK 매핑 | OpTC 라벨 101건 | 부분 - `attack_candidates` 는 **키워드 휴리스틱**이라 검토 필요하다고 라벨 파일이 스스로 적어뒀다 |
| 프롬프트 인젝션 | 저작 | 이미 있음 |

ATT&CK 매핑은 그대로 정답으로 쓰지 않는다. 라벨 파일의 경고를 무시하고 휴리스틱 매칭을
그라운드트루스로 승격시키면, 측정하는 것이 모델의 매핑 능력이 아니라 **우리 키워드 목록과
모델의 일치도**가 된다.

## 3. 확신도를 어떻게 받을 것인가

캘리브레이션을 재려면 모델이 문장마다 확신도를 말해야 한다. 그런데 **확신도를 요구하는
방식이 결과를 만든다.**

- "확신도를 0-100 으로 적어라" -> 대부분 90, 95 로 몰린다. 자유 서술 숫자는 캘리브레이션이
  아니라 화법을 측정한다.
- **선택지 방식** -> 문장마다 `certain / likely / unsure` 중 하나를 고르게 하고, 각 구간의
  실제 정확도를 잰다. 구간이 셋뿐이라 ECE 가 거칠지만 **비교 가능**하고, 모델이 흉내낼
  여지가 적다.

셋으로 간다. 그리고 **거부(abstention)를 1등급 시민으로 둔다** - 근거가 없으면 "모름" 을
고를 수 있어야 하고, `04-evaluation.md` 가 거부율을 지표로 적어둔 이유가 그것이다.
거부가 불가능한 설문은 확신도를 위로 밀어올린다.

## 4. 무엇을 측정하지 않는가

- **요약이 유용한가는 측정하지 않는다.** 자동 유도한 골든셋은 "사실을 맞게 적었는가" 만
  묻는다. 지휘관이 읽고 판단에 도움이 되었는가는 다른 질문이고, ADR-0015 로 전문가 평가를
  하지 않기로 했으므로 이 과제에서는 **측정하지 않는다고 적는다.** 못 재는 것을 잰 척하지
  않는다.
- **일반화.** 시나리오 2종, 모델 3~4종.
- **파인튜닝 비교 없음.** ADR-0006, 계획서 원칙 6.

## 5. 작업 순서

1. 골든셋 생성기 - 리플레이에서 요약·원인분해·봉쇄비용·질의 과제를 유도
2. 브리핑 출력 스키마에 문장별 확신도 3등급 + 거부 추가
3. 채점기 - 사실 정확성, 인용률·정합성(기존 검사 재사용), ECE/Brier, 거부율
4. 모델 3~4종 비교 실행
5. 인젝션 셋 재실행 (ADR-0019 작업분 재사용)
