# 23. 교전장 - 파생 시나리오, 연결 규칙표, 준비도 게이트, 프리셋

**근거**: ADR-0027(교전장 - 파생 시나리오, 연결 규칙표, 준비도 게이트, 분석은 같은 코어의
재실행), ADR-0026(교전 규칙), ADR-0003/0004(모델은 상태를 정하지 않고 실행 경로는 없다)
**상태**: A 단계(기반) 구현 완료(2026-09-21, 브랜치 `ui/sandbox-a`). 설계는
`docs/superpowers/specs/2026-09-21-sandbox-and-analysis-design.md`(A 절), 구현 결정은
`docs/design/decisions.md` "2026-09-21" 절. B 단계(분석)는 6절에 예고만 한다.

---

코드는 `ui/src/sandbox.js`(파생·후보·준비도·배치·검증·플랜 저장, 순수 함수),
`ui/src/presets.js`(공격 프리셋 3종), `ui/src/editor.js`(`addLinkWith`, `setSite/setUnit`,
`toggleJewel`, `moveAsset`), `ui/src/ui/Readiness.jsx`(준비도 카드), `ui/src/ui/Rail.jsx`
`Build`(구성 블록), `ui/src/ui/Wargame.jsx` `StartCard`(잠금·프리셋), 규칙표 데이터
`configs/link-rules.json`(정본, `Export-ReplayData.ps1` 이 `ui/public/data/` 로 복사).

교전장은 **임무·작업·서비스만 물려받고 자산과 링크는 비어 있는** 시나리오 `sandbox-01` 이다.
사용자가 자산을 놓고, 규칙표가 고른 상대와 연결하고, 서비스와 작업에 붙인다. 준비도가 차면
교전(ADR-0026)이 열리고, 그 교전은 저작 시나리오와 같은 엔진·같은 게임 코어 위에서 돈다.

## 1. 왜 파생인가, 그리고 준비도 게이트

> ADR-0027 은 B 단계(분석)에서 초안이 작성된다. 이 문서는 그 ADR 이 있는 것으로 쓴다.

**파일이 아니라 파생이다.** `sandbox-01` 은 `scenarios/` 에 없다. 브라우저가 tacnet-01 replay
를 받아 `makeSandbox(template)` 로 만든다 - 임무 2, 단계 5(`window` 를 떼어 전부 활성, 정적),
작업 8(`performed_at: null`), 서비스 5, 부대, `edges.requires`, `geo.georef/frame`(인제 AO)
은 물려받고 자산·링크·`provided_by/hosted_on/depends_on/redundant_with`·보석·시간축·공격은 비운다.
`steps` 는 비어 있고 App 이 로컬 엔진으로 스냅샷 하나(`t = -1`)를 만든다("편집됨" 경로 재사용).
파일을 두지 않은 이유는 셋이다. 정본(저작 시나리오)을 건드리지 않고, exporter·게이트를 손대지
않으며, 임무 계층이 바뀌면 템플릿을 따라 자동으로 바뀐다. 상단에는 "편집됨" 대신
`구성 중 · 자산 n · 링크 m` 이 보인다.

**엔진 사실 하나가 게이트를 만든다.** `serviceDegFor` 는 제공자가 없는 서비스를 저하 0 으로
본다. 빈 교전장을 그대로 두면 임무가 "정상" 이라 지킬 것이 없고, 자산 하나만 놓아도 교전이
"이긴다". 엔진(과 PowerShell 참조, parity)을 고치는 대신 **준비도 게이트**가 시작을 막는다.
`readiness(graph)` 가 `ready` 를 주려면 셋이 다 차야 한다.

| 조건 | 뜻 | 카드 행 |
|---|---|---|
| 서비스 제공 | 서비스마다 `provided_by` 가 그래프의 자산을 가리킨다 | `서비스 제공 n/5` |
| 작업 배치 | 작업마다 `performed_at` 이 그래프의 자산이다 | `작업 배치 n/8` |
| 도달성 | 위 둘이 찬 뒤, 엔진의 **무공격 기준선**(`runChain(g, {}, { t: -1 })`)에서 모든 작업의 저하가 0 이다. 제공자가 작업 수행 자산에서 링크로 닿아야 한다 - 닿지 않는 제공자는 공격 전부터 저하 1 이다 | `도달성 n/8` (구조가 찬 뒤에만 보인다) |

세 번째가 필요했던 이유는 실측이다. 서비스 5/5·작업 8/8 인 "준비된" 8자산 7링크 판을 놓고
보니 공격 없이 화력지원 저하 76 % 였다. 게이트웨이(중계)가 종단 단말하고만 이어져 서버의
컴포넌트에 못 들어갔고, 그 뒤에 매달린 워크스테이션·관측반 단말이 제공자에 닿지 않았다.
구조상으로는 완성이고 기능상으로는 죽은 판이다. 도달성 행은 그것을 시작 전에 이름으로 보인다.
시작 카드의 잠금 문구도 갈린다 - 구조가 비면 `서비스 n·작업 m 이 비어 있다`, 구조는 찼는데
닿지 않으면 `작업 n 이 서비스에 닿지 않는다 (링크 확인)`.

**링크 0 인 판.** 엔진 `reach()` 는 링크가 하나도 없으면 `true` 를 돌려준다(링크 계층이 없는
그래프는 전송로를 모델링하지 않은 것으로 보는 규칙이고 PowerShell 참조 엔진과 같은 값, parity
대상). 교전장은 그 경우가 아니다 - 자산이 둘 이상인데 링크가 없는 판은 전송로를 안 그린 것이
아니라 아직 안 이은 것이다. 그래서 게이트는 그런 판을 **자기 루프 하나**(`_probe`, 첫 자산에서
자기 자신으로)를 붙인 사본으로 엔진에 묻는다. 연결성은 그대로이고 엔진은 도달성 규칙을
적용하므로, 제공자에 링크로 닿지 않는 수행 자산은 전부 `닿지 않음` 으로 잡힌다(9자산 0링크
판이면 8/8). 자산 하나가 서비스와 작업을 전부 제공·수행하는 판은 자기 루프 없이도 준비되고
그것이 맞다 - 링크가 필요 없는 판이다. 판 자체는 손대지 않는다(`g.links` 는 그대로 `[]`).
`고립 자산` 행(링크 없는 자산 수)은 시작을 막지 않고 무채색 강조로 센다. 보석 0 은 `보석 방어`
모드만 잠근다.

## 2. 규칙표 형식과 후보 규칙

`configs/link-rules.json` 은 데이터다. 시나리오 저작자가 UI 를 안 건드리고 "무엇이 무엇과
통하는가" 를 바꿀 수 있어야 해서다.

```json
{
  "template": "tacnet-01",
  "bearers": {
    "wired":  { "label": "유선", "same_site": true },
    "vhf":    { "label": "VHF" }, "hf": { "label": "HF" }, "lte": { "label": "LTE" },
    "satcom": { "label": "위성", "needs_type": "satcom-terminal" }
  },
  "types": {
    "c2-server": { "bearers": ["wired", "vhf", "satcom"], "provides": ["messaging", "intel"], "performs": ["T-ORDER", "T-SITREP"] },
    "...": {}
  }
}
```

| 키 | 뜻 |
|---|---|
| `bearers.<b>.same_site` | 이 베어러는 양쪽 `site` 가 같을 때만 후보(유선) |
| `bearers.<b>.needs_type` | 한쪽이 이 유형일 때만 후보(위성은 위성 단말) |
| `types.<t>.bearers` | 이 유형이 쓸 수 있는 베어러 |
| `types.<t>.provides` | 이 유형이 제공할 수 있는 서비스 `kind` |
| `types.<t>.performs` | 이 유형이 수행할 수 있는 작업 id |

**후보 규칙** (`linkCandidates(graph, rules, assetId)`): 두 유형의 `bearers` 교집합 가운데
`same_site`·`needs_type` 조건을 통과한 것, 이미 있는 링크는 제외. 순위는 같은 site → 같은 unit
→ 상대가 transit(중계 노드) → 베어러 순서 `wired, vhf, satcom, hf, lte`. `'신규'`(새 자산의
자리표시 site)와 빈 site 는 site 가 아니다 - 새 자산 둘이 "같은 위치" 로 유선 후보가 되면 안
된다(`siteOf`).

**임무 연결 후보** (`missionCandidates`): `provides` 에 맞는 `kind` 의 서비스와 `performs` 의
작업만 위에 펼치고 나머지는 접는다. 연결 자체는 기존 `setProvidedBy/setPerformedAt` 이다.

**규칙 밖은 막지 않는다.** 링크 도구로 어떤 두 자산이든 이을 수 있다. 인스펙터는 규칙에 안
맞는 링크(site 를 바꾼 뒤의 유선, 베어러를 바꾼 링크)에 `규칙 밖` 을 붙일 뿐 지우지 않는다.
규칙표는 표의 의견이고 판은 사용자의 것이다.

**시나리오는 자기 예외를 데이터로 선언한다** (ADR-0033). 저작 시나리오가 의도적으로 한 계층을
접었을 때, 그 사실을 링크의 `rule_exception` 에 적는다.

```json
{"id": "L-FW-WKS001", "a": "FW01", "b": "WKS001", "bearer": "wired",
 "rule_exception": {"exempts": ["same_site"], "why": "부대별 액세스 스위치를 모델링하지 않아 ..."}}
```

| 키 | 뜻 |
|---|---|
| `exempts[]` | 면제받는 규칙표 조건의 이름. `same_site`, `needs_type` 만 가능 |
| `why` | **필수.** 무엇이 모델링되지 않았는지. 없으면 예외로 인정되지 않는다(그 링크는 여전히 규칙 밖) |

"두 끝이 그 베어러를 탄다" 는 검사는 **면제 대상이 아니다.** 그것은 규칙표의 행이 맞는가에
대한 질문이고 답은 행을 고치는 것이다(`c2-server` 의 `vhf` 가 그 경우였다). 넓은 면제를
허용하면 그 빠진 행까지 조용히 덮인다.

선언을 읽는 것은 `linkFitsRules` 뿐이다. `linkCandidates` 는 **아직 없는 링크**를 만들므로
읽을 선언이 없고, 사이트 밖 유선을 여전히 제안하지 않는다. 판정기는 하나다. 선언된 예외는
인스펙터에 `선언된 예외` 로 표시되고 `why` 가 title 에 실린다 - 단순화를 데이터로 적는 목적은
감추는 것이 아니라 보이게 하는 것이다.

## 3. 화면

- **툴바(편집 모드, 교전장에서만)**: `구성 저장`(이름) / `구성 불러오기…` / `삭제…` / `JSON
  불러오기`. 초기화 버튼은 `교전장 비우기`. 되돌리기·다시 실행·내보내기는 저작 시나리오와 같다.
- **인스펙터 구성 블록**(자산 선택 시): 위치(site) 입력(blur/Enter 에서 확정), 부대 셀렉트,
  보석 토글, `연결 가능 (n)` 후보 행(`이름 id · 베어러 · 이유` + `연결`), `이 자산의 링크`(베어러
  셀렉트, `규칙 밖` 또는 `선언된 예외`, `끊기`). 후보가 없으면 "같은 위치의 자산을 놓거나 베어러가 맞는 중계
  노드를 두어라".
- **준비도 카드**(레일 상단, 교전장에서만): 1절의 표. 미충족 항목은 이름으로 나열한다. 색은
  `교전 가능` 한 단어의 `--ok` 뿐이고 부족·경고 행은 무채색 강조다(ADR-0024/0025).
- **지도 배치**: 새 자산의 `geo.at` 은 AO 2 km 격자에서 자산이 1 km 안에 없는 첫 칸의
  중앙(`placeFree`), 첫 링크가 생기면 상대 기준 150 m 링에서 다른 자산과 60 m 이상 떨어진 첫
  각도(`placeNear`). 둘 다 순수·결정론. 편집 모드에서는 MapLibre 마커를 끌어서 놓고 undo 에
  들어간다. z 는 0 이고 표시 전용이다(DEM 은 판단에 안 들어간다, ADR-0025).
- **시작 카드 프리셋**(`presets.js`, 코드): `초기 거점` 셀렉트 위에 `.wg-preset` 버튼 셋.
  `pick(graph)` 가 null 이면 비활성이고 `title` 에 사유가 붙는다.

  | 프리셋 | 고르는 것 | 수준 |
  |---|---|---|
  | 내부자 | `transit === false` 인 첫 자산 | 0.5 |
  | 위성링크 침해 | `satcom-terminal` 첫 자산 | 0.8 (자격증명까지) |
  | 다중 거점 | `transit === false` 인 처음 둘 | 0.5, 0.5 |

  누르면 셀렉트는 첫 거점을 보이고 아래에 `프리셋: 내부자 (CP-01)` 캡션이 붙는다. 셀렉트나
  수준을 다시 만지면 프리셋이 풀린다. 시작 cfg 에는 `foothold`(첫 거점)와 `footholds[]` 가
  함께 들어가고 `startGame` 은 `footholds[]` 가 있으면 그것을, 없으면 `foothold` 를 쓴다.
  교전장에서 시간축이 없으므로 시점 셀렉트는 `정적` 하나이고 `t = -1` 이다. 기본 거점은
  저작 시나리오면 공격 타임라인의 첫 침해 자산, 교전장이면 `transit === false` 인 첫 자산이다.

## 4. 저장 / 불러오기 형식

| 저장소 | 키·형식 | 뜻 |
|---|---|---|
| 작업본 | `localStorage['mccycop:edit:sandbox-01']` = `{ graph, at }` | 저작 시나리오의 "편집됨" 과 같은 경로. 새로고침해도 남는다 |
| 플랜 | `localStorage['mccycop:sandbox:plans']` = `[{ name, saved_at, graph }]` 이름순 | `구성 저장/불러오기/삭제`. 같은 이름은 덮어쓴다 |
| 내보내기 | `sandbox-01-edited.json` = `graph` | 파일 |
| 불러오기 | `graph` 또는 `{ graph, ... }`(replay 페이로드 전체) | `validateImport`: `assets`·`links`·있는 `edges.*` 가 배열이고, `missions/tasks/services` 의 id 열이 템플릿과 같고, 자산 id 가 중복되지 않고, 링크와 모든 `edges.*` 의 양끝이 자산·서비스·작업 중에 있고, `edges.requires` 의 (from,to) 쌍이 템플릿과 같아야 한다. 통과하면 `scenario_id` 는 `sandbox-01` 로 덮는다. 거부 사유는 토스트로 |

불러오기가 임무 계층을 검사하는 이유는 교전장이 망을 짓는 곳이지 임무를 다시 쓰는 곳이
아니기 때문이다. 플랜에는 `steps` 가 없다 - 로컬 엔진이 다시 만든다.

## 5. 한계

- **합성이고 정적이다.** 교전장에는 시간축이 없다(`t = -1`, 단계 전부 활성). 기동·지형 단절은
  저작 시나리오의 것이고 교전장에는 없다. 여기서 나온 점수로 탐지·방어 성능을 주장하지 않는다
  (ADR-0008, `docs/07` 6절과 같은 취지).
- **규칙표는 tacnet-01 기준 17개 유형이다.** 팔레트 유형이 규칙표에 없으면 인스펙터가
  `규칙표에 없는 유형` 이라 적고 후보를 내지 않는다.
- **도달성은 엔진의 답이다.** 링크 0 인 판은 1절의 자기 루프로 엔진에 묻는다 - 자산이 둘
  이상이면 링크로 닿지 않는 수행 자산이 잡히고, 혼자 다 하는 자산 하나짜리 판은 링크 없이
  준비된다. 고립 자산 행은 드러내되 막지 않는다.
- **배치는 표시 전용이다.** `geo.at` 은 엔진에 안 들어간다(ADR-0002, `Test-GeoInvariance`).
  드래그로 옮겨도 숫자는 안 바뀐다.
- **프리셋은 셋이고 코드다.** 규칙표처럼 데이터로 빼지 않은 이유는 프리셋이 그래프를 읽어
  "해당 없음" 을 말해야 하기 때문이다. 늘어나면 그때 형식을 정한다.
- **플랜은 이 브라우저에만 있다.** localStorage 라 다른 기기·다른 브라우저에는 없다. 옮기려면
  내보내기/불러오기다.
