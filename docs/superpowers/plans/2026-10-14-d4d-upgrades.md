# D4D 쇼케이스 반영 업그레이드 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** D4D 쇼케이스 90개 중 우리 구조에 맞는 것만 골라 적용한다. 전부 **ADR 개정 없이** 들어가고, 대부분 기존 ADR 을 더 지키는 방향이다.

**Architecture:** 새 계층을 만들지 않는다. `facts.js` 에 빌더를 더하고, `staff.js` 카탈로그에 질의를 더하고, `game.js` history 에 필드를 더하고, 시나리오 데이터에 출처를 적고, 게이트를 늘린다.

**출처 조사:** `.superpowers/sdd/d4d-2026-10/` 의 세 보고서(DELPHI·천이 / COIC2S·Cert Copilot / 혜안·ARGOS·FlowFront)와 RedCarpet 직접 확인.

## Global Constraints

- **LLM 은 상태값을 만들지 않는다**(ADR-0003). 이 계획에서 추가되는 숫자는 전부 엔진 산출이다. 조사에서 COIC2S 가 LLM 으로 `is_attack` 을 판정하고 LLM 으로 로그를 정규화해 그 결과를 탐지 입력으로 쓰는 것을 확인했다. 그 구조는 복제하지 않는다.
- **인용 없는 문장은 미검증**(ADR-0009). 새로 만드는 사실도 전부 `[F#]` 로 붙는다.
- **실행 경로 없음**(ADR-0004). 결심 기록은 기록이지 명령이 아니다. `authorize` 가 아니라 `record_decision` 이다.
- 엔진(`ui/src/engine.js`, `attack.js`)의 숫자 경로를 바꾸지 않는다. `node ui/tools/parity.mjs` 는 1622 값 0 불일치를 유지한다.
- `npm test` 는 현재 **268개**이고 줄어들면 안 된다. `Invoke-Gates.ps1` 9/9.
- 크롬 무채색, 빨강은 공격 전용(ADR-0024/0025).
- **측정하지 않은 수치를 적지 않는다.** 조사에서 Cert Copilot 의 KPI 7개가 전부 fixture 였고 ARGOS 의 평가가 항진명제였다. 같은 일을 하지 않는다.
- 커밋 트레일러 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`. 문서에 em 대시를 쓰지 않는다.
- 브라우저 확인은 동일 출처 iframe(`browser_resize` 가 이 환경에서 페이지에 안 닿는다). 개발 서버는 `http://localhost:5180` 에 떠 있다.

### U1: 자산별 기여도 역산 `attributionFacts`

**출처:** DELPHI 의 기여 원장(`contrib.py`). 관측 1건이 결과에 몇 dB 를 더했는지 적어 두고 역산한다. 우리는 확률이 아니라 저하도이므로 단위는 %p 이고, 엔진이 결정론이라 **역산이 아니라 직접 계산**이 된다.

**Files:** `ui/src/facts.js`, `ui/src/staff.js`, `ui/src/__tests__/facts.test.js`, `ui/src/__tests__/staff.test.js`

- [ ] **Step 1: 테스트 먼저**

`attributionFacts(g, s, missionId)` 는 그 임무의 저하도를 자산별 기여로 가른다. 방법은 leave-one-out: 각 자산의 침해를 0 으로 되돌린 what-if 를 돌려 임무 저하도가 얼마나 내려가는지 잰다.

```js
contribution(a) = mission(현재) - mission(compromise[a] = 0 으로 둔 경우)
```

테스트가 못 박을 것:
- 기여도 합이 전체 저하도를 넘지 않는다(상호작용 때문에 정확히 같지는 않다. 그 차이를 `잔차` 사실로 따로 낸다)
- 침해가 0 인 자산은 기여 0 이고 목록에 안 나온다
- 같은 입력에 같은 출력
- 각 기여도가 `runChain` 을 직접 두 번 불러 뺀 값과 일치한다
- 자산 13개에서 50ms 미만 (`runChain` 이 0.07ms 다. 측정해서 보고에 숫자를 적는다)

- [ ] **Step 2: 구현**

`facts.js` 에 빌더를 더한다. `value` 는 %p 원값, `text` 는 `pct()` 표기, `ref` 는 `{kind:'asset', id}`. 기여도 내림차순, 상위 `TOP_N`.

**잔차를 숨기지 않는다.** 개별 기여의 합과 전체 저하도의 차이는 상호작용이므로, 마지막 사실로 "개별 합 X%p, 전체 Y%p, 차이 Z%p 는 상호작용" 을 낸다. DELPHI 가 `db/30` 같은 근거 없는 상수로 정규화한 것이 그들의 약점이었다.

- [ ] **Step 3: 질의로 올린다**

`staff.js` 카탈로그에 `mission_attribution(missionId)` 를 더한다. `needs: 'graph'`. 표는 자산 / 기여 %p / 침해 수준. 기존 `mission_why` 는 원인 분해(침해·환경·상호작용)를 내고, 이쪽은 **어느 자산이** 를 낸다. 둘의 차이를 `note` 에 적는다.

- [ ] **Step 4: 게이트와 커밋**

```
참모: 임무 저하를 자산별로 가른다 - 76.2% 중 어느 자산이 몇 %p 인가
```

### U2: 결심 기록과 `decision_why`

**출처:** 천이(결심을 1급 객체로 두고 질의 가능하게), 혜안 `auditLog.ts`(`actorType: human | system`), ARGOS `ACTION_SPECS`(Action 별 `authority`).

우리는 ADR-0004 로 사람 승인을 요구하면서 **승인의 기록을 남기지 않는다.** 이 태스크가 그 구멍을 메운다.

**Files:** `ui/src/game.js`, `ui/src/staff.js`, `ui/src/facts.js`, `ui/src/ui/Wargame.jsx`, 테스트

- [ ] **Step 1: history 행이 근거를 든다**

`defend(g, G, act)` 가 history 에 적는 방어 행을 넓힌다:

```js
defender: {
  type: 'isolate', id, cost,
  actor: 'human',              // 사람이 눌렀다. 자동 경로는 없다(ADR-0004)
  basis: ['F2','F5'],          // 누를 때 화면에 있던 사실 번호
  rank: 3,                     // 그 턴 staffTable 에서 이 자산의 순위
  rationale: '단일 경로라서'    // 선택 입력, 없으면 null
}
```

공격 행에는 `by: 'greedy'|'random'|'llm'` 을 행마다 적는다. 지금은 `cfg.strategy` 가 전역이라 행 단위 추적이 안 된다.

**`rank` 가 핵심이다.** U4 의 순위 일치도가 이 필드로 계산된다.

- [ ] **Step 2: 질의**

`staff.js` 에 `decision_why(turn)` 을 더한다. `needs: 'game'`. **이것이 카탈로그의 첫 `needs:'game'` 질의이므로, S1 때 공허했던 카탈로그 게이트 테스트가 이제 실질 검사가 된다**(`staff.test.js:26-34` 의 주석을 갱신할 것).

사실로 낼 것: 그 턴에 무엇을 격리했는지, 참모 순위 몇 위였는지, 1위는 무엇이었고 왜 안 골랐는지(비용·차단 수 비교), 그때의 근거 사실 번호, 그 결정 뒤 다음 턴 P1 이 어떻게 됐는지.

- [ ] **Step 3: UI**

방어 행동을 누를 때 선택 입력 한 줄(`rationale`)을 받는다. 비워도 된다. 참모 카드에 사실이 떠 있으면 그 번호가 자동으로 `basis` 에 담긴다.

- [ ] **Step 4: 게이트와 커밋**

```
교전: 결심이 기록으로 남는다 - 무엇을 왜 격리했고 참모 순위는 몇 위였나
```

### U8: 조사에서 얻은 원칙을 문서에 박는다

**Files:** `docs/04-evaluation.md`, `docs/adr/0032-evaluation-integrity.md`(신규), `docs/design/decisions.md`, `STATE.md`

- [ ] **Step 1: ADR-0032 평가 무결성**

조사에서 본 실패 사례를 금지 규칙으로 적는다. 각 항목에 **어디서 봤는지**를 적어 둔다. 남을 깎으려는 것이 아니라 우리가 같은 함정에 빠지지 않으려는 것이므로, 사실만 적고 평가는 절제한다.

- **생성기와 채점기가 같은 함수를 쓰면 안 된다.** ARGOS 의 `evaluate_expected_impacts` 가 `point_to_route_km` 로 정답을 심고 같은 함수로 채점해 precision/recall 이 1.0 에 고정된다. 측정이 아니라 항진명제다.
- **측정하지 않은 KPI 를 표로 제시하지 않는다.** Cert Copilot 의 KPI 7개가 전부 fixture 였다(README 가 "기대 수치" 라고 밝히기는 한다).
- **비교에서 시드를 다르게 쓰지 않는다.** 혜안이 기본 대 최적을 다른 시드로 비교한다.
- **기준선을 약하게 만들지 않는다.** 혜안이 실제 최적 교리를 못 이기자 기준선을 바꿨다(주석이 자인).
- **"최악" 은 열거를 완주한 범위에서만 쓴다.** 표집했으면 표본 크기와 재시작 수를 같이 적는다.
- **캘리브레이션 없는 confidence 를 쓰지 않는다.** COIC2S 의 `confidence` 는 후보 간 비율이라 후보가 하나면 100% 가 된다.
- 우리 쪽 금지는 이미 있다: accuracy 금지(ADR-0008), 합성 데이터로 탐지 성능 주장 금지(docs/07 6절).

- [ ] **Step 2: 긍정 원칙 둘**

혜안의 설계 문서에서 가져올 문장 둘을 우리 어휘로 적는다.
- **전수 열거는 비용이 아니라 거버넌스 자산이다**(완전·결정론·감사가능). 우리 교전은 합법수를 열거하므로 이미 그 자리에 있다.
- **검증된 스칼라와 LLM 서술은 타입으로 분리한다.** 우리는 사실(`Fact`)과 문장(`narrate`)이 이미 다른 타입이다.

- [ ] **Step 3:** `docs/04-evaluation.md` 에 참모 평가 절을 보강하고, TRAIN/HELD-OUT·공통난수 페어 비교·지는 구간 명시를 보고 양식으로 적는다.
- [ ] **Step 4: 커밋** `문서: ADR-0032 평가 무결성 - 남의 실패에서 배운 금지 목록`

## 하지 않는 것 (조사에서 보류한 것)

- **판별력 IDF 가중**(COIC2S): ATT&CK 행위자-기법 매핑 데이터가 우리에게 없다. 데이터 취득은 ADR-0010 절차를 따라야 하므로 별도 과제다.
- **기대값 목적함수와 한계수익 탐욕**(혜안): `attack.js` 의 greedy 정렬이 바뀌므로 **ADR-0019 개정**이고 기록된 수치가 전부 무효가 된다. 09-23 의 동률 사고와 같은 함정이라 조용히 하면 안 된다. S3 이후 별도 결정.
- **regret 기반 반사실 복기**(혜안 `replayCritic`): S3 의 B2 항목이다. 거기서 한다.
- **출처 신뢰도 λ(r)**(DELPHI): 시나리오에 출처 등급 데이터가 없다. 온톨로지 결정이 먼저다.
- **공진화 서사**: 혜안도 교대 루프를 구현하지 않았다. 우리가 구현하지 않은 채 같은 말을 쓰면 같은 과장이 된다.
- **팔란티어 AIP**: 플랫폼이 곧 제품이 되어 ADR-0007·0018 과 충돌한다. 가져온 것은 "결심도 1급 객체" 라는 모양뿐이다.

### U9: 자산을 클릭하면 추천 연결이 화면에 보인다

**출처:** 사용자 요청. 조사와 별개로, 교전장 편집에서 실제로 불편한 지점이다.

지금도 `sandbox.js` 의 `linkCandidates(g, rules, assetId)` 가 규칙표로 후보를 고르고 `Rail.jsx:471` 의 구성 블록이 목록으로 보여 준다. 문제는 **목록이 인스펙터 안에만 있다**는 것이다. 자산을 클릭해도 "어디로 이을 수 있는지" 가 화면에서 안 보이고, 후보 이름을 읽고 머릿속에서 지도·그래프의 위치와 맞춰야 한다.

**Files:** `ui/src/ui/GraphCanvas.jsx`, `ui/src/ui/MapPane.jsx`, `ui/src/derive.js`, `ui/src/style.css`

- [ ] **Step 1: 후보를 오버레이로**

편집 모드에서 자산이 선택되면 그 자산에서 각 후보로 **유령 선**을 그린다. 그래프와 지도 양쪽에. 기존 교전 오버레이(`gameOverlay` 의 후보수 유령 화살표)가 이미 같은 일을 하므로 그 방식을 따른다: 점선, 낮은 불투명도, 순위에 따른 굵기.

색은 쓰지 않는다. 이것은 공격이 아니라 구성 보조다(ADR-0024, 빨강은 공격 전용).

- [ ] **Step 2: 유령 선을 눌러 연결**

후보 선이나 그 끝의 자산을 누르면 그 베어러로 바로 연결된다. `editor.addLinkWith(a, b, bearer)` 가 이미 있다. 인스펙터의 `연결` 버튼과 **같은 경로**를 써야 한다. 두 경로를 만들면 규칙이 갈라진다.

- [ ] **Step 3: 규칙 밖은 규칙 밖으로 보인다**

`linkCandidates` 가 규칙표에서 고른 것과 `규칙 밖` 연결을 지금도 가른다. 오버레이에서도 그 구분이 보여야 한다(파선 대 점선 등, 색이 아니라 선 모양으로).

- [ ] **Step 4: 확인**

교전장에서 자산을 놓고 클릭 → 후보 선이 뜬다 → 하나를 눌러 연결 → 선이 실선이 되고 후보 목록이 갱신된다. 되돌리기로 돌아온다. 관측 모드에서는 오버레이가 없다. 390px 에서도 동작한다(마커 겹침은 M2 의 목록 선택으로 이미 처리됨).

- [ ] **Step 5: 커밋** `ui: 자산을 고르면 이을 수 있는 곳이 보인다 - 규칙표 후보를 유령 선으로`

문서·시나리오·리플레이로 복사돼 퍼진 것이었다. `geo.source` 를 16 자산 전부

출력을 고치려고 입력을 바꾸는 것은 이 태스크가 없애려던 바로 그 동작이다.
