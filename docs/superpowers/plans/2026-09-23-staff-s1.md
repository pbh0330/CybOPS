# 참모 S1 - 사실 계층과 질의 카탈로그 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 모델이 없어도 동작하는 참모. 엔진이 사실을 만들고, 닫힌 질의 카탈로그가 그 사실을 뽑고, 화면이 그것을 읽어 준다. S1 에는 LLM 호출이 한 줄도 없다 — 문장은 S2 가 붙인다.

**Architecture:** 세 층. `facts.js`(순수, 엔진 산출 → `Fact[]`), `staff.js`(순수, 읽기 전용 질의 카탈로그 + 인자 검증 + 엔진 호출), `StaffDock.jsx`(UI). 의존 방향은 한쪽이다 — `staff.js` 는 `engine.js`/`game.js`/`sandbox.js` 를 읽고, UI 는 엔진을 직접 부르지 않는다.

**Tech Stack:** React 18, Vite 5, vitest 3. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-09-23-staff-officer-design.md` (S1 은 13절의 첫 항목)

## Global Constraints

- **LLM 을 부르지 않는다.** `staff-llm.mjs` 도, `probeLlm` 도 이 계획에서 건드리지 않는다. S1 의 성공 조건은 "모델 없이 온전히 동작"이다.
- **엔진이 상태를 만든다**(ADR-0003). 질의는 전부 읽기 전용이고, 사실의 숫자는 전부 엔진 산출에서 온다. 질의가 자기 식으로 저하도를 계산하지 않는다.
- **실행 경로 없음**(ADR-0004). `actions` 는 S1 에서 항상 빈 배열이다 — 교전 연동은 S3 다.
- 크롬 무채색, 빨강(`#ff4d5e`)은 공격 전용(ADR-0024/0025).
- 엔진(`ui/src/engine.js`, `attack.js`, `game.js`)을 **수정하지 않는다.** 부르기만 한다. `node ui/tools/parity.mjs` 는 1622 값 0 불일치를 유지한다.
- `npm test` 는 현재 **95개**이고 줄어들면 안 된다.
- 데스크톱(> 860px) 기존 레이아웃은 참모 드로어가 새로 생기는 것 외에 바뀌지 않는다. 컴팩트 규칙은 `[data-compact="1"]` / `@media (max-width: 860px)` 안에만 쓴다.
- 커밋 트레일러 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.
- 브라우저 확인은 **동일 출처 iframe** 으로 한다 — `browser_resize` 가 이 환경에서 페이지에 안 먹는다(네 에이전트가 확인). `http://localhost:5180` 의 부모 문서를 비우고 `<iframe src="/">` 를 띄워 `contentWindow`/`contentDocument` 로 잰다.

### Task 1: `facts.js` - 사실 모델과 빌더

**Files:**
- Create: `ui/src/facts.js`, `ui/src/__tests__/facts.test.js`

**Interfaces (뒤 태스크가 쓴다):**

```js
Fact = { id: 'F3', text: '...', ref: { kind, id } | null, value: number|null, unit: '%'|'%p'|null }

export function numbered(list)                 // {text,ref,value,unit}[] -> Fact[] (F1..Fn)
export function missionFacts(g, s)             // 임무별 저하도 + 원인 분해
export function assetFacts(g, s, id)           // 한 자산: 침해, 역할, 연결 수, 단일점 여부
export function serviceFacts(g, s)             // 서비스 저하와 제공자
export function containmentFacts(rows)         // {id,cost,blocks,gainBlocked,net,rank}[] -> 사실
export function gameFacts(g, G)                // 턴/모드/점수/거점/격리
export function readinessFacts(g, r)           // 교전장 준비도
```

`ref.kind` 는 `'asset'|'mission'|'task'|'service'|'link'|'turn'` 중 하나다. `ref` 가 있으면 S2 의 인용 칩이 그 노드를 강조한다 — **지금 달아 두지 않으면 나중에 전부 다시 만져야 한다.**

```js
import { describe, it, expect } from 'vitest'
import replay from '../../public/data/tacnet-01.replay.json'
import { computeStep } from '../derive.js'
import { numbered, missionFacts, assetFacts } from '../facts.js'

const g = replay.graph
const s = computeStep(g, replay, 12)   // 기존 시그니처를 확인하고 맞출 것

describe('numbered', () => {
  it('renumbers from F1 and keeps order', () => {
    const out = numbered([{ text: 'a' }, { text: 'b' }, { text: 'c' }])
    expect(out.map((f) => f.id)).toEqual(['F1', 'F2', 'F3'])
    expect(out[1].text).toBe('b')
  })
  it('fills the optional fields so consumers never read undefined', () => {
    const [f] = numbered([{ text: 'a' }])
    expect(f.ref).toBeNull(); expect(f.value).toBeNull(); expect(f.unit).toBeNull()
  })
})

describe('missionFacts', () => {
  it('says the same number the mission panel says', () => {
    const facts = missionFacts(g, s)
    const p1 = g.missions.find((m) => Number(m.priority) === 1)
    const f = facts.find((x) => x.ref && x.ref.id === p1.id)
    expect(f).toBeTruthy()
    expect(f.value).toBeCloseTo(s.mission[p1.id], 6)   // 실제 step 모양을 확인하고 맞출 것
    expect(f.unit).toBe('%')
  })
  it('is deterministic', () => {
    expect(missionFacts(g, s)).toEqual(missionFacts(g, s))
  })
})

describe('assetFacts', () => {
  it('carries an asset ref and mentions the id', () => {
    const facts = assetFacts(g, s, 'BN-SRV')
    expect(facts.length).toBeGreaterThan(0)
    expect(facts.every((f) => !f.ref || f.ref.kind === 'asset')).toBe(true)
    expect(facts.some((f) => f.text.includes('BN-SRV'))).toBe(true)
  })
  it('returns an empty list for an unknown id rather than throwing', () => {
    expect(assetFacts(g, s, 'NOPE')).toEqual([])
  })
})
```

**먼저 `ui/src/derive.js` 의 `computeStep` 시그니처와 반환 모양을 읽고** 위 테스트를 그 모양에 맞춘다. 추측해서 쓰지 말 것 — 틀린 필드명으로 통과하는 테스트는 아무것도 지키지 않는다.

규칙 셋만 지키면 나머지는 재량이다:
1. **숫자는 엔진에서 온다.** `value` 에는 원값(0~1)을 담고, `text` 에는 사람이 읽는 표기(`%`)를 담는다. 표기는 `derive.js` 의 `pct` 를 쓴다 — 반올림 방식이 화면과 달라지면 안 된다.
2. **`text` 는 한국어 한 문장**이고 자산·임무는 `이름(ID)` 형태로 적는다(`staff-llm.mjs` 의 기존 `staffFacts` 가 쓰던 방식과 같다 — 그 파일을 읽고 표기를 맞춘다).
3. 입력이 같으면 출력이 같다. `Object.keys` 순회는 정렬한다.

`missionFacts` 는 임무마다 저하도와 원인 분해(침해/환경/상호작용)를 낸다 — `derive.js` 의 `splitBar` 가 이미 그 분해를 한다. 복제하지 말고 부른다.

### Task 2: `staff.js` - 질의 카탈로그, 검증, 실행

**Files:**
- Create: `ui/src/staff.js`, `ui/src/__tests__/staff.test.js`

**Interfaces:**

```js
export const QUERIES = [{ id, label, args, needs, run }]
export function catalog(ctx)                  // 지금 쓸 수 있는 질의만
export function validate(ctx, queryId, args)  // {ok:true, args} | {ok:false, reason}
export function ask(ctx, queryId, args)       // Answer

ctx = { graph, step, game, sandbox }
Answer = { query, args, label, facts, table|null, series|null, actions: [], note|null }
```

S1 의 질의 **6종**(나머지 4종은 S3):

| id | 인자 | 하는 일 | 무엇을 부르나 |
|---|---|---|---|
| `state_summary` | - | 현 시각 요약: 임무 상위, 진행 중 사건 | `step` 과 `missionFacts` |
| `mission_why` | `missionId` | 이 임무가 왜 저하됐나 | `runChain` + `derive.cutRows` |
| `asset_impact` | `assetId` | 이 자산이 죽으면 어느 임무가 무너지나 | `runChain` what-if |
| `containment_top` | `k=5` | 격리 후보 순위 | 아래 규칙 |
| `compare_defense` | `aId`, `bId` | 두 격리안 비교 | `containment_top` 의 비용 계산 2회 |
| `readiness_gap` | - | 교전장 구성이 왜 안 찼나 | `sandbox.readiness` |

`needs`: `'graph'`(항상) / `'game'`(교전 중에만) / `'sandbox'`(교전장에서만). `catalog(ctx)` 는 쓸 수 있는 것만 돌려준다 — 교전이 없으면 목록에 없고, 따라서 S2 에서 모델이 고를 수도 없다.

**`containment_top` 의 비용은 한 정의만 쓴다.** 교전 중(`ctx.game` 있음)이면 `game.staffTable(g, G)` 를 **그대로** 부른다. 관측 모드이면 같은 모양을 만들되 비용은 `game.js` 의 `isolationCost` 와 같은 식이어야 한다:

```
cost(id) = weighted(runChain(g, { ...compromise, [id]: 1 }, {t}).mission)
         - weighted(runChain(g, compromise,            {t}).mission)
weighted(missions) = Σ missions[m.id] / max(1, m.priority)
```

`weightedOf` 는 `game.js` 가 이미 export 한다 — **복제하지 말고 import 한다.** 관측 모드에는 공격자가 없으므로 `blocks`/`gainBlocked` 는 계산하지 않고 `null` 로 두고, 정렬은 `cost` 오름차순(싼 것이 위)으로 한다. 표의 열 이름이 두 경우에 달라진다는 것을 `Answer.note` 에 적는다.

- [ ] **Step 1: 실패하는 테스트를 먼저 쓴다** (최소 10개)

- `catalog` 가 교전 없이 `needs:'game'` 질의를 내놓지 않는다
- `catalog` 가 교전장이 아닐 때 `readiness_gap` 을 내놓지 않는다
- `validate` 가 없는 질의 id 를 거부한다
- `validate` 가 그래프에 없는 `missionId`/`assetId` 를 거부한다(이유 문자열 포함)
- `validate` 가 `k` 의 형 오류(문자열, 음수)를 거부하거나 기본값으로 보정한다 — **어느 쪽인지 정하고 테스트로 못 박는다**
- `ask('mission_why')` 의 사실 중 임무 저하도 값이 `runChain` 을 직접 부른 값과 같다
- `ask('asset_impact')` 가 what-if 로 낸 숫자가 직접 부른 값과 같다
- `ask('containment_top')` 가 교전 중이면 `staffTable` 의 상위 k 와 같은 id 순서를 낸다
- `ask('containment_top')` 가 관측 모드에서 비용 오름차순이고, 값이 위 식과 일치한다
- `ask` 가 같은 입력에 같은 출력을 낸다(결정론)
- 모든 `Answer.actions` 가 빈 배열이다(ADR-0004, S1)
