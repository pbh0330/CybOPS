# AI 기반 SOC 센터 설계 - 실시간 경보 분류 콘솔

**작성** 2026-11-10 · **상태** 설계 승인 대기

## 1. 무엇을 만드는가

상황도(COP)와 나란히 서는 **두 번째 최상위 화면**을 만든다. 상황도는 되감아 보는
분석 화면이고, SOC 센터는 시계가 흘러가는 관제 화면이다. 상단 좌측 토글이 둘을 오간다.

그리고 교전장(sandbox)을 걷어낸다.

### 의도 (사용자가 말한 것)

> 지금 시나리오는 어차피 가정이니까 데모 버전에서는 나중에 분석용으로 사용하고
> AI 기반 SOC 센터는 이 화면이다 이런 식으로 보여주면 좋을 것 같아서.
> AI SOC는 실시간으로 하면 좋을 듯

두 화면의 역할 분담이 여기서 나온다. 심사·시연에서 먼저 보여줄 것은 SOC 센터이고,
상황도는 "그래서 왜 그런가" 를 파고들 때 들어가는 곳이다.

### 성공 기준

1. 화면을 열면 경보가 **스스로 쌓인다.** 아무것도 누르지 않아도 시계가 간다.
2. 발표자가 임의의 순간에 멈추고 한 건을 열어 **왜 중요한지**를 근거와 함께 보일 수 있다.
3. **모델이 없어도** 큐·영향·격리후보·분류·감사로그가 전부 돈다. 빠지는 것은 AI 소견 문장뿐이다.
4. 같은 시연을 두 번 돌리면 **같은 순서로 같은 줄**이 나온다.
5. 화면의 어떤 버튼도 차단·격리를 **실행하지 않는다.**

SPiDER TM 상관분석, 사이버 위협 현황), 롯데정보통신 관제 화면 하나, 그리고

## 4. 경보 모델 - `ui/src/alerts.js`

### 4.1 실측 경보는 리플레이 step 에서 나온다

`tacnet-01.replay.json` 의 step 28개는 이미 경보가 필요로 하는 것을 전부 들고 있다.
**새 데이터 파일을 만들지 않는다.** 경보는 리플레이를 다르게 읽는 방식이지 새 진실이 아니다.

| 경보 필드 | 출처 | 예 |
|---|---|---|
| `t` | `step.t` | `150` |
| `at` | `step.time_iso` | `2026-09-10T08:30:00+09:00` |
| `title` | `step.label` | `노획 단말 비인가 접속` |
| `detail` | `step.note` | `2중대 지휘차 단말에서 비인가 계정 사용` |
| `technique` / `tactic` | `step.gt[0]` | `T1078` / `initial-access` |
| `assets` | `Object.keys(step.compromise)` | `["CO2-VEH"]` |
| `severity` | **파생.** 아래 4.2 | `P2` |
| `origin` | `measured` | |

`step.compromise` 가 빈 step 은 경보를 만들지 않는다. 아무 자산도 새로 침해되지 않은
시점은 사건이 아니다.

### 4.2 심각도는 사람이 매기지 않는다

심각도는 **그 step 이 임무에 입힌 저하 증분**에서 파생한다. 자산의 중요도를 손으로
적어 두고 그것을 읽는 방식이 아니다. 손으로 적은 등급은 엔진이 이미 계산하는 것과
어긋날 수 있고, 어긋나면 어느 쪽이 맞는지 아무도 모른다.

```
d = max over missions( mission[m] at this step  -  mission[m] at previous step )

d >= 0.25            -> P1
0.10 <= d < 0.25     -> P2
0.02 <= d < 0.10     -> P3
d < 0.02             -> P4
```

임계값 넷은 **이 스펙이 정하는 유일한 임의 상수**다. 근거는 tacnet-01 의 실제 증분
분포이고, 구현 시 실제 값을 재어 표를 ADR 에 적는다. 분포를 재서 넣는 것과 지어내는
것의 차이가 이 프로젝트의 ADR-0008 정신이다.

우선순위 가중(`mission.priority`)은 **쓰지 않는다.** P1 임무의 2% 저하와 P3 임무의
25% 저하 중 무엇이 급한지는 이 화면이 답할 질문이 아니고, 섞으면 숫자의 출처가 흐려진다.
임무별 우선순위는 상세 패널에 **따로** 보인다.

### 4.3 합성 잡음

28건이 전부 참이면 분류할 것이 없다. 관제의 본질은 신호와 잡음을 가르는 일이다.

**생성 규칙.** 시나리오 id 로 시드를 고정한 PRNG(xorshift32, `ui/src/rng.js` 신규)가
정상 트래픽 패턴에서 경보를 만든다. 실측 step 사이의 빈 구간에 떨어지고, 비율은
**실측 1건당 합성 2건**(구현 시 화면을 보고 조정 가능, 기본 2).

합성 경보는 **엔진을 거치지 않는다.** 침해가 아니므로 `compromise` 가 없고, 따라서
임무 영향도 격리 후보도 없다. 상세 패널은 그 자리에 "임무 영향 없음 · 합성 배경" 이라 쓴다.

**표기 의무.** `docs/07-synthetic-data.md` 6절이 합성 데이터로 탐지 성능을 주장하는 것을
금지한다. 그래서:

1. 행마다 `실측` / `합성` 배지가 붙는다. 끌 수 없다.
2. 모든 집계 위젯은 **실측과 합성을 따로 센다.** 한 숫자로 합치는 경로를 만들지 않는다.
3. 화면 하단에 상시 고지: `합성 경보는 배경이고 탐지 성능의 근거가 아니다`

세 번째는 ADR-0025 의 워터마크와 같은 성질의 문장이다. 끌 수 없다.

### 4.4 실측 구간이 끝난 뒤

시나리오 시각 405초를 지나면 실측 경보가 더 없다. 시계는 계속 가고 합성 잡음만 남는다.
화면은 `실측 구간 종료 (t=405) · 이후는 합성 배경` 이라고 **직접 말한다.** 데이터가
떨어진 것을 숨기지 않는다.

## 5. 시계 - `ui/src/clock.js`

### 5.1 압축 재생

시나리오 시각이 벽시계로 흐른다. 기본 **1초 = 시나리오 15초**, 405초가 27초에 지난다.
배속은 x1 / x15 / x60 셋.

**재생/정지가 있어야 하는 이유는 하나다.** 심사장에서 발표자가 "여기를 보십시오" 하고
멈출 수 있어야 한다. 흐르기만 하는 화면은 시연이 안 된다.

### 5.2 결정론

`clock.js` 는 `performance.now()` 를 읽지 않는다. **누적 틱**을 들고 있고, 바깥에서
경과 ms 를 받아 전진한다.

```js
// 순수. 같은 입력에 같은 출력.
export function advance(clock, elapsedMs) { ... }   // -> { t, crossed: [...] }
```

React 쪽의 `requestAnimationFrame` 루프가 `advance` 를 호출하는 유일한 지점이고,
테스트는 그 루프 없이 `advance` 를 직접 돌린다. 시간에 의존하는 테스트를 쓰지 않는다.

`crossed` 는 이번 전진에서 **넘어간 경보**들이다. 배속을 올려도 건너뛰지 않는다.
x60 으로 한 틱에 시나리오 1분이 지나면 그 사이 경보가 전부 `crossed` 에 담겨 나온다.

## 6. 분류와 감사 로그 - `ui/src/triage.js`

### 6.1 상태 기계

```
                  +------------------------------+
                  v                              |
미접수 --접수--> 접수 --이관건의--> 이관 --종결--> 종결
   |                |                              ^
   +----오탐 종결----+------------------------------+
```

참고 화면의 `종결요청` 은 뺀다. 승인자가 한 명인 데모에서 요청과 종결 사이에 아무도 없다.

### 6.2 이관은 실행이 아니라 건의다

**ADR-0004 는 차단·격리 실행에 사람 승인을 요구하고 자동 실행 경로를 코드에 넣는 것을
금지한다.** 그래서 이 화면의 어떤 버튼도 격리를 실행하지 않는다.

`이관 건의` 는 "이 자산의 격리를 건의한다" 를 감사 로그에 적을 뿐이다. 버튼 라벨이
`격리` 가 아니라 `이관 건의` 인 것이 이 설계의 일부이고, 상세 패널이 한 줄로 명시한다:

> 이 화면은 조치를 실행하지 않는다. 건의는 기록이고, 실행은 사람이 다른 경로로 한다.

**시험으로 고정한다.** 격리·차단을 실행하는 코드 경로가 SOC 모듈 아래에 존재하지 않는다는
것을 테스트가 검사한다(11절).

### 6.3 감사 로그는 추가 전용

enigmart 의 변경 불가능한 감사 추적 원칙을 가져온다. 모든 상태 전이가 한 줄씩 쌓인다.

```js
{ seq, at, alertId, from, to, note }
```

- **추가만 된다.** 수정도 삭제도 하는 함수가 없다. `triage.js` 는 `append` 만 내보낸다
- `seq` 는 단조 증가한다
- JSON 으로 내보낼 수 있다. ADR-0029 4항이 승인 기록을 브라우저 저장소에 두고 JSON 으로
  내보내게 하고 있고, 같은 자리를 쓴다
- 비우는 것은 사람이 명시적으로 하는 한 가지 동작뿐이고 확인을 받는다 (ADR-0010 의 정신)

### 6.4 상태는 어디에 사는가

메모리 + `localStorage`. **서버측 상태 없음**(ADR-0029 4항). 심사위원 둘이 같은 판을
보려면 JSON 을 주고받는다. 그 대가는 ADR-0029 가 이미 받아들였다.

### 7.1 위기단계

정상 / 관심 / 주의 / 경계 / 심각 다섯 단계. **최고 우선순위 임무의 현재 저하도**에서
환산한다. 새 상태가 아니고 엔진 값의 다른 표현이다. 경계선은 4.2 와 같은 방식으로
실측 분포를 재서 ADR 에 적는다.

색은 무채색 채움 비율로 보인다. **단계별 색 코딩을 하지 않는다.** ADR-0024 에서
빨강은 적대 행위 효과 전용이고, 위기단계는 효과가 아니라 요약이다.

### 7.2 작은 그래프

선택한 경보의 자산을 중심으로 **2단계 이웃만** 잘라낸 의존 그래프. 전체 상황도가 아니라
"이 경보가 어디에 앉았나" 를 보이는 정도다. ADR-0001 의 "좌표계는 그래프" 를 SOC 에서도
유지한다. 클릭하면 상황도로 전환하면서 그 자산을 선택한 상태로 연다.

### 7.3 모바일

ADR-0030 의 compact 규약을 따른다. 큐와 상세가 세로로 쌓이고, 상세는 바텀시트로 올라온다.
하단 고지 문장은 U15 가 만든 `--sheet-h` 단일 출처를 그대로 쓴다.

## 8. LLM - Claude API

### 8.1 ADR-0007 이 이미 허용하고 있다

ADR-0007 본문:

> 개발 중 편의를 위해 API 모델을 써도 되지만, **평가(트랙 C)는 반드시 온프렘 후보 모델을
> 포함**한다. (...) **온프렘 전용, API 완전 배제**: 기각. 과함. 개발 중 API 사용은
> 어댑터 뒤에 있는 한 문제없다.

그래서 **ADR-0007 은 개정하지 않는다.** 다음 셋을 지키는 한 이것은 그 ADR 의 적용이다.

1. 어댑터 뒤에 있을 것
2. 공통 분모만 쓸 것 (메시지, 시스템 프롬프트, 스트리밍, 구조화 출력)
3. 평가에 온프렘 후보를 포함할 것

### 8.2 어댑터

`staff-llm.mjs` 가 지금 Ollama `/api/chat` 을 직접 부른다. 이것을 `provider` 로 가른다.

```
ui/src/llm/index.mjs       어댑터 선택
ui/src/llm/ollama.mjs      현행 코드를 옮긴 것
ui/src/llm/anthropic.mjs   신규. 동일 출처 프록시로만 간다
```

**공통 인터페이스.** 상위 코드(`staff-llm.mjs` 의 `routeQuestion` / `narrate`)는 이것만 안다.

```js
chat({ system, messages, schema, effort }) // -> { text, obj, ms }
```

`schema` 가 있으면 구조화 출력, 없으면 자유 텍스트. 두 provider 가 각자의 와이어 형식
(Ollama 는 `format`, Anthropic 은 `output_config.format`)으로 번역한다. **상위 코드는
어느 쪽인지 모른다.**

### 8.3 구조화 출력이 ADR-0028 과 정확히 맞는다

ADR-0028 2항: "모델은 그 안에서 id 를 고를 뿐이다."

라우팅 단계를 구조화 출력으로 묶으면 그 문장이 와이어 수준에서 강제된다.

```json
{ "type": "object",
  "properties": {
    "query_id": { "enum": ["state_summary", "mission_why", "asset_impact"] },
    "args": { "type": "object" } },
  "required": ["query_id"], "additionalProperties": false }
```

`enum` 은 `catalog(ctx)` 가 **지금** 내주는 것만 담는다. 교전 중이 아니면 교전 질의는
enum 에 없고, 따라서 모델이 고를 수 없다.

**그래도 `staff.validate` 는 그대로 돈다.** 구조화 출력은 스키마를 보장하지, `assetId` 가
이 그래프에 실제로 있는 자산인지는 모른다. ADR-0028 3항이 요구하는 검증은 없어지지 않는다.

### 8.4 키는 브라우저에 들어가지 않는다

**이것이 이 절에서 가장 중요한 결정이다.**

`config.js:26` 이 이미 세 자세 중 `proxied` 를 적어 두고 있다. `/api/llm`, 동일 출처.
Claude 어댑터는 **오직 그 경로로만** 간다. `api.anthropic.com` 을 브라우저에서 직접
부르는 코드를 쓰지 않는다. 키가 번들에도, `localStorage` 에도, URL 에도 들어가지 않는다.

| 환경 | `/api/llm` 뒤 | 키 보관 |
|---|---|---|
| 로컬 개발 | Ollama (현행 기본) 또는 로컬 프록시 프로세스 | 프록시의 환경변수 |
| AWS 시연 | **Lambda Function URL** | Lambda 환경변수 / Secrets Manager |

**키를 대화창에 붙여넣지 않는다.** 설정은 사용자가 AWS 콘솔이나 CLI 에서 직접 한다.

### 8.5 그리고 이것이 ADR-0029 를 더 단순하게 만든다

ADR-0029 3항은 "모델은 시연 시간에만 켜는 GPU 인스턴스" 다. 5항은 도메인이 없어
모델 오리진 구간이 **평문 http** 라는 문제를 CloudFront 함수로 막고 있다.

Lambda Function URL 로 바꾸면:

- GPU 인스턴스가 필요 없다. 켜고 끄는 운영이 사라지고 유휴 요금이 0 이 된다
- Function URL 은 https 다. **5항이 애써 막고 있는 평문 구간이 아예 없어진다**
- 상태가 없다. 4항 유지
- "꺼진 상태가 기본" 도 유지된다. 키가 없으면 프록시가 503 을 주고 화면은 지금처럼
  `unavailable_note` 를 띄운다. **ADR-0029 3항의 핵심 주장, 즉 모델 없는 사본이 온전히
  동작한다는 것은 그대로다**

그러므로 **ADR-0029 3·5항 개정**이 필요하다. 자세를 약화하는 개정이 아니라 강화하는
개정이고, 개정안에 그렇게 적는다.

### 8.6 모델과 파라미터

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | `claude-opus-5-5` | 현행 기본. **`config.json` 이 덮어쓴다. 코드에 하드코딩하지 않는다**(ADR-0007) |
| thinking | 파라미터 생략 | Claude Opus 5.5 는 thinking 을 끌 수 없다. `disabled` 와 `budget_tokens` 둘 다 400 |
| effort | `low` | 라우팅은 분류, 서술은 주어진 사실 2~3문장 재진술. 둘 다 단순 작업이다. Opus 5.5 의 기본은 `medium` 이므로 **명시한다** |
| max_tokens | 1024 | 소견은 짧다. 길면 화면에 안 들어간다 |
| 스트리밍 | 쓰지 않는다 | 응답이 짧아 이득이 없고, 어댑터 인터페이스가 단순해진다 |

### 8.7 평가에 온프렘 후보를 포함한다 (ADR-0007 의 조건)

`ui/tools/staff-eval.mjs` 가 `--provider` 를 받는다. 골든셋 41항목을 Ollama 와 Anthropic
양쪽에서 돌리고 결과를 `eval/results/` 에 각각 남긴다. **한쪽만 돌린 결과를 "평가했다"
라고 적지 않는다.**

## 9. sandbox 제거

### 9.1 지우는 것

| 대상 | 비고 |

### 9.2 살리는 것. 이것을 놓치면 안 된다

`sandbox.js` 의 **`linkCandidates` 와 `linkFitsRules` 는 교전장 전용이 아니다.**
편집 모드 전체에서 돌고, 사용자가 명시적으로 요청한 **추천연결 오버레이**를 구동한다.
`App.jsx:262-267` 이 `mode === 'edit'` 조건으로 부른다.

두 함수를 **`ui/src/links.js` 로 옮긴다.** 파일 이름만 sandbox 였을 뿐이다.

두 함수를 **쪼개지 않는다.** `sandbox.js:115` 위의 주석이 그 이유를 적고 있다.
인스펙터의 `규칙 밖` 표시와 오버레이의 점선 유령 선이 같은 술어 하나를 쓰기 때문에
플래그와 선이 어긋날 수 없다는 성질이다. 옮기되 붙여서 옮긴다.

### 9.3 교전은 남는다

`Wargame.jsx:373` 을 확인했다. 준비도 게이트는 `sandbox && graph` 일 때만 걸리고
저작 시나리오는 언제나 `ready: true` 로 지나간다. 교전장이 빠져도 교전 모드는
tacnet-01 에서 그대로 돈다. **모드 세그먼트는 관측/편집/교전 셋 그대로다.**
