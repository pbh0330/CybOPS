# 모바일 컴팩트 모드 (설계)

작성 2026-09-23. 승인됨(대화). 구현 계획은 별도 문서(M1/M2/M3).

## 0. 왜

시연 사본이 공개 주소로 떠 있다(`docs/24-aws-demo.md`). 심사위원이 폰으로 열 수 있다.
390×844 에서 실제로 찍어 보면:

- `.main` 이 `grid-template-columns: 1fr 380px` 이라 **레일이 화면을 거의 다 먹고 그래프
  캔버스가 왼쪽 80px 남짓 조각**으로 찌그러진다. 범례와 축 라벨이 빈 공간에 떠 있다.
- 상단 브랜드가 두 줄로 접히고 KPI 띠가 오른쪽에서 잘린다.
- 미디어 쿼리는 **`@media (max-width: 1400px)` 하나**뿐이고, 그것도 상단바만 손본다.

반면 **레일 내용물은 좁은 폭에서 이미 잘 읽힌다.** 임무 저하도 카드, 대응 탭, 브리핑,
이벤트 스트림이 세로로 쌓여 정상으로 보인다. 그러므로 이 작업은 내용을 다시 만드는 일이
아니라 **껍데기를 바꿔 끼우는 일**이다.

## 1. 범위와 불변 조건

**유지**
- 데스크톱 레이아웃은 그대로다. 컴팩트 모드는 좁은 화면에서만 켜진다.
- 상태 산출은 엔진이 한다(ADR-0003). 이 작업에 엔진 변경은 없다.
- 빨강=공격, 크롬 무채색(ADR-0024/0025). 워터마크는 끌 수 없다(ADR-0025).
- 번들은 하나다(ADR-0018). 모바일 전용 번들·라우트를 만들지 않는다.
- 새 UI 라이브러리를 도입하지 않는다.

**바꿈**
- 브레이크포인트 `≤ 860px` 에서 **컴팩트 모드**: 단일 컬럼 무대 + 하단 시트.
- 레일(`<aside class="rail">`)의 내용이 컴팩트에서는 시트 안에 들어간다.
- 폰 기본 뷰가 **지도**다(7절, ADR-0001 의 모바일 한정 예외).
- 터치에 없는 입력(Delete 키, 호버)에 대응물을 만든다(5절).

**신설 ADR-0030** - 모바일 컴팩트 모드: 브레이크포인트, 지도 기본, 하단 시트, 터치 타깃,
데스크톱 불변.

## 2. 브레이크포인트와 모드

```
data-compact="1"  <=  matchMedia('(max-width: 860px)')
```

- 860px 은 폰 가로·태블릿 세로를 포함한다. 그 위는 지금 레이아웃 그대로다.
- `ui/src/useCompact.js` - `matchMedia` 를 구독하는 훅 하나. `<div className="app">` 에
  `data-compact` 속성을 달고, CSS 는 `[data-compact="1"] ...` 로 건다. 미디어 쿼리만으로는
  못 하는 것(기본 뷰 전환, 시트 상태)이 있어 JS 쪽 신호가 필요하다.
- 추가 조정용으로 `≤ 560px` 에서 몇 가지를 더 줄인다(6절). 이것은 순수 CSS 다.

## 3. 컴팩트 레이아웃

```
┌──────────────────────┐
│ MC-CyCOP  [시나리오] ⋯│  상단바 56px
├──────────────────────┤
│ KPI ▸ 가로 스크롤     │  44px, 스냅
├──────────────────────┤
│                      │
│   무대 (지도 | 그래프) │  남는 높이 전부
│                 [전환]│
├──────────────────────┤
│ ◀ ▶ 06:00            │  타임라인 48px
├──────────────────────┤
│ ═══ 지휘통제 P1 0.0% │  시트 엿보기 56px
└──────────────────────┘
```

- `.main` 은 컴팩트에서 `grid-template-columns: 1fr` 이 되고, 레일은 `display: none` 이
  아니라 **시트로 옮겨진다**(같은 React 노드를 다른 컨테이너에 렌더한다 - 내용이 두 벌
  존재하면 안 된다).
- `.main.is-editing` 의 팔레트 컬럼(210px)도 컴팩트에서는 열이 아니라 무대 위 **가로
  스크롤 바**가 된다.
- 높이는 `100dvh`(폴백 `100vh`). 모바일 주소창이 `100vh` 를 잘라먹는다.
- iOS 노치: 시트와 타임라인에 `env(safe-area-inset-bottom)`, 상단바에
  `env(safe-area-inset-top)`.

## 4. 하단 시트

`ui/src/ui/Sheet.jsx` - 컴팩트에서만 렌더된다.

- **스냅 3단**: `peek`(56px, 한 줄 요약) / `half`(50dvh) / `full`(상단바 아래 전부).
- 손잡이를 끌면 따라오고, 놓으면 가장 가까운 스냅으로 간다. 손잡이를 탭하면 다음 단으로.
- **자동 상승**: 자산을 탭해 선택이 생기면 `peek` 이었을 때만 `half` 로 올린다. 이미
  사용자가 올려 둔 높이를 낮추지 않는다.
- `peek` 줄에 보이는 것: 우선순위 최상위 임무와 그 저하도(`지휘통제 P1 0.0%`). 교전 중이면
  `턴 3/8 · 점수 214`.
- 시트가 `full` 일 때도 무대는 살아 있다(시트가 덮을 뿐 언마운트되지 않는다). 지도의
  카메라 상태가 보존돼야 한다.
- 스냅 계산은 순수 함수 `snapTo(y, points)` 로 분리한다 - **유닛 테스트 대상은 이것뿐이다.**
- 스크롤 잠금: 시트 내부가 스크롤될 때 뒤 페이지가 같이 밀리지 않게 `overscroll-behavior:
  contain`.

## 5. 터치 동등성

"전부 동작"이 요구하는 실제 항목이다. 지금 화면에는 터치에 없는 입력이 있다.

| 지금 | 컴팩트에서 |
|---|---|
| `Delete` 키로 자산 삭제 | 인스펙터에 **삭제 버튼**. 폰에는 Delete 키가 없다 |
| 마우스 호버 툴팁 | 탭으로 같은 정보를 띄운다(인용 칩·범례·KPI) |
| 지도 마커 드래그 | 터치 드래그. 지금 탭 오인 가드는 `click` 기준이라 `touchend` 경로를 확인해야 한다 |
| 24~28px 버튼 | **최소 44×44** (컴팩트 한정 오버라이드) |
| `100vh` | `100dvh` |
| 그래프 편집 | 이미 탭 기반(A 탭 → B 탭)이라 그대로 쓴다 |

삭제 버튼은 컴팩트에서만 보이는 것이 아니라 **항상 보인다** - 키보드가 있는 환경에서도
버튼이 있는 편이 낫고, 두 경로가 갈리면 테스트가 두 벌이 된다.

## 6. 상단바·타임라인 축소

**상단바**(컴팩트 56px)
- 브랜드는 `MC-CyCOP` 한 줄. 부제는 이미 1400px 에서 숨는다.
- 남기는 것: 브랜드, 시나리오 셀렉트, `⋯` 메뉴.
- `⋯` 로 들어가는 것: 뷰 전환(그래프/지리), 모드(관측/편집/교전), 라벨 토글, 배속,
  교전장 도구(구성 저장·불러오기·가져오기).
- KPI 띠는 상단바 아래 **가로 스크롤 줄**로 내려간다(`scroll-snap-type: x mandatory`).
  잘리는 것보다 넘기는 것이 낫다.

**타임라인**(컴팩트 48px)
- 남기는 것: 이전/재생/다음, 시각, 잠금 배지.
- `≤ 560px` 에서 스파크라인을 숨긴다. 배속은 `⋯` 메뉴에 있다.

## 7. 폰 기본 뷰는 지도다 (ADR-0001 예외)

ADR-0001 은 좌표계가 임무-자산 그래프이고 지리는 기본 뷰가 아니라고 못 박았다. 컴팩트
모드는 **그 결정의 모바일 한정 예외**다. 근거:

- 390px 폭에서 dagre 그래프는 노드 라벨이 겹쳐 읽히지 않는다. 좌표계로서 기능하지 못한다.
- 지도는 같은 폭에서도 방향 감각을 준다.
- 뷰 전환 버튼이 무대 위에 항상 떠 있으므로 그래프는 한 번의 탭 거리에 있다.

**데스크톱 기본 뷰는 그대로 그래프다.** 그리고 `graph.geo.georef` 가 없는 시나리오
(`defnet-01`)에서는 컴팩트에서도 그래프가 기본이다 - 없는 뷰를 기본으로 둘 수 없다.
이 예외는 ADR-0030 에 적고 ADR-0001 에 상호 참조를 남긴다.

## 8. 하지 않는 것

모바일 전용 번들·라우트, 새 UI 라이브러리, 데스크톱 레이아웃 변경, 그래프 자동 레이아웃
알고리즘 교체, 오프라인(PWA) 지원, 제스처 라이브러리, 가로 모드 전용 레이아웃(가로는
860px 을 넘으면 데스크톱 레이아웃으로 자연히 돌아간다).

## 9. 검증

레이아웃은 vitest 로 못 잡는다. 그래서:

- **순수 함수만 유닛 테스트**: `snapTo`, `useCompact` 의 질의 문자열.
- **Playwright 스크린샷 3종**: 390×844(폰), 768×1024(태블릿), 1600×900(데스크톱 회귀).
  `docs/design/screens/2026-09-23-mobile-*.png`.
- 폰 크기에서 **실제로 해 보는 것**: 시나리오 전환, 시간 이동, 자산 탭 → 시트 상승,
  교전 한 턴, 교전장에서 자산 추가·연결·삭제.
- 기존 게이트는 그대로 통과해야 한다(vitest 75+, parity 0, `Invoke-Gates.ps1` 9/9).
