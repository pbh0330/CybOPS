# 25. 참모

**근거**: ADR-0028(LLM 의 역할은 참모다), ADR-0003(상태 산출은 엔진), ADR-0009(모든 문장은
인용), ADR-0004(실행 경로 없음).

이 문서는 **S1 과 S2** 를 서술한다. S1 에는 모델 호출이 한 줄도 없고(질의 버튼·사실·표),
S2 가 그 위에 자연어 라우팅·서술 문장·기권·골든셋을 얹었다. 교전 흡수는 S3 다. ADR-0028
안에 줄 단위 구현 현황표가 있다. **평가 수치의 현재 상태는 8절이다 - 아직 없다.**

## 1. 왜 만들었나

브리핑은 **사전 생성**이었다. `tacnet-01` 의 세 시각(t120/t300/t390)에 대해
`New-BriefingPack.ps1` 이 팩을 만들어 번들에 넣고, 화면은 그것을 읽었다. 그래서:

- 그 세 시각 밖에서는 브리핑이 없다.
- **편집된 그래프에는 아예 없다.** `Rail.jsx` 가 "편집된 그래프에는 해당 브리핑이 없다"를
  띄운다. 교전장(`sandbox-01`)은 정의상 전부 편집된 그래프이므로, 새로 만든 시나리오에
  LLM 이 닿지 않았다.

한편 사실을 만드는 구조는 이미 옳았다 - 규칙 엔진이 숫자를 내고 모델은 문장만 썼다. 그래서
바꾼 것은 **사실을 어디서 뽑느냐**다: 오프라인 팩 세 개가 아니라, 화면에 떠 있는 그래프에서
실시간으로.

## 2. 세 층

| 파일 | 성격 | 책임 |
|---|---|---|
| `ui/src/facts.js` | 순수 | 엔진 산출 → `Fact[]`. 번호(F1..Fn)와 참조를 붙인다 |
| `ui/src/staff.js` | 순수 | 질의 카탈로그, 인자 검증, 엔진 호출 → `Answer` |
| `ui/src/ui/StaffDock.jsx` | UI | 데스크톱 하단 드로어 / 폰 레일 탭 |

의존 방향은 한쪽이다. `staff.js` 는 `engine.js`·`game.js`·`sandbox.js` 를 읽고, UI 는
엔진을 직접 부르지 않는다. S2 의 `staff-llm.mjs` 는 카탈로그 **명세만** 받는다(구현을 모른다).

## 3. 질의 카탈로그 (읽기 전용, 닫힌 집합)

| id | 라벨 | 인자 | 조건 |
|---|---|---|---|
| `state_summary` | 현 상황 요약 | - | 항상 |
| `mission_why` | 이 임무가 왜 저하됐나 | `missionId` | 항상 |
| `asset_impact` | 이 자산이 죽으면 어느 임무가 무너지나 | `assetId` | 항상 |
| `containment_top` | 격리 후보 순위 | `k`(기본 5) | 항상 |
| `compare_defense` | 두 격리안 비교 | `aId`, `bId` | 항상 |
| `readiness_gap` | 교전장 구성이 왜 안 찼나 | - | 교전장에서만 |

`catalog(ctx)` 는 **지금 쓸 수 있는 것만** 돌려준다. `readiness_gap` 은 `tacnet-01` 에서
목록에 없다 - 없는 것은 사람도 모델도 고를 수 없다. S3 가 더할 네 종(`counterfactual`,
`autoplay`, `harden`, `trend`) 중 교전이 필요한 것들은 같은 방식으로 교전 중에만 나타난다.

**인자는 거부하지, 고쳐 주지 않는다.** 없는 `missionId`, `k='3'`, `k=0`, `k=2.5` 는 전부
이유와 함께 거부된다. 인자가 아예 없을 때만 기본값을 채운다. 이유는 S2 에 있다 - 읽을 수
있는 거부 사유는 모델에게 교정 신호이지만, 조용한 보정은 "틀린 인자가 맞았다"고 가르친다.

**비용 정의는 하나다.** 교전 중이면 `game.staffTable` 을 그대로 부른다. 관측 모드에는
공격자가 없으므로 같은 식을 `game.js` 의 `weightedOf` 를 **import 해서** 세운다 - 복제하지
않는다. 대신 관측 모드에서는 `막는 수`·`차단 이득`을 계산하지 않고(`null`) 비용 오름차순으로
세우며, 그 차이를 답변의 `note` 가 말한다.

## 4. 사실과 참조

```js
Fact = { id: 'F3', text: '...', ref: { kind, id } | null, value: 0.8, unit: '%' }
```

- `value` 는 엔진 원값(0~1), `text` 의 표기는 `derive.js` 의 `pct` 를 쓴다 - **화면과 반올림이
  달라지면 안 된다.**
- `ref.kind` 는 `asset|mission|task|service|link|turn`. 참조가 있는 사실은 **누를 수 있고**,
  누르면 그 노드가 선택된다. S2 의 인용 칩이 같은 경로를 쓴다 - 근거 체인은 별도 기능이
  아니라 인용 그 자체다.
- 입력이 같으면 출력이 같다. 객체 키 순회는 정렬한다.

## 5. 화면

**데스크톱**: 화면 하단 드로어. 접힘 한 줄, 펼침 40dvh.
**폰(≤ 860px)**: 레일의 `참모` 탭. 레일은 폰에서 하단 시트 안에 있으므로 결과적으로 시트
안에서 열린다.

드로어를 폰에서 또 고정 배치하지 않은 이유는 **하단을 이미 시트가 쓰고 있기 때문**이다. 둘을
같이 두면 서로 가린다. 그래서 컴포넌트는 하나만 만들고 부모만 바꾼다 - 모바일 M1 이
레일에 썼던 규칙과 같다. 두 벌로 렌더하면 질의 기록도 두 벌이 된다.

답변 한 건의 구성: 실행 배지(무엇이 어떤 시각 기준으로 돌았는지) → 사실 F1..Fn → 표 → note.

**S2 가 카탈로그 위에 질문 상자를 하나 얹었다.** 한 줄 입력과 `묻기` 뿐이고, 그 아래
질의 버튼은 그대로다. 결과는 **세 갈래로 갈라서** 보여 준다 - 셋 중 어느 것도 조용하지
않다.

| 결과 | 화면 |
|---|---|
| 답 | 버튼과 같은 카드로 기록에 쌓인다. 문장은 `[F#]` 칩을 달고, 칩을 누르면 그 사실로 간다. 인용 없는 문장에는 `미검증` 배지가 붙는다 |
| 기권 | 기록에 쌓이지 않는다. **계산된 것이 없으므로 남길 답이 없다.** 이유를 적고 질의 버튼을 가리킨다 |
| 실패 | 이름을 대고(전송·파싱·검증) 질의 버튼을 가리킨다 |

라우팅이 두 번 실패하면 `state_summary` 로 떨어지고, note 가 **떨어졌다는 사실과 이유를
같이** 적는다(`fallbackNote`). 서술만 실패한 경우에는 사실과 표를 그대로 두고 "서술
실패" 한 줄을 얹는다 - **숫자는 모델이 만든 것이 아니므로 문장이 없다고 버릴 이유가
없다.**

**답은 무엇을 기준으로 돌았는지 말한다.** 답변은 두 가지를 들고 있다 - 계산된 시나리오
시각(`staff.js` `ctxT`)과 그래프 지문(`staff.js` `graphFingerprint`). 둘 중 하나라도 화면의
현재 값과 다르면 그 카드는 낡은 것으로 표시되고, **무엇이 달라졌는지**까지 적는다:
"기준 시각이 다름", "기준 그래프가 다름", "기준 시각과 그래프가 모두 다름". 낡은 숫자에
확신에 찬 문장이 매달리는 것이 ADR-0009 가 막으려는 실패이고, 문장이 붙은 S2 부터는 더
그렇다. "이 답은 낡았다"만 있고 이유가 없으면 읽는 사람이 시계를 되돌려야 할지 질의를 다시
눌러야 할지 모른다.

**시각만으로는 부족하다.** 교전장에서는 시계를 그대로 둔 채 그래프를 고치는 것이 일상이고
(ADR-0027), 그때 숫자는 전부 움직이는데 `t` 는 가만히 있다. 실제로 TOC-SRV 의 링크를 전부
끊으면 `t=180` 에서 M-C2 가 32.1% → 89.3% 로 가는데, 시각만 보던 구현은 기록된 카드에
32.1% 를 표시 없이 계속 띄웠다. 지문은 **엔진이 실제로 읽는 구조**로만 만든다 - 자산 id
정렬, 링크 `a|b|bearer` 정렬, `provided_by`/`requires` 간선 쌍 정렬을 짧은 문자열 해시로
접는다. 개수는 세지 않는다(링크를 옮기면 개수는 그대로다). 이름·site·좌표는 들어가지
않는다 - 자산 이름을 바꿨다고 답이 틀린 것은 아니다.

동률은 동률로 보인다. 관측 모드에서는 비용 0 동률이 흔한데, 순위가 id 순으로 갈린다고 해서
"1위가 최선"으로 읽히면 안 된다. 같은 이유로 `compare_defense` 의 관측 모드 순위는 **임무
비용 오름차순**이다. 인자 순서로 매기면 `aId` 로 넣은 쪽이 비싸든 싸든 "순위 1" 이 되고,
인자를 바꿔 넣으면 순위가 뒤집힌다 - 타이핑 순서를 따라가는 것은 순위가 아니다.

## 6. 모델이 없을 때

**빠지는 것은 기능이 아니라 서술이다.** 카탈로그가 버튼으로 나오고, 누르면 사실·표가 그대로
나온다. S1 의 브라우저 확인은 **전부 모델 서버가 없는 상태에서** 통과했다(콘솔에 Ollama
연결 거부가 계속 찍힌 채로).

이것이 GPU 없는 AWS 시연 사본이 제 기능을 하는 근거다(`docs/24-aws-demo.md`). 시연 시간에만
모델을 켜는 배치에서, 꺼져 있는 상태는 고장이 아니다.

**그 배치가 재확인 버튼을 요구했다.** 탐지는 드로어가 붙을 때 한 번 돌고, 결과는 질문
상자 하나만 잠근다. 그런데 시연 사본의 GPU 는 **시연 시간에 켜진다** - 즉 세션 도중에
모델이 올라오는 것이 정상 경로이고, 한 번만 재는 구현에서는 그때부터 새로고침 전까지
상자가 계속 죽어 있었다. 그래서 잠긴 입력 옆에 `다시 확인` 을 둔다. 누르면 같은 탐지를
다시 돌리고, 성공하면 상자가 그 자리에서 살아난다. **자동 폴링은 하지 않는다** - 대부분의
배치에서 그 주소는 실행 내내 비어 있을 예정이고, 없는 것을 계속 두드리는 것은 답이 아니다.
못 닿으면 상자는 잠긴 채로 남고 사유만 새 것으로 바뀐다.

## 7. 한계와 다음

- **관측 모드의 격리 후보가 좁다.** `containmentCandidates` 는 핵심 자산 + 현재 침해된
  자산만 준다(tacnet-01 에서 6개). "모든 자산 중 싼 것"이 아니다. 넓히려면 자산 수만큼
  `runChain` 2회이므로 성능을 먼저 재야 한다.
- **`needs:'game'` 게이트는 아직 실질 검사가 아니다.** S1 6종에 교전 전용 질의가 없어서다.
  S3 가 `counterfactual`/`autoplay` 를 문 뒤에 넣는 순간 실질 검사가 된다.
- **S2 는 끝났다**: 자연어 라우팅(`staff-llm.mjs` `routeQuestion`), 서술과 `[F#]` 칩,
  미검증 배지(`ui/src/ui/cite.jsx` 한 벌), 기권·1회 재시도·`state_summary` 폴백, 골든셋
  38문항(`eval/golden/staff/tacnet-01.jsonl`)과 러너(`ui/tools/staff-eval.mjs`),
  `llm.attacker_enabled` 플래그, 질의창 재확인. **다만 지표는 아직 수치가 아니다(8절).**
- **공격자 LLM 은 플래그 뒤에 있다.** `config.json` 의 `llm.attacker_enabled` 가 기본
  `false` 이고, 참일 때만 교전 시작 카드에 LLM 공격자 선택지가 뜬다. `attack-llm.mjs` 와
  프롬프트는 그대로 남아 있다 - ADR-0019 를 뒤집은 것이 아니라 기본값을 옮긴 것이고,
  되돌리는 비용은 그 한 줄이다(ADR-0028 1절).
- **S3**: `autoplay`·`counterfactual`·`harden`·`trend`, AAR 서술, SITREP 초안과 승인 기록.

## 8. 평가 상태 - 골든셋은 있고 수치는 없다

**이 절은 "아직 모른다" 를 적는 절이다.** ADR-0008·ADR-0009 가 요구하는 지표는 정의됐고
러너도 돌지만, **이 기계에는 Ollama 가 없어서 한 번도 재지 못했다.**

| | 상태 |
|---|---|
| 골든셋 | **있다.** `eval/golden/staff/tacnet-01.jsonl`, 38문항. 기권 8문항(21.1%), 질의별 6/6/6/5/4/3 |
| 러너 | **있다.** `ui/tools/staff-eval.mjs`. 전송 계층이 주입 가능해서 단위 테스트는 스텁으로 돈다 |
| 카탈로그 회귀 | **측정했다.** 30건 전부 통과 - 골든셋의 기대 질의를 `validate` + `ask` 로 실제 실행해 사실이 나오는지 확인한 것이다. **모델이 들어가지 않는 절반이다** |
| 라우팅 precision@1 | **미측정** |
| 인용률 / 미검증률 | **미측정** |
| 기권 정확도(두 수) | **미측정** |
| 지연 | **미측정** |

`eval/results/staff-nomodel-2026-09-26.json` 이 그 기록이고, 미측정 항목은 **0 이 아니라
`null`** 로 적혀 있다. 0 은 "쟀더니 0" 이라는 뜻이고 그것은 거짓이 된다.

모델이 있는 기계에서 실측하는 명령은 한 줄이다:

```
node ui/tools/staff-eval.mjs --model qwen2.5:7b-instruct-q4_K_M --endpoint http://127.0.0.1:11434
```

`eval/results/staff-<model>-<date>.json` 이 나온다. 그 파일이 나오기 전까지 **로컬 7B 가
6종 카탈로그를 정확히 고르는지는 열린 질문이다.** ADR-0028 의 재검토 조건도 그 수치를
기다리고 있다 - precision@1 이 낮으면 질의 라벨이 모호한 것인지 모델이 약한 것인지부터
가른다.
