# 07. 합성 데이터와 오프라인 개발 트랙

## 1. 왜 만들었나

공개 데이터셋은 크고, 느리고, 둘은 수동 승인이 필요하다. 인터넷이 끊기면 아무것도 못 한다.
2026-09-05에 실제로 그 상황이 발생했다.

그래서 **네트워크 없이 파이프라인 전체를 개발·테스트할 수 있는 합성 트랙**을 만들었다.
L2 임무 온톨로지는 어차피 공개 데이터가 없어 직접 정의해야 하므로(`03-mission-ontology.md`),
이 작업은 우회가 아니라 원래 해야 할 공정을 앞당긴 것이다.

## 3. 시나리오 요약 - defnet-01

**국방망(엔터프라이즈 유사) 가정.** Q1이 전술망으로 확정됐으므로(ADR-0012) 이 시나리오는
**단일 스냅샷 참조 구현**으로 유지한다. 시간축은 `tacnet-01`이 담당한다(3.1절).

- 임무 2개: `M-C2` 지휘통제(우선순위 1), `M-LOG` 군수지원(2)
- 서비스 5개 중 **`S-DIR`(인증)과 `S-DB`만 이중화**. 나머지는 단일 경로
- `ESX01`에 DC01/MAIL01/FS01/WEB01/DB01이 몰려 있는 **단일 장애점**
- 공격: 피싱 → WKS003 침해 → 자격증명 탈취 → DC01 → DC02 → DB01 → 유출 → 흔적 삭제
- ATT&CK 기법 11종: T1566.001, T1059.001, T1071.001, T1003.001, T1046, T1021.002,
  T1003.003, T1078.002, T1005, T1048.003, T1070.001

### 3.0.1 전송로 계층 (2026-09-07 추가)

`FW01`(방화벽)과 `SW01`(스위치)은 자산 목록에는 있는데 어떤 엣지에도 붙지 않아
검증기 경고 2건으로 오래 남아 있었다. 의존 그래프에는 넣을 자리가 없다. 방화벽은
누구에게 서비스를 제공하지도, 누구에게 의존하지도 않는다. **트래픽을 나를 뿐이다.**

ADR-0017이 그 자리를 만들었다. `links[]`(물리 전송로)와 `transit`(중계 여부)이다.
defnet-01에 같은 계층을 넣어 두 장비를 중계 노드로 세웠다. 링크 15개, 2계층 구조다.

| 구간 | 구성 |
|---|---|
| 전산실 | `SW01`이 코어. DC01/DC02/MAIL01/FS01/DB01/DB02/WEB01/ESX01/ESX02를 전부 문다 |
| 사용자 | 지휘소(WKS001/002), 1대대(WKS003/004), 군수대대(WKS005)가 `FW01`에 붙는다 |
| 경계 | `FW01` - `SW01` 한 회선. 워크스테이션에서 서버로 가는 모든 트래픽이 지난다 |

`transit`은 ADR-0017 5항대로다. 서버·하이퍼바이저·방화벽·스위치는 `true`,
워크스테이션 5대는 `false`. 작업 4개에는 `performed_at`을 채웠다
(T-SITREP@WKS001, T-ORDER@WKS002, T-REQ/T-ISSUE@WKS005).

**`communicates_with`를 그대로 옮기지 않았다.** 논리 통신 관계와 물리 전송로는 다른
층이다. WKS001-DC01은 논리적으로 직결이지만 물리적으로는 FW01과 SW01을 경유한다.
복사했다면 워크스테이션끼리 서버를 우회 중계하는 경로가 생기고, FW01/SW01은 여전히
아무 역할도 못 했을 것이다. 두 층은 병존한다.

**회귀는 없다.** `links[]`가 생기면 엔진의 도달성 판정이 켜지지만(`hasLinks`), 정적
위상에서 모든 작업 단말이 모든 서비스 제공 자산에 도달하므로 값이 바뀌지 않는다.
`performed_at` 하한(ADR-0017 6항)도 발동하지 않는다. 합성 공격에서 침해되는
워크스테이션은 WKS003뿐인데 WKS003은 모델된 작업을 수행하지 않기 때문이다.
소수점까지 동일한 것을 실측으로 확인했다.

| 기준값 | 도입 전 | 도입 후 |
|---|---|---|
| DC01 단독 침해 | 0.0% | 0.0% |
| DC01+DC02 침해 M-C2 | 0.80479545454545443 | 0.80479545454545443 |
| ESX01 격리 what-if 첫 행 | 70.1% | 70.1% |

검증기는 오류 0, 경고 0이다. 정적 도달성 검사(모든 링크가 살아 있다고 가정해도 닿지
못하면 오류)는 `timeline`이 있는 시나리오에서만 도는 검사라 defnet-01에서는 실행되지
않는다. 임시 사본에 `timeline`을 붙여 별도로 돌려 통과를 확인했다.

**알면서 넣지 않은 한계.** `SW01`이 본부·예비 두 전산실을 모두 잇는 단일 스위치다.
예비 전산실용 스위치가 없으므로 이 모델에서 SW01 단절은 DC02/DB02까지 끊어 이중화를
무의미하게 만든다. 현재 시나리오에 outage가 없어 산출 수치에는 영향이 없다. 전송로
이중화 자체를 다루려면 SW02와 대체 회선을 추가해야 한다.

## 3.1 시나리오 요약 - tacnet-01 (전술망, 시간축)

**전술망(ADR-0012).** 여단 TOC - 대대 지휘소 - 2개 중대 - 포병 FDC, 420분.
정적 그래프로는 표현되지 않는 성질을 담는 것이 목적이다.

- 임무 2개: `M-C2` 지휘통제(1), `M-FIRE` 화력지원(2). 단계 5개에 각각 유효 구간이 있다
- **환경 단절 6건**(기동 3, 지형 2, 미상 1)이 공격과 별개로 내장돼 있다
- 공격 7단계: 노획 단말 → 자격증명 탈취 → BN-SRV 측면이동 → 장악 → 여단 TOC → TOC-SRV 장악
- 저하도를 `total / attack / env / inter`로 분해해 보고한다(ADR-0017)

핵심 장면은 **300~345분**이다. 공격 단독 0%, 환경 단독 0%, 그런데 실제 임무 저하 52.63%.
위성 단절로 대대에서 도달 가능한 C2 제공자가 침해된 BN-SRV 하나뿐이 되기 때문이다.
**도달성 없는 이중화는 이중화가 아니다.** 실측과 읽는 법은
[11-tactical-time-axis.md](11-tactical-time-axis.md).

```powershell
.\scripts\Show-TacticalReplay.ps1 -Step 15
.\scripts\Test-Ontology.ps1 -Scenario scenarios\tacnet-01\mission.json
```

## 5. 이미 나온 결과 - 설계 주장 3개가 숫자로 확인됨

### 5.1 임무 좌표계가 지리·자산 좌표계보다 낫다 (C1)

리플레이 결과:

| 시각 | 단계 | M-C2 저하 | M-LOG 저하 |
|---|---|---|---|
| 10:48 | 초기 침해 | 0.0% | 0.0% |
| 11:03 | 자격증명 탈취 | 0.0% | 0.0% |
| 11:18 | **DC01 측면이동** | **0.0%** | **0.0%** |
| 11:43 | **DC02 측면이동** | **55.9%** | **32.0%** |
| 11:58 | DB01 접근 | 80.9% | 53.3% |
| 12:08 | 데이터 수집 | 82.5% | 65.4% |

경보 나열형 콘솔이라면 11:18의 도메인 컨트롤러 침해가 최고 심각도로 뜬다. 임무 좌표계에서는
**0%**다. 이중화가 받치고 있기 때문이다. 진짜 변곡점은 11:43, 이중화가 소진되는 순간이다.

이것이 임무 좌표계의 논거다. "심각한 사건"과 "임무에 심각한 사건"은 다르다.

### 5.2 봉쇄에는 그 자체의 임무 비용이 있다 (ADR-0004)

| what-if | 초기 시점 M-C2 저하 |
|---|---|
| `-WhatIfIsolate DC01` | 0.0% - 이중화가 받쳐 봉쇄가 공짜 |
| `-WhatIfIsolate ESX01` | **70.1%** - 공격보다 봉쇄가 더 큰 피해 |

대응 실행에 사람 승인을 필수로 둔 결정이 추상론이 아님을 보여준다. 승인자는 이 숫자를
보고 결정해야 한다.

### 5.3 이중화 모델링을 틀리면 과잉경보가 난다

초기 온톨로지는 `MAIL01 depends_on DC01`처럼 **의존을 자산에 직접** 걸었다. 그 결과
DC01 단독 침해만으로 지휘통제가 52.6% 저하로 계산됐다 - DC02가 멀쩡히 인증을 처리하는데도.
자산 수준 엣지가 이중화 그룹을 우회한 것이다.

수정: 이중화된 대상에 대한 의존은 **반드시 서비스 id로** 건다. `Test-Ontology.ps1`이
이 실수를 오류로 잡는다.

## 6. 한계 - 반드시 지킬 것

**합성 데이터로 탐지 성능을 주장하지 않는다.**

| 항목 | 합성 | 실데이터 |
|---|---|---|
| 악성 비율 | 0.15% | LANL 0.0000713%, TC 0.0016%, OpTC 0.024% |
| 정상 트래픽의 결 | 균등 난수 | 실제 운영망의 주기성·버스트·롱테일 |
| 노이즈·오탐 유발 요인 | 없음 | 대량 존재 |
| 기법 다양성 | 11종, 각 1건 | 훨씬 넓고 변형 다수 |

합성 데이터의 악성 비율이 실데이터보다 **두 자릿수 이상 높다.** 여기서 잘 도는 탐지기가
실데이터에서 무너지는 것이 정상이다.

허용되는 용도:
- 파이프라인·엔진·UI 개발과 회귀 테스트
- 임무 저하도 전파 함수의 **구성 타당성** 검사 (단조성, 이중화 반영) - `04-evaluation.md` 2.2
- 데모 시나리오

금지되는 용도:
- PR-AUC, precision@k 등 **탐지 성능 지표의 근거**
- 논문의 성능 주장. 성능은 실데이터(OpTC/LANL/AIT)에서만 측정한다

## 7. 실데이터로 넘어갈 때

합성 트랙은 실데이터가 들어오면 **버리는 게 아니라 회귀 테스트로 남긴다.**

1. `events.jsonl`의 OCSF 스키마를 실데이터 정규화 결과와 맞춘다. 스키마가 어긋나면
   합성 쪽을 고친다(실데이터가 기준).
2. 실데이터의 호스트·계정 인벤토리를 `mission.json`의 `assets`에 조인한다.
   여기가 L1↔L2 조인 지점이고 수작업이 몰리는 곳이다.
3. AIT는 테스트베드 재생성이 가능하므로, 토폴로지를 `defnet-01`에 맞춰 재생성하면
   합성 온톨로지를 그대로 쓸 수 있다. 이것이 AIT를 1순위로 둔 이유 중 하나다.

## 8. 인코딩 함정 (실측으로 얻은 것)

Windows PowerShell 5.1은 **BOM 없는 UTF-8 .ps1을 시스템 ANSI 코드페이지로 읽는다.**
생성기 소스에 한글 단계 라벨을 넣었더니 조용히 깨졌고, 그 깨진 문자열이 `labels.jsonl`에
그대로 들어갔다. 데이터가 오염된 뒤에야 발견됐다.

규칙 두 가지:

1. **취득·다운로드 스크립트는 ASCII만.** 깨질 것이 없게 한다.
   (동일 원인으로 `fetch-ait.ps1`이 8개 파일 중 7개만 인식한 사고가 있었다 -
   `05-data-lifecycle.md` 참조)
2. **한글이 들어가는 스크립트는 BOM을 붙인다.** `scripts\Add-Bom.ps1`로 처리하고,
   `-Check`는 필요한 파일이 있으면 exit 1이므로 CI에 넣는다.
3. **사람이 읽는 문자열은 가능하면 JSON 데이터 파일에 둔다.** 데이터 파일은
   `-Encoding utf8`로 명시적으로 읽으므로 안전하다.
