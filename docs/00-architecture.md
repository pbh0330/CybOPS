핵심은 **D와 N 사이의 단방향 화살표**다. LLM은 결정론 계층의 산출물을 읽어 설명할 뿐,
상태를 쓰지 못한다. 이 경계가 무너지면 감사 추적성과 재현성이 동시에 사라진다. (ADR-0003)

## 1. 데이터 계층 3분할

과제 전체를 관통하는 조달 전략의 뼈대다.

| 계층 | 내용 | 조달 방법 | 난이도 |
|---|---|---|---|
| **L1 텔레메트리/경보** | 호스트 이벤트, 플로우, EDR, 레드팀 그라운드트루스 | 공개 데이터셋 그대로 | 낮음 |
| **L2 임무-자산 온톨로지** | 부대, 임무, 작전 단계, 자산 의존관계 | 공개된 것이 없음 → 자체 정의 | **가장 높음** |
| **L3 시뮬레이션(M&S)** | 공격 진행, 대응 효과, what-if | 공개 사이버 레인지 시뮬레이터 | 중간 |

L2가 공개 데이터에 없다는 사실은 제약이 아니라 정상이다. 기존 CyCOP 연구들도 시뮬레이션
데이터를 전제로 개발되었고, 임무-작업-자산 모델을 표준 시나리오 정의 언어로 추상화하는
방식이 방법론으로 제안되어 있다. **L2는 원래 만들어 넣는 것이다.** 상세는
`03-mission-ontology.md`.

실무적으로 이 과제의 진짜 공정은 L1 정규화가 아니라 **L1의 자산 식별자를 L2 온톨로지에
조인하는 일**이다. 여기가 수작업이 몰리는 지점이므로 초기부터 자동 매핑 규칙 + 수작업
보정 워크플로를 함께 설계한다.

## 2. 계층별 책임

### I. 수집·정규화 계층

- 입력: 데이터셋 리플레이어 또는 시뮬레이터 이벤트 스트림
- 출력: OCSF 정규화 이벤트 (ADR-0005)
- 필수 기능
  - **시간 정렬**: 데이터셋마다 타임존·시계 오차가 다르다. 단일 논리 시계로 재매핑한다.
  - **엔티티 해석**: IP ↔ 호스트 ↔ 계정 ↔ 자산 ID를 통합한다. DHCP 재할당 때문에
    IP는 시점 의존적 키라는 점을 전제로 설계한다.
  - **리플레이 속도 제어**: 실시간 배속, 배속 재생, 특정 구간 점프.
- 지리 정보는 여기서 `enrichment.geo` 필드에 국가 코드만 보관한다. 다운스트림 판단 로직은
  이 필드를 읽지 않는다. (ADR-0002)

### M. 임무 모델 계층 (L2)

- 노드: 임무(Mission) / 작전단계(Phase) / 작업(Task) / 서비스(Service) / 자산(Asset)
- 엣지: `depends_on`, `enables`, `hosted_on`, `communicates_with`
- 자산 중요도는 crown jewels 분석 관점으로 부여한다. 즉 "임무 핵심 기능을 직접 수행하거나,
  다른 핵심 자산에 대한 접근·보호·동작을 가능하게 하는가"를 기준으로 한다.
- 이 그래프가 상황도의 **지형**이다. 자산이 지물, 임무 저하도가 등고선 역할을 한다.

### D. 결정론 계층

상태값의 유일한 출처. 세 종류의 산출물을 낸다.

1. **자산 상태**: 정상 / 의심 / 침해추정 / 침해확인 / 격리. 규칙 + 경량 ML 분류기.
2. **임무 저하도**: 자산 상태를 의존성 그래프를 따라 임무 노드까지 전파한 값.
   전파 함수는 명시적 수식으로 정의하고 문서화한다(가중 최소경로 / noisy-OR 등 후보는
   `03-mission-ontology.md` 참조).
3. **우선순위**: 임무 저하도 × 확신도 × 시급성. 정렬 가능한 스칼라.

모든 산출물은 `(입력 이벤트 ID 집합, 적용 규칙 ID, 중간값, 출력)`을 감사 로그에 남긴다.
상황도의 어떤 색깔이든 클릭하면 이 경로를 역추적할 수 있어야 한다.

### N. LLM 계층

담당하는 것:

- 상황 요약, 지휘관 브리핑 초안
- 상관 가설 생성 ("이 세 경보가 같은 캠페인일 가능성과 그 근거")
- 자연어 질의 → 구조화 질의 변환 ("어제 밤 A임무 건드린 계정 보여줘")
- ATT&CK 기법 매핑에 대한 서술적 설명

담당하지 않는 것:

- 경보 우선순위 결정, 임무 저하도 산출, 자동 차단·격리

이 분담의 근거는 실측이다. SOC 경보 분류에서 LLM은 recall은 높게 나오지만 **우선순위 결정의
precision이 일관되게 낮아** 노이즈와 오탐을 유발하고, 경량 ML 베이스라인이 경쟁력 있는 F1을
낸다는 보고가 있다. 여기에 지연시간(경보당 초 단위), 프롬프트 인젝션, 안전하지 않은 출력
처리, 캘리브레이션 미검증 문제가 겹친다. (근거 상세와 검증 상태는 `02-research-plan.md`)

**프롬프트 인젝션 전제**: 입력 텔레메트리(파일명, 프로세스 커맨드라인, HTTP 헤더, 사용자
에이전트)는 공격자가 쓰는 필드다. LLM 컨텍스트에 들어가는 모든 텔레메트리 문자열은
신뢰 불가 데이터로 표시해 감싸고, 지시로 해석될 수 있는 경로를 차단한다.

### P. 표현 계층

기본 뷰는 임무 그래프. 지리 레이어는 토글 가능한 보조 뷰이며 자산의 물리적 위치 표시에만
쓴다. (ADR-0001, ADR-0002)

응답성 목표는 선행 연구의 측정치를 벤치마크로 삼는다: 단순 조회 평균 0.11초, 복합 조회 평균
1.07초 수준. LLM 응답은 이 예산 밖에 두고 별도 패널에서 스트리밍한다. **상황도의 상태 갱신이
LLM 응답을 기다리는 구조를 만들지 않는다.**

## 3. 3트랙 구성

세 트랙은 병렬 진행하되 의존 순서가 있다. A가 정규화 스키마를 확정해야 B가 그 위에 임무
모델을 올릴 수 있다.

### 트랙 A — 실증 (Replay)

- 목적: 실제 텔레메트리 위에서 상황도가 동작함을 보인다.
- 데이터: DARPA OpTC (1순위), LANL (보조)
- 산출물: OCSF 정규화 파이프라인, 타임라인 리플레이어, 자산 상태 엔진
- 완료 기준: OpTC 레드팀 3일 구간을 리플레이했을 때 그라운드트루스 침해 호스트가 상황도에서
  상태 변화로 나타나고, 각 상태 변화의 근거 이벤트를 역추적할 수 있다.

### 트랙 B — M&S (What-if)

- 목적: 임무 저하도 전파와 what-if 시뮬레이션을 보인다.
- 도구: CybORG/CAGE 계열, PrimAITE, Yawning Titan, Cyberwheel
- 산출물: 시뮬레이터 어댑터, 임무 모델 오버레이, what-if 실행 패널
- 대표 질의: "이 자산을 격리하면 임무 A가 몇 % 저하되는가", "통제 X를 먼저 적용할 때와
  Y를 먼저 적용할 때 위험 감소 속도 차이"
- 근거: 공격그래프 기반 사이버 디지털 트윈이 통제 적용 순서를 바꿔가며 위험 감소를 평가하는
  what-if를 제공하는 선례가 있다. 또한 Cyberwheel은 기존 환경들의 한계로 **시각화 도구 부재**를
  명시적으로 지적한다 — 그 빈칸이 이 과제의 자리다.

### 트랙 C — 평가

- 목적: LLM 계층의 정확성·근거 인용률·캘리브레이션을 측정한다.
- 산출물: 수백 건 규모 골든셋, 평가 하네스, 리포트
- 파인튜닝은 하지 않는다 (ADR-0006). 상세는 `04-evaluation.md`.
